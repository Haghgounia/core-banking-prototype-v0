## 2. Source/runtime hotfixes absorbed into the frozen baseline

The final baseline incorporates the successful runtime patches rather than leaving them as external ZIP overlays:

1. **Phase 7 semantic idempotency guard** — unique coverage is detected by table/column semantics rather than a fixed index name.
2. **Rollback probe hardening** — the Phase 7 readiness probe uses valid current business basis data and verifies rollback non-persistence.
3. **Phase 10 index idempotency** — existing covering indexes are recognized semantically; reruns no longer fail on `ORA-01408` because of alternate index names.
4. **Phase 10F reference allow-list** — runtime repository permits the seven v5 reference tables used by validation:
   - `REF_DEP_OPEN_JOINT_BASIS`
   - `REF_DEP_OPEN_ACTIVATION_STATUS`
   - `REF_DEP_OPEN_FUND_PURPOSE`
   - `REF_DEP_OPEN_OBLIGATION_TYPE`
   - `REF_DEP_OPEN_SETTLEMENT_STATUS`
   - `REF_DEP_OPEN_CHECK_PHASE`
   - `REF_DEP_OPEN_BLOCKING_SCOPE`
5. **Cash funding contract** — `CASH_MANAGEMENT_TXN_REF` is required by backend for `CASH`, populated by the Angular wizard, and generated by the Phase 10F qualification tool.
6. **Phase 10F qualification fixture preparation** — final metadata-aware runtime preparation tool is part of `tools/prepare-dps2-phase10f-runtime.mjs`.
7. **Evidence-expiry test-tool hardening** — the E2E harness refreshes the validity of controlled test evidence immediately before Readiness. This affects only qualification tooling, not production business logic.
