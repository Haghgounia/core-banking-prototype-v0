## سیاست پاک‌سازی و درج
- 239 ردیف فیزیکی Excel خوانده شده است.
- 10 ردیف ادامه‌ی پله‌های ارزیابی در 5 تعرفه منطقی تجمیع شده‌اند؛ در نتیجه 229 `FEE_DEFINITION` رسمی ایجاد/به‌روزرسانی می‌شود.
- 17 سرفصل فایل منبع به 17 `FEE_FEATURE` گروه‌بندی شده‌اند؛ عنوان فارسی سرفصل منبع حفظ شده است.
- کد ردیف بانک مرکزی در `FEE_DEFINITION_VERSION.REGULATORY_TARIFF_CODE` بدون ساختن شماره جعلی نگهداری می‌شود. اگر کد در فایل منبع خالی باشد، همین فیلد NULL می‌ماند و فقط `FEE_CODE` داخلی یکتا ساخته می‌شود.
- درصدهای Excel در واحد «درصد» هستند؛ برای موتور، `RATE_VALUE = درصد / 100` ذخیره می‌شود. مثال: `0.5` در Excel به `0.005` در Oracle تبدیل می‌شود.
- فرمول‌هایی که در ستون‌های ساختاری فایل عدد کافی ندارند به `EXTERNAL_VALUE` تبدیل می‌شوند؛ متن منبع در Description حفظ می‌شود و هیچ فرمول اجرایی حدسی ساخته نمی‌شود.
- 5 تعرفه ارزیابی پلکانی به‌صورت 3 Tier مدل می‌شوند. وابستگی «هر کدام کمتر باشد: محاسبه بانکی یا تعرفه کارشناس رسمی» با Rule Component و External Value حفظ شده است.
- 6 تعریف موجود Baseline که از همین بخشنامه نمونه‌سازی شده بودند، با همان `FEE_CODE` قبلی استفاده می‌شوند تا رکورد تکراری ایجاد نشود.
- خطای مهم نمونه قبلی `CREDIT_STAGE2` اصلاح می‌شود: مرحله دوم `0.001` (یک در هزار) است تا همراه مرحله اول `0.0005` مجموعاً 1.5 در هزار شود.
