# PB-R22 — فرم‌های مرجع محصول تسهیلات

## دامنه تغییر

زیرمجموعه جدید **اطلاعات پایه ← فرم‌های مرجع محصول تسهیلات**، مسیر `/loan/reference-data`، و لینک مستقیم از صفحه «محصول‌ساز یکپارچه».

| فرم | جدول واقعی Oracle | کاربرد |
|---|---|---|
| انواع عقود تسهیلات | `PDL.LOAN_TYPE` | کد داخلی/بانک مرکزی، عنوان و ویژگی‌های عددی عقد |
| طرح‌های تسهیلات | `PDL.PLAN_TYPE` | نام/کد طرح و ۸ نرخ اجباری مطابق ساختار واقعی بانک |
| ارتباط نوع عقد و طرح | `PDL.LOAN_TYPE_PLAN_TYPE` | انتخاب یک عقد و چند طرح؛ هر زوج به‌صورت یک رکورد جدا ذخیره می‌شود |
| مصرف تسهیلات | `PDL.LOAN_USAGE` | حفظ و ویرایش اطلاعات مصرف موجود |
| بخش‌های اقتصادی | `PDL.ECONOMIC_SECTION` | FK به طرح |
| زیربخش‌های اقتصادی | `PDL.ECONOMIC_SUB_SECTION` | FK به بخش |
| پارامترهای عملیاتی | `PDL.FACILITY_OPERATION_PARAMETER` | دوره‌ها و ضوابط انتقال طبقه‌بندی |
| اقلام الگوی وثایق | `PDL.LOAN_PRODUCT_COLLATERAL` | اطلاعات وثایق متناسب با محصول/نسخه و FK واقعی |

سه فرم نخست برای هدف جاری حیاتی‌اند. بقیه برای جلوگیری از برگشت مجدد به فرم‌های عمومی PDL، در همان زیرمنو دیده می‌شوند.

## روش نصب کم‌خطر

۱. از پوشه پروژه فعلی نسخه پشتیبان تهیه کنید.
۲. ZIP را **در ریشه** `D:\Projects\core-banking-prototype-v0` استخراج کنید تا ابزار و محتویات بسته به `tools/` و `docs/` اضافه شوند. فایل‌های قبلی پروژه با استخراج ZIP بازنویسی نمی‌شوند.
۳. در CMD:

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\repair-pb-r22-loan-reference.mjs --check
node tools\repair-pb-r22-loan-reference.mjs --apply
node tools\repair-pb-r22-loan-reference.mjs --check
node tools\verify-pb-r22-loan-reference.mjs
build-production.cmd
```

`--check` پس از نصب باید `CHANGES=0` نمایش دهد. در صورت تشخیص تغییرات ناسازگار، ابزار بدون بازنویسی سورس متوقف می‌شود. پیش از هر تغییر، فایل‌های قبلی در `docs/patch-backups/pb-r22-loan-reference/<timestamp>/` پشتیبان‌گیری می‌شوند. ابزار فقط بخش‌های کد مربوط به R22 را ادغام می‌کند و فایل‌هایی مانند `build-production.cmd`، FEE2، ORG یا فرم‌های سپرده را تغییر نمی‌دهد.

**هیچ اسکریپت Oracle اجرا نشود**؛ مدل DB و رکوردهای موجود تغییر نمی‌کنند.

## ترتیب ورود اطلاعات در UI

۱. از «اطلاعات پایه» به «فرم‌های مرجع محصول تسهیلات» بروید.
۲. در «انواع عقود تسهیلات» کد عقد، نام، کد مرجع بانک مرکزی و سه ویژگی عددی الزامی (گروه، نوع تعهد، روش سود) را با داده‌های مصوب وارد کنید. در DDL ارسالی برای سه ویژگی عددی فهرست کدگذاری/برچسب ارائه نشده؛ سیستم برای آن‌ها گزینه فرضی نمی‌سازد.
۳. در «طرح‌های تسهیلات» کد داخلی، نام، کد مرجع بانک مرکزی و **تمام هشت نرخ اجباری** را مطابق قرارداد مالی بانک وارد کنید. حداقل/حداکثر نرخ‌های متناظر کنترل می‌شود. صفر به‌صورت پیش‌فرض ایجاد نمی‌شود.
۴. وارد «ارتباط نوع عقد و طرح» شوید، عقد فعال را انتخاب کنید و طرح‌های مجاز را به‌صورت چندانتخابی اضافه کنید. هر انتخاب جداگانه در `PDL.LOAN_TYPE_PLAN_TYPE` ذخیره می‌شود. برای غیرفعال‌کردن یا فعال‌کردن رابطه از دکمه همان ردیف استفاده کنید. ردیف‌ها فیزیکی حذف نمی‌شوند؛ وضعیت `ARCHIVED` از این صفحه بازفعال نمی‌شود.
۵. به «پروفایل تسهیلات» برگردید؛ طرح‌ها باید بعد از انتخاب عقد، از روابط فعال دریافت شوند. دریافت رابطه‌ها صفحه‌بندی‌شده است و به ۲۰۰ رکورد اول محدود نیست.

## محافظت‌های Backend

- جلوگیری از تکرار `LOAN_TYPE_CODE` و `PLAN_TYPE_CODE` بدون توجه به بزرگی/کوچکی حروف و فاصله‌های اطراف.
- جلوگیری از تکرار زوج `(LOAN_TYPE_ID, PLAN_TYPE_ID)` حتی اگر نسخه قبلی غیرفعال باشد؛ باید همان رکورد مجدداً فعال شود.
- کنترل وجود و **فعال‌بودن** هر دو رکورد عقد و طرح هنگام ایجاد/فعال‌سازی رابطه.
- قفل تراکنشی روی رکورد عقد برای سریال‌سازی ایجاد رابطه و کاهش خطر ثبت تکراری هم‌زمان.
- حذف/ویرایش سایر اطلاعات طبق قرارداد و قیود واقعی Oracle انجام می‌شود؛ هیچ Seed، تغییر DDL یا داده نمونه‌ای وجود ندارد.

**محدودیت امنیتی شناخته‌شده Prototype:** هویت تغییر‌دهنده همچنان بر مبنای قرارداد موجود `X-User-Name` است و احراز هویت/مجوزدهی بانکی را جایگزین نمی‌کند. استفاده تولیدی نیازمند RBAC واقعی است.

## آزمون‌های اجراشده در محیط تهیه Patch

- `PB_R19_STATIC_PASS=51 FAIL=0`
- `RGL_R20_STATIC_PASS=53 RGL_R20_STATIC_FAIL=0`
- `PB_R21_LOAN_STATIC_PASS=38 PB_R21_LOAN_STATIC_FAIL=0`
- `PB_R22_LOAN_REFERENCE_STATIC_PASS=36 FAIL=0`
- TypeScript syntax parse: کدهای جدید و مسیرهای تغییریافته؛ موفق.
- آزمون نصب و بازنصب: ادغام روی سورس R21، انطباق بایت‌به‌بایت فایل‌های هدف و نصب مجدد بدون تغییر؛ موفق.
- **Build کامل Maven/Angular و تست REST روی Oracle در محیط حاضر انجام نشده است؛ فقط در Windows شما قابل تأیید است.**

پس از پایان موفق Build و بالا آمدن Backend، تست فقط‌خواندنی زیر را اجرا کنید:

```bat
set CORE_BANKING_BASE_URL=http://127.0.0.1:8091
node tools\runtime-pb-r22-loan-reference-readonly.mjs
```

## آزمون پذیرش عملی (UAT)

- در صفحه `/loan/reference-data` هر هشت فرم دیده شود.
- قبل از Seed معتبر: عقد و طرح در فرم رابطه خالی باشند و پیام راهنما نشان داده شود. ۵ رکورد موجود `LOAN_USAGE` حفظ شوند.
- ساخت نوع عقد معتبر و طرح معتبر از فرم‌های خودشان موفق شود؛ مقادیر اجباری خالی پذیرفته نشوند.
- یک طرح برای یک عقد و سپس چند طرح برای همان عقد ثبت شود؛ هر ارتباط در Oracle یک ردیف جدید باشد.
- درج دوباره همان زوج منع شود؛ غیرفعال‌کردن و فعال‌سازی همان ردیف سابق موفق شود.
- افزودن رابطه با عقد/طرح غیرفعال منع شود.
- در پروفایل محصول تسهیلات، بعد از انتخاب عقد فقط طرح‌هایی نمایش داده شوند که ارتباط فعال دارند.
- رگرسیون مسیر سپرده، FEE2، منابع DPS/DPS2 و فرم‌های موجود Product Builder حفظ شود.
