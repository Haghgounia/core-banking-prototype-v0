# PB-R23 — طبقه‌بندی گروه تسهیلات، نوع تعهد و توقف موقت روش سود

## تصمیم معماری

بر اساس ساختار فعلی `PDL.LOAN_TYPE`، هر سه فیلد `LOAN_GROUP`، `OBLIGATION_TYPE` و `INTEREST_METHOD` دارای نوع `NUMBER(1)` و `NOT NULL` هستند. هیچ جدول FK یا CHECK دامنه‌ای برای این سه کد در DDL فعلی وجود ندارد. از این رو **Enum ثابت با شناسه عددی** در Java انتخاب شده است، نه جدول جدید. این کدها **داخلی سامانه** و مستقل از فیلد `LOAN_TYPE_CBI_CODE` هستند. تغییر کدها در آینده نیازمند مهاجرت داده و تأیید است؛ در این نسخه تغییری در داده‌ها و DDL اجرا نمی‌شود.

| ستون | کد | معنا |
|---|---:|---|
| `LOAN_GROUP` | 1 | قرض‌الحسنه |
| `LOAN_GROUP` | 2 | مبادله‌ای |
| `LOAN_GROUP` | 3 | مشارکتی |
| `LOAN_GROUP` | 4 | تعهدات |
| `OBLIGATION_TYPE` | 0 | فاقد کاربرد (در سه گروه غیرتعهدی) |
| `OBLIGATION_TYPE` | 1 | اعتبارات اسنادی (فقط گروه 4) |
| `OBLIGATION_TYPE` | 2 | ضمانت‌نامه (فقط گروه 4) |
| `INTEREST_METHOD` | 0 | هنوز پیکربندی نشده (موقت) |

## رفتار عملیاتی

- در مسیر **اطلاعات پایه > اطلاعات پایه محصول تسهیلات > انواع عقود تسهیلات**، گروه تسهیلات ComboBox کنترل‌شده و فارسی است.
- وقتی گروه تعهدات انتخاب می‌شود، نوع تعهد از میان دو گزینه فوق انتخاب و اجباری می‌شود. برای دیگر گروه‌ها فیلد غیرفعال شده و مقدار `0` ثبت می‌شود.
- روش محاسبه سود به صورت یک قلم **غیرفعال و فقط‌خواندنی** دیده می‌شود؛ برای رکورد جدید مقدار `0` به‌صورت سیستمی ثبت می‌شود تا با `NOT NULL` کنونی سازگار باشد. برای رکورد قدیمی مقدار قبلی حفظ می‌شود و تغییر آن توسط API ممنوع است.
- کنترل‌های فوق علاوه بر Angular در Backend پیاده شده‌اند؛ حتی درخواست مستقیم API با مقدار خارج از دامنه رد می‌شود.
- کدهای بانک مرکزی، نوع عقد و طرح‌های تسهیلات را کاربران از طریق فرم‌های اطلاعات پایه ثبت می‌کنند. این بسته هیچ عقد، طرح یا ارتباط ساختگی ایجاد نمی‌کند.
- توقف روش سود **فقط** به `PDL.LOAN_TYPE.INTEREST_METHOD` مربوط است و موتور عمومی قیمت‌گذاری سپرده یا `PRODUCT_PRICING_*` را تغییر نمی‌دهد.
- نام‌های رابط کاربری سپرده و تسهیلات با قرارداد توافق‌شده «اطلاعات پایه + دامنه» یکسان‌سازی شده‌اند، بدون تغییر مسیر URL/API و Schema.

## نصب افزایشی روی R22

1. پیش‌نیاز: PB-R21 و PB-R22 روی سورس فعلی اعمال شده باشند. HF5 مستقل است و فایل اجرای Maven را این بسته بازنویسی نمی‌کند.
2. ZIP را در ریشه پروژه استخراج کنید. فایل‌های اصلی کد داخل `docs/patches/pb-r23-loan-type/new-files/` هستند؛ **آن پوشه را دستی روی سورس کپی نکنید**.
3. از ریشه `D:\Projects\core-banking-prototype-v0`:

```bat
node tools\repair-pb-r23-loan-type.mjs --check
node tools\repair-pb-r23-loan-type.mjs --apply
node tools\verify-pb-r23-loan-type.mjs
node tools\verify-pb-r22-loan-reference.mjs
node tools\verify-pb-r21-loan-ux.mjs
build-production.cmd
```

- `--check` فقط سازگاری و وضعیت را بررسی می‌کند؛ `--apply` پس از بررسی تمام فایل‌ها اصلاحات را همراه با نسخه پشتیبان اعمال می‌کند.
- با عدم تطابق فایل‌های پایه، نصب توقف می‌کند؛ پوشه‌های FEE2، سپرده، ساختار Oracle و فایل‌های غیرمرتبط دست‌نخورده می‌مانند.
- برای آزمون واقعی Oracle، پس از Build و شروع سرویس، یک عقد غیرتعهدی با گروه 1/2/3 و یک عقد تعهدی با گروه 4 و نوع 1/2 ثبت کنید؛ سپس مقدارهای ذخیره‌شده در PDL و نمایش فارسی Grid را بررسی کنید.
- با اجرای `node tools\repair-pb-r23-loan-type.mjs --check` پس از نصب، باید گزارش `CHANGES=0` نمایش داده شود.

## محدوده QA

Verifier ایستای R23 در سورس محلی پاس شده است. مواردی مانند Maven/Angular Build کامل روی Windows، بررسی Page UI در مرورگر و نوشتن رکورد واقعی Oracle باید در محیط اجرا تأیید شود. آزمون JUnit دامنه در بسته موجود است و توسط Maven build/test پروژه بررسی خواهد شد.
