# FEE UX R2.3 — اصلاح تکمیلی فرم تعریف کارمزد

## محدوده تغییر
این بسته **صرفاً مکمل R2.2 در موتور مستقل FEE** است. نسخه مبنای آزمایش: کد ۲۰۲۶/۱۰/۱۱ ساعت ۲۱:۵۳، همراه با FEE UX R2.2 (منوی NAV-R22 و NAV-R22.1 هیچ وابستگی فنی به این بسته ندارند).

- در فرم «تعریف کارمزد جدید» و «ویرایش تعریف»، انتخاب **ویژگی کارمزد** جست‌وجوپذیر است: نام فارسی یا کد ویژگی را وارد و یک گزینه از `FEE_FEATURE` انتخاب کنید. فقط `FEE_FEATURE_ID` واقعی در درخواست ذخیره ارسال می‌شود. متن آزاد به جای FK پذیرفته نمی‌شود. برای ویرایش، حتی شناسه ویژگی غیرفعال/خارج از فهرست موجود حفظ می‌شود تا بدون انتخاب جدید، FK تغییر نکند.
- `CATEGORY_CODE` و `CLASSIFICATION_CODE` بنا بر DDL موجود **مرجع مستقل، FK یا CHECK الزام‌آور ندارند**. کدهای متمایز و ثبت‌شده از صفحه‌های `FEE_DEFINITION` به‌صورت **پیشنهاد غیرالزام‌آور** دریافت می‌شوند. کاربر می‌تواند کد معتبر جدید وارد کند. با ایجاد یک FK/دامنه در نسخه‌های آتی، این پیشنهادهای آزاد غیرفعال خواهند شد تا کنترل واقعی Oracle/Metadata رعایت شود.
- سربرگ داخلی تکراری «ثبت رکورد جدید» و آیکون فنی از سر فرم حذف شده است؛ عنوان کاری دقیق در بالای صفحه نمایش داده می‌شود. «جزئیات فنی» با یک کنترل ثانویه در پایین فرم همچنان در دسترس است.
- برای فیلدهای اجباری پیام قابل‌فهم نمایش داده می‌شود؛ اعتبارسنجی Angular قبلی و خطاهای Oracle دست‌نخورده‌اند.
- نمایش فهرست تمام‌عرض، فرم مستقل، انتخاب رکورد موجود، پیوند نسخه و قواعد، محافظ تغییرات ذخیره‌نشده، و تمام APIهای قبلی تغییر نمی‌کنند.

## استقلال پروژه
تغییرات محتوایی به چهار فایل FEE محدود است:

```
frontend/src/app/features/fee-admin/fee-admin-table.component.ts
frontend/src/app/features/fee-admin/fee-admin-table.component.html
frontend/src/app/features/fee-admin/fee-admin-table.component.scss
frontend/src/app/features/fee-admin/fee-design-studio.component.html
```

به‌علاوه فقط آزمون ایستای `tools/verify-fee-ux-r22.mjs` برای پذیرش SHA نسخه R2.3 به‌روزرسانی می‌شود. فایل‌های AppShell، Product Builder R29 (و جدیدتر)، FEE2، Backend، Oracle یا Release تغییر نمی‌کنند.

## نصب روی ویندوز
از پروژه Backup بگیرید. ZIP را در ریشه پروژه استخراج کنید؛ استخراج به‌تنهایی کد را تغییر نمی‌دهد. دستورها:

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\install-fee-ux-r23.mjs --check
node tools\install-fee-ux-r23.mjs
node tools\verify-fee-ux-r23.mjs
node tools\verify-fee-ux-r22.mjs
node tools\verify-fee-ux-r21.mjs
node tools\verify-fee2-studio.mjs
node tools\verify-pdl-r29-finalization.mjs
build-production.cmd
```

نصب‌کننده قبل از **هر تغییر** SHA-256 تمام پنج فایل و محتوای بسته را کنترل می‌کند. اگر توسعه موازی FEE یکی از این فایل‌ها را تغییر داده، بدون بازنویسی آنها متوقف می‌شود؛ برای آن نسخه یک Rebase لازم است. تغییرات هم‌زمان محصول‌ساز یا FEE2 که فایل‌های مشترک یادشده را تغییر نداده‌اند، مانع نصب نیستند. نصب دوباره بی‌اثر است.

## بازگشت کنترل‌شده

```bat
node tools\uninstall-fee-ux-r23.mjs --check
node tools\uninstall-fee-ux-r23.mjs
build-production.cmd
```

بازگشت به محتوای R2.2 فقط در صورت تطابق SHA انجام می‌شود و در صورت تغییر جدید فایل‌های هدف، متوقف می‌شود. هیچ تغییر Oracle لازم نیست.

## پذیرش در مرورگر
۱. `/fee/design/catalog` → «تعریف کارمزد جدید»؛ فقط **یک سربرگ** و فرم تمام‌عرض را ببینید.

۲. «ویژگی کارمزد» را با چند حرف نام فارسی/کد جست‌وجو و نتیجه را انتخاب کنید. سپس متن را پاک کنید: شناسه قبلی نباید معتبر باقی بماند. با «ذخیره»، خطای فیلد اجباری باید ظاهر شود؛ **برای این آزمون رکورد جدید نسازید**.

۳. در «دسته کارمزد» و «طبقه‌بندی کارمزد»، هنگام تایپ پیشنهادهای داده‌های فعلی Oracle را ببینید. هر دو همچنان متن آزاد معتبر بپذیرند. نمایش پیشنهاد ممکن است اندکی بعد از بازشدن فرم انجام شود.

۴. «جزئیات فنی» را در انتهای فرم باز/بسته کنید؛ با «انصراف» به فهرست برگردید.

۵. یک کارمزد موجود را انتخاب کنید؛ «ویرایش تعریف» باید مشخصات **همان کارمزد** را پیش‌بارگذاری کند. با «انصراف»، داده‌های Oracle نباید تغییر کنند. سپس تب نسخه و لینک طراح قواعد را بررسی کنید.

۶. ساختار اصلی منو و مسیر `/fee2/studio` باید مستقل و بدون تغییر باقی بمانند.

## وضعیت آزمون
آزمون‌های ایستا و Regressions در بسته محلی اجرا شده‌اند. کامپایل کامل Angular، اتصال زنده Oracle، و آزمون واقعی مرورگر **باید توسط شما روی محیط ویندوز انجام شود**.
