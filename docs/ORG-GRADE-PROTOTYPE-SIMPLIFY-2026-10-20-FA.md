# اصلاح ساده‌سازی درجه‌بندی ORG — مخصوص پروتوتایپ

## هدف و مبنا

مبنای Patch فایل `core-banking-prototype-v0-2026-10-19-1129.zip` است.

- ثبت و ویرایش درجات شعبه از فرم «تعریف درجات واحدهای سازمانی»؛
- تخصیص مستقیم درجه در فرم «درجه‌بندی واحدهای سازمانی»، بدون مصوبه، Maker/Checker یا نقش امنیتی جدید؛
- حفظ دوره قبلی هنگام تغییر درجه و جلوگیری از تداخل دوره‌ها؛
- نمایش تاریخ‌های شمسی و سوابق؛
- حذف محدودیت ایجاد و فعال‌سازی شعبه که Patch قبلی اضافه کرده بود؛
- حفظ جداول و داده‌های قبلی، بدون حذف یا انتقال خودکار.

## نصب

**فقط محتویات ZIP را با حفظ زیرپوشه‌های آن در Root پروژه Overlay کنید.** ZIP هیچ فایل مستقلی در Root ندارد. از کپی فایل‌هایی نظیر `README-START-FA.md` و `manifest.json` در Root خودداری کنید.

مسیر پروژه: `D:\Projects\core-banking-prototype-v0`

1. از پروژه نسخه پشتیبان بگیرید.
2. فایل‌های ZIP را روی مسیرهای متناظر کپی و جایگزین کنید.
3. در SQL Developer با کاربری که اجازه تغییر ساختار `ORG` دارد، فایل زیر را با **F5** اجرا کنید:
   `database\oracle\org\grade\ORG-GRADE-PROTOTYPE-01-ALLOW-DIRECT-ASSIGN.sql`
4. در Root پروژه اجرا کنید:
   `node tools\verify-org-forms.mjs`
   `node tools\verify-org-grade-p3-p4.mjs`
   `build-production.cmd`
5. برنامه را طبق روش معمول پروژه راه‌اندازی کنید و دو فرم درجه‌بندی را باز نمایید.

**توجه:** اجرای فایل SQL فقط یک بار کافی است و Script برای اجرای مجددِ بی‌اثر طراحی شده است. قبل از اجرای SQL، از بانک نسخه پشتیبان/نقطه بازگشت مناسب داشته باشید. DDL در Oracle Auto Commit است؛ این نسخه از طرف سازنده Patch روی دیتابیس شما اجرا نشده است.

## چرا SQL کوچک لازم است؟

جدول دوره‌ها در P2 اجازه `RECORD_STATE='ACTIVE'` نمی‌داد و وضعیت `APPROVED` به فیلدهای تأیید اجباری وابسته بود. این Patch برای درج مستقیم، از وضعیت `ACTIVE` استفاده می‌کند. SQL فقط CHECK وضعیت را گسترش می‌دهد، یک ایندکس یکتای مکمل برای دوره بدون پایان ایجاد می‌کند و توضیح جدول را به‌روز می‌کند. هیچ جدول، ستون، رکورد یا الزام تأیید قبلی حذف نمی‌شود. رکوردهای `APPROVED` قدیمی صرفاً برای نمایش تاریخچه معتبر درنظر گرفته می‌شوند.

## محدودیت روشن پروتوتایپ

`CREATED_BY='PROTOTYPE'` صرفاً برچسب فنی ثبت است و هویت تأییدشده کاربر نیست. گردش تأیید، الزام سیستمی درجه برای تمام شعب فعال، و مهاجرت داده‌های قدیمی عمداً خارج از این Patch هستند. این نسخه برای تست توسعه است و برای تولید بانکی تأیید نشده است.

آزمون‌های Oracle زنده و Build کامل Maven/Angular باید در محیط پروژه اجرا شوند. خروجی تست استاتیک/کامپایل با Build کامل برابر نیست.
