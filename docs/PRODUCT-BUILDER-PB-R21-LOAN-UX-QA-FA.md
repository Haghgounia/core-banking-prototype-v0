# PB-R21 — بازنگری فرم‌های تسهیلات و ماتریس حاکمیت

**تاریخ:** 2026-10-10  
**مبنا:** Core Banking Prototype 0.11.0 / Product Builder PB-R20 Lite + HF4  
**نوع انتشار:** Source Patch (بدون DDL/DML و بدون تغییر FEE2/DPS2)

## دامنه اصلاح

1. **ماتریس حاکمیت و شواهد قواعد نسخه:** شش ستون معنادار با عرض ثابت و Scroll افقی، خلاصه تعداد کنترل‌ها، تعداد موانع و کنترل‌های پیکربندی‌شده، متن دلایل با شکست خط استاندارد RTL و حفظ نشانه «اتصال اجرایی تأیید نشده». این تغییر صرفاً نمای ارائه گزارش را اصلاح می‌کند؛ خطاهای کسب‌وکار را به موفقیت کاذب تبدیل نمی‌کند.
2. **LOAN_PRODUCT_PROFILE:** فیلدهای `LOAN_TYPE_ID`, `LOAN_USAGE_ID`, `PLAN_TYPE_ID`, `ECONOMIC_SUB_SECTION_ID`, `OPERATION_PARAMETER_ID` به lookup واقعی PDL متصل‌اند. `PLAN_TYPE_ID` مطابق داده واقعی `LOAN_TYPE_PLAN_TYPE` برای عقد انتخابی فیلتر می‌شود. انطباق زیربخش اقتصادی با طرح سمت سرور بررسی می‌شود. `CURRENCY_TYPE_CODE` از کدهای ISO سه‌حرفی فعال مرجع DPS خوانده می‌شود؛ گزینه اشتباه `FOREIGN` برای ستون `VARCHAR2(3)` حذف شده است.
3. **LOAN_PRODUCT_REPAYMENT_RULE:** گروه‌بندی الگو و روش، اقساط، تنفس و پیش‌پرداخت؛ عنوان الگو سیستمی؛ فلگ‌ها Toggle؛ وابستگی‌ها و حداقل/حداکثر توسط Backend کنترل می‌شوند.
4. **LOAN_PRODUCT_COLLATERAL_RULE:** انتخاب وثیقه از رکورد فعال `PDL.LOAN_PRODUCT_COLLATERAL`، سوییچ‌های جایگزینی و وثیقه شخص ثالث و اعتبارسنجی پوشش/اولویت.
5. **LOAN_PRODUCT_PROCESS_RULE:** تفکیک اعتبار پرونده، تصویب، استثناء و مجوز؛ فیلد سطح تصویب استثناء فقط با فعال‌بودن آن مجاز است.
6. **LOAN_FINANCIAL_EXTENSION:** حدود مبلغ و نسبت آورده مشتری؛ حفظ NULL و معنی اعشاری درصد؛ جلوگیری از سقف کمتر از کف.
7. **LOAN_ELIGIBILITY_EXTENSION:** دسته‌بندی شرایط اعتبارسنجی، اشتغال، رتبه ریسک و الزامات ضامن/استعلام.

## منبع گزینه‌های انتخابی

| قلم | منبع |
| --- | --- |
| نوع عقد، مصرف، طرح، زیربخش اقتصادی، پارامتر عملیات | FK واقعی در `PDL`؛ فقط رکوردهای فعال |
| نگاشت نوع عقد به طرح | `PDL.LOAN_TYPE_PLAN_TYPE`؛ فقط رکورد فعال |

| نوع ارز پروفایل | `dps-default-currencies`؛ فقط کد ISO سه حرفی |
| تناوب اقساط | `dps-payment-frequencies` |
| واحد مدت، فاصله اقساط و تنفس | `dps-term-units` |
| سطح تأیید استثناء | `dps-approval-levels` |
| الگو و روش بازپرداخت، روش تنفس، ماهیت متقاضی، وضعیت اشتغال و رتبه ریسک | گزینه‌های قرارداد فرم تأییدشده، مشروط به محدودیت‌های Oracle CHECK (در DDL تحویلی جدول مرجع مستقلی برای این موارد وجود ندارد) |

## اجرا و پذیرش

1. از سورس موجود Backup بگیرید؛ Patch را در همان Root پروژه استخراج کنید و پوشه‌ها را Merge کنید. **هیچ فایل جاوا از HF3** (`ProductBuilderController`, `ProductGovernanceWriteGuard`) در Patch وجود ندارد.
2. `node tools\verify-pb-r19.mjs`، سپس `node tools\verify-rgl-lite-r20.mjs` و `node tools\verify-pb-r21-loan-ux.mjs`.
3. `build-production.cmd` و سپس راه‌اندازی Backend/Frontend جدید.
4. در Product Builder، مرحله ۶ ماتریس را با داده واقعی بررسی کنید و افقی اسکرول کنید. دلایل Ruleهای نامعتبر باید خوانا و واقعی باقی بمانند.
5. در نسخه آزمایشی محصول تسهیلات، هر شش فرم را تست کنید: باز شدن ComboBox، متن فارسی، ایجاد و ویرایش، قفل فیلدهای سیستمی، ارتباط عقد/طرح، سناریوی مرجع غیرفعال، تنفس و پیش‌پرداخت، وثیقه، استثناء و Clone به نسخه متفاوت.
6. با اتصال `SYSTEM`، اسکریپت **صرفاً خواندنی** `docs/install/PDL-LOAN-REFERENCES-R21-READONLY.sql` را در SQL Developer با F5 اجرا کنید تا تعداد رکوردهای مرجع فعال مشخص شود.

در صورت خالی بودن جدول مرجع، وظیفه این Patch تولید ردیف ساختگی نیست؛ فرم پیام نبود مرجع را نشان می‌دهد. رفع واقعی مستلزم Seed معتبر از منبع مصوب است.

**تصاویر دوم و سوم اشاره‌شده توسط کاربر در پیام حاوی درخواست در دسترس نبودند.** تطبیق دقیق پیکسل‌به‌پیکسل برای آن دو تصویر هنوز نیازمند بازبینی تصویری UAT است.
