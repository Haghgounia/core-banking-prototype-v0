# CLT R2 — کارتابل پیش‌نویس معرفی وثیقه (Implementation Checkpoint)

- **تاریخ:** 2026-11-09
- **نقشه راه ثابت:** `CLT-ROADMAP-R1.0`؛ فاز R2 «شناسنامه، معرفی و جست‌وجو»؛ فازهای R0..R7 بدون تغییر.
- **منبع رفتاری:** Collateral UI V1.42، BUC-02/03، SUC-02/03 و API Contract هدف.
- **نوع تحویل:** `IMPLEMENTATION_CANDIDATE`; این تحویل گواهی UAT، اجرای Oracle یا پایان فاز R2 نیست.

## قابلیت‌های پیاده‌سازی‌شده

1. حفظ و تجمیع ۲۴ تغییر شناخته‌شده بسته `CLT-R2-R3-CONSOLIDATED-2026-11-08` در محدوده جست‌وجو، پیش‌بررسی و پیش‌نویس R2؛ فعالیت پیش‌نویس ذیل **R2** طبقه‌بندی می‌شود، نه R3.
2. ایجاد API `GET /api/v1/collaterals/introduction-drafts/mine?page=0&size=20` برای کارتابل شخصی؛ پاسخ از Oracle Stage دریافت می‌شود و فقط داده‌های همان `MAKER_SUBJECT` و `BRANCH_CODE` معتبر را نمایش می‌دهد. اندازه صفحه ۱ تا ۵۰ و شماره صفحه ۰ تا ۱۰۰۰ کنترل می‌شود؛ مرتب‌سازی قطعی `CREATED_AT DESC, DRAFT_ID DESC`.
3. نمایش جدول صفحه‌بندی‌شده «پیش‌نویس‌های ثبت‌شده من» در فرم معرفی، بازیابی هر پیش‌نویس از Backend و نمایش شناسه، مالک، نوع، مبلغ و تاریخ.
4. کپی اطلاعات یک پیش‌نویس ذخیره‌شده به فرم **جدید**؛ رکورد اصلی و Audit تغییر نمی‌کنند؛ شناسه مالک مجدداً باید از CIF انتخاب و اعتبارسنجی شود، نوع غیرفعال یا ویژگی چندمقداری با کپی خودکار وارد نمی‌شود.
5. استفاده از همان DataSource، Starter و Angular موجود؛ هیچ DataSource یا Starter جدید و هیچ فایل IAM اصلاح نمی‌شود.

## مرز فنی و گیت‌های باز

- هیچ `INSERT/UPDATE/DELETE` روی `CLT.COLLATERAL`، صدور شماره انتظامی، فعال‌سازی تخصیص، بیمه، رفع تخصیص یا آزادسازی انجام نمی‌شود.
- ردیف‌های پیش‌نویس **تغییرناپذیر** هستند؛ کپی باعث ایجاد پیش‌نویس جدید با شناسه جدید می‌شود، نه ویرایش خود رکورد پیشین. این رفتار به خاطر Snapshot/Audit و محدودیت Stage تأییدنشده فعلی است.
- اجرای این قابلیت نیازمند وجود جداول مرحله‌ای `CLT_INTRODUCTION_DRAFT` و `CLT_INTRODUCTION_DRAFT_AUDIT` و مجوزهای قبلاً فراهم‌شده است. هیچ DDL در بسته نصب اجرا نمی‌شود؛ اگر Stage موجود نباشد `draftWritesEnabled=false` باقی می‌ماند.
- **G-01/03/12/14/16/17** همچنان باز هستند. گیت شماره انتظامی `NUMBER(19)` و شماره واقعی مشتری قبل از ثبت قطعی حل نشده؛ نمونه V1.42 به‌عنوان سیاست مصوب بانک تلقی نمی‌شود.
- **R1** همچنان نیازمند تکمیل حاکمیت قواعد و Audit است؛ بازگشت به R3 پس از تکمیل R2 انجام می‌شود.
