# وضعیت نقشه راه مصوب CLT-ROADMAP-R1.0 — R6B

**قانون تغییر:** هشت فاز R0 تا R7 بدون تغییر نام یا تعریف باقی می‌مانند.

| فاز | وضعیت بر اساس شواهد گفتگو و سورس |
|---|---|
| R0 تحلیل و تثبیت خط مبنا | تکمیل خط مبنا |
| R1 اطلاعات پایه و حاکمیت قواعد | سورس/Build پیشین؛ تکمیل Oracle و گردش کار باز |
| R2 شناسنامه، معرفی و جست‌وجو | سورس/Build پیشین؛ ثبت قطعی باز |
| R3 ضامن، بیمه و ارزیابی | R3A–R3C Build موفق؛ نوشتن نهایی غیرفعال |
| R4 ظرفیت و تخصیص بین‌دامنه‌ای | R4A–R4D Build موفق؛ ظرفیت اتمیک/Write عملیاتی باز |
| R5 رفع تخصیص، آزادسازی و سوابق | R5A–R5C Build موفق؛ Write مالی و استعلام حقوقی باز |
| R6 تکمیل UI و UAT جامع | R6A Build موفق ولی Route غایب؛ **R6B** اتصال Route و گزارش‌های واقعی/دفتر UAT واردشونده، آماده Build |
| R7 یکپارچه‌سازی، امنیت و آمادگی عملیاتی | IAM کامل نیست؛ ارزیابی Oracle، امنیت، کارایی و تأیید عملیاتی همچنان باز |

## تصمیم مهندسی

R6B شامل رفع مانع ثبت Route و تکمیل گزارش‌های واقعی Read-only است؛ **هیچ وابستگی جدیدی به تکمیل IAM ایجاد نمی‌کند** و مسیر IAM را تغییر نمی‌دهد. اتصال واقعی داده به JWT در Runtime همچنان به تکمیل IAM یا IdP آزمون مجاز وابسته است. این تحویل نباید به‌عنوان تأیید نهایی UAT یا خاتمه R7 گزارش شود.

## ادامه مستقل از IAM

- تکمیل Responsive، Accessibility و رفع عیوبی که در Build/UAT بدون داده مشخص می‌شوند؛
- گزارش‌های CLT با داده واقعی در صورت فراهم بودن Reader و مجوزهای موجود؛
- تکمیل دفتر شواهد UAT و پوشش ۱۵ نمای مرجع بدون نمایش اطلاعات جعلی؛
- تعیین تکلیف شکاف‌های `G-01` تا `G-22` با مالک قواعد کسب‌وکار و DBA، بدون اعمال DDL/DML قبل از تصویب؛
- آماده‌سازی آزمون واقعی Oracle و سناریوهای هم‌زمانی/تراکنش در R7.

**R6B**: وضعیت تحویل = سورس و Installer؛ Windows Build و Browser/Oracle UAT در زمان تدوین سند تأیید نشده.
