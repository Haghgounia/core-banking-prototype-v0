## ۱) شواهد پذیرفته‌شده قبلی

| شاهد | نتیجه محدود و قابل دفاع |
|---|---|
| ثبت شرکت بیمه رکورد ۴۳ | پیام موفق و حضور رکورد در فهرست UI |
| حذف رکورد ۴۳ | حذف عمدی توسط تحلیلگر تأیید شد و دیگر در فهرست نبود |
| ویرایش شرکت بیمه رکورد ۳۵ | نام «بیمه زندگی مفید 22» از Chrome به Firefox منتقل و در مرورگر دوم نمایش داده شد؛ شاهد ماندگاری تغییر |
| جزئیات و فرم ویرایش | استاندارد نسبی CRUD، اطلاعات حسابرسی در بخش بازشونده و تاریخ شمسی در تصویر قابل مشاهده است |
| Build/Startup R1 Closure | در لاگ Windows کاربر، Maven/Angular موفق و Spring Boot روی 8091 شروع شد |

این شواهد **برای پذیرش تمام قواعد شرکت بیمه کافی نیستند**: تغییر `RECORD_VERSION`، تکراری‌بودن کد، کنترل FK، اعتبارسنجی منفی و ممانعت از تغییر هم‌زمان هنوز اثبات نشده‌اند. نتیجه INSURANCE_COMPANY در ماتریس `PARTIAL_UAT` است. ۱۶ جدول دیگر هیچ گواهی CRUD مستقل ندارند.

## ۲) توسعه جدید — CLT R1 17-Table UAT Matrix

- تب پیش‌فرض «اطلاعات پایه وثایق (۱۷ جدول)» به میزکار فعلی UAT افزوده شد؛ هیچ مسیر ماژول جدید یا Starter جداگانه تعریف نشد.
- دکمه «بررسی خواندن هر ۱۷ جدول»: برای هر جدول مجاز `GET /api/v1/collateral/reference/{table}?page=0&size=1` را اجرا می‌کند؛ در صورت وجود رکورد، یک `GET` مستقل با کلید اصلی می‌فرستد و تطبیق شناسه/نسخه را بررسی می‌کند. حداکثر سه جدول هم‌زمان خوانده می‌شوند.
- خالی بودن جدول از شکست API جدا است؛ شمارش واقعی به همراه موفق/ناموفق‌بودن خواندن نمایش داده می‌شود. هر خطای API یا ناسازگاری قرارداد ثبت می‌شود؛ هیچ داده نمونه ساختگی یا پاسخ کش‌شده به‌عنوان سند پذیرش محسوب نمی‌شود.
- چهار نتیجه تحلیلگر برای هر جدول مستقل از نتیجه GET ثبت می‌شود: ثبت/Read-back، ویرایش/نسخه، حذف یا رد حذف مجاز، اعتبارسنجی/وابستگی. هیچ وضعیت PASS خودکار برای CRUD تولید نمی‌شود.
- گزارش JSON فقط نام جدول، تعداد رکورد، نتیجه HTTP و وضعیت/توضیح آزمون را حمل می‌کند؛ **هیچ رکورد، Party، شماره حساب یا payload محرمانه استخراج نمی‌شود**. گزارش قدیمی قابل بازیابی است، اما خواندن جاری از Oracle هنگام import تأیید نمی‌شود و باید دوباره اجرا شود.
- نمایش آیکون‌های مشاهده/ویرایش/حذف با حداقل پهنای ستون عملیات برای سازگاری Firefox بهبود یافت؛ مرورگر واقعی این اصلاح هنوز نیازمند تأیید است.
- امنیت، Spring DataSource مشترک، APIهای مالی، جدول‌ها، Sequenceها، SQL/DDL و IAM تغییر نکرده‌اند؛ ابزار جدید هیچ POST/PUT/PATCH/DELETE اجرا نمی‌کند.

## ۳) گیت R1 و ادامه مسیر

| گیت | وضعیت |
|---|---|
| ۱۷ کاتالوگ ثابت و ۲۰۴ ستون | PASS ایستا در تحویل قبلی |
| Build و Startup CLT-R1-Closure قبلی | PASS بر اساس لاگ کاربر |
| Live 17-table list + independent GET | **منتظر اجرای جدید در محیط بانک**؛ ابزار UI فراهم شده |
| CRUD ۱۷/۱۷ جدول + READ-BACK + کنترل‌ها | **باز**؛ شرکت بیمه فقط Partial UAT |
| G-10: داده سیاست/ضرایب مصوب بانک | **OPEN**؛ مقادیر Demo مرجع تصمیم نیستند |
| G-15: Audit before/after و Maker/Checker | **OPEN**؛ موفقیت CRUD Local جایگزین چرخه ستادی نیست |
| G-16: PENDING در برابر PENDING_APPROVAL | **OPEN** |
| G-17: الگوریتم شماره انتظامی و NUMBER(19) | **OPEN** |
| R2: شناسنامه، معرفی و جست‌وجو | پیگیری طراحی و پیش‌نمایش مجاز؛ ثبت قطعی تا حل گیت‌ها ادعا نمی‌شود |
| R3: ضامن/بیمه/ارزیابی | قواعد کسب‌وکار و تصمیم بیمه‌گر همچنان باز |
| R4/R5/R6/R7 | بدون تغییر دامنه یا اعلام تکمیل |

**معیار خروج:** حداقل بررسی خواندن ۱۷/۱۷ و پذیرش واقعی CRUD و قواعد هر جدول، به‌همراه تعیین تکلیف گیت‌های Governance. این بسته تنها ابزار جمع‌آوری شواهد را فراهم می‌کند؛ فاز R1 را خودکار بسته اعلام نمی‌کند.

**QA این بسته:** کنترل ایستای سورس جدید، آزمون خالص TypeScript مدل UAT، آزمون نصاب و صحت هش. Build/Oracle در محیط بانک پس از نصب باید آزموده شود.
