# CLT-R6L — گیت T1 نمایش واقعی گروه‌های وثیقه

**مبنا:** R6K / Prototype 0.11.0، ۷ نوامبر ۲۰۲۶. **وضعیت سند:** پیاده‌سازی گیت و عیب‌یابی؛ پذیرش واقعی مرورگر پس از اجرای Windows/Oracle تعیین می‌شود.

## چرایی T1

- در R6K، GET گروه‌ها با Node و هدرهای مشابه مرورگر HTTP=200 و GROUPS=28 بود.
- در Chrome واقعی، حتی پس از «بازیابی»، جدول صفر و پیام 403 نمایش داد.
- این تفاوت با افزودن تست واقعی Chrome Headless و ثبت کد رد درخواست، بدون کاهش امنیت، باید حل شود.

## پوشش

- Backend: برای GET محلی `X-CLT-Local-UAT` و `Cache-Control: no-store` صادر می‌کند؛ موارد رد با کدهای ثابت بدون ثبت هدر، شعبه یا اطلاعات حساس مشخص می‌شوند؛ هیچ اجازه جدیدی ایجاد نمی‌شود.
- Frontend: جست‌وجوی گروه‌ها و انواع فعال Oracle با Query Cache-busting اجرا می‌شود، پیام 401/403 همراه با کد گیت نمایش می‌یابد و داده ساختگی جایگزین نمی‌شود.
- آزمون مرورگر: Chrome تازه بدون Proxy/Extension به JAR راه‌اندازی‌شده متصل و Grid را از نظر ۲۰ رکورد صفحه اول و مجموع ۲۸ رکورد کنترل می‌کند؛ نتیجه `PASS` فقط بعد از مشاهده DOM است.
- در صورت شکست، خروجی `logs/clt-r6l-t1-browser-result.json` و وضعیت `T1_FAIL` تولید می‌شود؛ شمارش داده بدون نمایش UI، قبولی نیست.

## داده و محدودیت‌ها

- در T1 هیچ DML/DDL لازم یا مجاز نیست. ۲۸ گروه از قبل ثبت شده‌اند.
- `CLT.COLLATERAL_TYPE=0` و `CLT.COLLATERAL=0` برای آزمون مثبت R2/R3 مانع داده‌ای‌اند، اما نباید باعث شکست نمایش گروه‌ها شوند.
- برنامه آزمون بعدی: T2 نمایش و جست‌وجو/صفحه‌بندی؛ T3 منفی و خالی؛ T4 اطلاعات نوع وثیقه با سیاست مصوب. تأیید T1 پیش‌نیاز ورود به T2 است.

## معیار خروج

```
CLT_R6L_API_CONTRACT_PASS; GROUPS=28
CLT_R6L_BROWSER_E2E_PASS; PAGE_1_ROWS=20; TOTAL=28
CLT_R6L_T1_PASS
```

خروجی موفق Build یا API به‌تنهایی جایگزین `BROWSER_E2E_PASS` نیست.
