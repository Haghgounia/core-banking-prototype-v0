# CLT-R6G-HF1 — رفع خطای راه‌اندازی حالت محلیِ خواندنی

تاریخ: 2026-11-04 | مرجع ثابت: CLT-ROADMAP-R1.0 | پروژه: Core Banking Prototype 0.11.0

## شواهد مشاهده‌شده

- `CLT_R6G_INSTALL_AND_BUILD_PASS` و اجرای JAR نسخه `0.11.0` ثبت شد.
- فرایند Spring Boot با `CLT_REFERENCE_READ_CONFIG_DENIED` در `CollateralReferenceReaderPool` متوقف شد.
- مسیر اجرای سازنده `CollateralReferenceReaderPool(CollateralReferenceProperties)` نشان می‌دهد که در آن نقطه شاخه محلی انتخاب نشده و اعتبارسنجی تنظیمات JWT و حساب Oracle مستقل اجرا شده است.
- دلیل دقیق اولویت نداشتن تنظیمات محیطی در محیط کاربر، بدون امکان مشاهده تنظیمات واقعی او، قطعی نیست. این اصلاح دو منبع متفاوت برای انتخاب حالت محلی را حذف می‌کند.

## اصلاح

1. تنها مرجع فعال‌سازی حالت محلی `CLT_LOCAL_UAT_READONLY_ENABLED` در Environment است. همان متغیری که `SecurityFilterChain` بر پایه آن فعال می‌شود، اکنون منبع مستقیم `CltLocalUatProperties` نیز است.
2. کد شعبه فقط از `CLT_LOCAL_UAT_BRANCH_CODE` سمت سرور اخذ می‌شود؛ از کلاینت، Header و JWT خوانده نمی‌شود.
3. وابستگی غیرضروری به یک `@ConfigurationProperties` مجزای `core-banking.collateral.local-uat` حذف شد؛ مقادیر متناقض آن دیگر نمی‌توانند انتخاب pool را تغییر دهند.
4. فیلتر Loopback، محدودیت GET، deny-all برای مسیرهای نامجاز، گیت‌های READ و تمام گیت‌های WRITE بسته همچنان برقرار هستند.
5. دو آزمون JUnit جدید، تعارض مقادیر Environment و مسیر واقعی انتخاب Reader Pool بدون JWT، در کنار حفظ سیاست Fail-Closed در حالت غیرمحلی را کنترل می‌کنند.

## محدوده

- فقط دو کلاس پیکربندی محلی CLT و دو مجموعه JUnit جدید تغییر/افزوده می‌شود؛ به‌همراه اسناد و آزمون ایستای CLT.
- هیچ فایل IAM، سایر ماژول‌ها، DDL/DML اوراکل و داده بانکی تغییر نمی‌کند.
- دسترسی به DB هنوز از `DataSource` فعلی Prototype برای SELECTهای موجود استفاده می‌کند؛ حساب DB به‌صورت ذاتی فقط‌خواندنی نیست.
- حالت موقت R6G صرفاً روی همان رایانه (`127.0.0.1`) و داده‌های غیرمحرمانه آزمون قابل استفاده است؛ هر فرایند محلی بالقوه می‌تواند GETهای مجاز را فراخوانی کند، پس برای محیط مشترک/عملیاتی مجاز نیست.

## نصب و آزمون

1. نمونه قبلی Backend را در صورت اجرا متوقف کنید.
2. فایل ZIP را Extract و از داخل پوشه جدید دستور زیر را اجرا کنید:
   `INSTALL-BUILD-AND-RUN.cmd "D:\Projects\core-banking-prototype-v0"`
3. کد شعبه واقعی مربوط به داده آزمایشی CLT را وارد کنید (در لاگ قبلی کد 1 وارد شد؛ معتبر بودن آن در Oracle تأیید نشده است).
4. اگر Backend بالا آمد، ابتدا `http://127.0.0.1:8091/actuator/health` و سپس `http://127.0.0.1:8091/#/collateral/uat` را بررسی کنید.
5. کنترل‌های R6D و R6E را اجرا کنید و JSON جدید را ارسال کنید. HTTP=200 به‌تنهایی تأیید UAT یا عملیات مالی نیست.

## معیار پذیرش

- Build و JUnit: PASS در ماشین پروژه (در محیط تولید بسته Maven در دسترس نیست).
- آغاز Spring Boot بدون `CLT_REFERENCE_READ_CONFIG_DENIED`: ضروری.
- GETها از همان رایانه با کد شعبه ثابت، بدون JWT کاربر، در حالت local اجرا شوند؛ POST/PUT/PATCH/DELETE ممنوع باقی بمانند.
- Oracle و UAT همچنان تا مشاهده شواهد Runtime، تأیید نشده‌اند.
