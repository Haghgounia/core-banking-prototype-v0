# CLT — بازگشت فرم شرکت‌های بیمه به CRUD استاندارد و ویرایش وب‌سایت

## هدف
پس از پایان عملیات ورود لوگوها در Oracle، بخش‌های موقت دریافت دسته‌جمعی و بارگذاری فایل از فرم شرکت‌های بیمه حذف شده‌اند. نمایش لوگو و نشانی وب‌سایت حفظ شده است. افزودن، مشاهده، ویرایش و حذف در الگوی ثابت ۱۷ جدول CLT باقی می‌مانند.

## قرارداد نسخه
- جدول: `CLT.INSURANCE_COMPANY`.
- فیلد اختیاری جدید: `WEBSITE_URL VARCHAR2(500 CHAR)`؛ از قبل در Oracle ایجاد شده است.
- فیلد `LOGO BLOB`: خواندنی در فرم، داده و سرویس قبلی بدون تغییر؛ این Patch هیچ SQL برای BLOB اجرا نمی‌کند.
- فیلد وب‌سایت در سطر لیست به‌صورت URL قابل کلیک و در جزئیات به‌صورت آدرس کامل دیده می‌شود.
- فیلد وب‌سایت در همان ویرایشگر اصلی با دکمه مشترک «ذخیره» قابل تغییر/پاک‌کردن است؛ حتی ایجاد شرکت جدید با وب‌سایت نیز پشتیبانی می‌شود.
- Backend تنها برای `INSURANCE_COMPANY` مقدار `WEBSITE_URL` را به فهرست فیلدهای مجاز تغییر اضافه می‌کند. برای ۱۶ جدول دیگر هیچ فیلد جدیدی مجاز نشده است.
- مقدار فقط URL معتبر HTTP/HTTPS با طول حداکثر ۵۰۰ نویسه و بدون userinfo پذیرفته می‌شود؛ مقدار `NULL` برای پاک‌کردن قابل استفاده است.
- فیلدهای استاندارد و وب‌سایت در **همان درخواست و تراکنش** به‌روزرسانی می‌شوند. کنترل هم‌زمانی `RECORD_VERSION` فعال است.
- پس از ذخیره، یک GET مستقل برای فیلدهای ثابت و یک GET مستقل برای وب‌سایت انجام می‌شود. پیام موفقیت فقط پس از تایید هر دو نمایش داده می‌شود.
- بر اساس وضعیت پایگاه داده گزارش‌شده در گفتگو، ۴۲ شرکت و ۴۱ نشانی سایت قبلاً ثبت شده‌اند؛ این بسته خودکار داده را تغییر نمی‌دهد.

## نصب
1. نسخه در حال اجرای برنامه را متوقف کنید؛ پورت ۸۰۹۱ باید آزاد باشد.
2. ZIP را خارج از مخزن پروژه استخراج کنید.
3. از CMD در پوشه استخراج‌شده اجرا کنید:

```cmd
INSTALL-BUILD-START.cmd "D:\Projects\core-banking-prototype-v0"
```

4. پس از Build و Startup، صفحه `http://127.0.0.1:8091/#/collateral/reference-data/INSURANCE_COMPANY` را باز کنید.
5. به‌عنوان UAT، یک شرکت را ویرایش کنید، وب‌سایت را تغییر دهید، روی دکمه اصلی ذخیره کلیک کنید و مقدار را در مرورگر دوم یا بعد از Refresh مشاهده نمایید.

نصاب با هش سورس از تغییرات غیرمنتظره جلوگیری می‌کند، از فایل‌های قبلی پشتیبان می‌گیرد و در صورت شکست Build به وضعیت پیش از نصب بازمی‌گردد. اگر سورس تغییر کرده باشد، به‌جای بازنویسی پیام `PROJECT_FILE_MODIFIED` صادر می‌شود.

## QA و محدوده
- تست Java مستقل در سطح سیاست وب‌سایت و منطق فیلد اختصاصی: پاس.
- اعتبارسنجی TypeScript برای URL و کنترل‌های سورس CRUD: پاس.
- نصب مجدد و کنترل هش فایل‌های نصب: آزمایش‌شده.
- Build رسمی Windows، دسترسی Oracle و آزمون مرورگری این نسخه: نیازمند اجرا روی محیط کاربر و **هنوز در این محیط تأیید نشده‌اند**.
- IAM، Schema Migration، عملیات مالی و نقشه راه R0–R7 تغییری نکرده‌اند؛ G-16/G-17 باز می‌مانند.

## نکته معماری
کاتالوگ رسمی ۲۰۴ ستونی رفرنس CLT و مدل آن تغییر نکرده است. `WEBSITE_URL` یک Extension اختصاصی برای جدول بیمه است تا سایر جدول‌های اطلاعات پایه و کنترل‌های تطبیق ۱۷/۱۷ آسیب نبینند. به‌روزرسانی وب‌سایت توسط کد Generic CRUD Oracle انجام می‌شود، نه API/نصاب مستقل.
