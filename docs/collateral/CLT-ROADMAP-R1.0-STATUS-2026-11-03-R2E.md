# وضعیت نقشه راه CLT-ROADMAP-R1.0 پس از R2E

**نسخه محصول:** `0.11.0`؛ **دامنه:** Collateral؛ **تاریخ:** 2026-11-03.

نام و ترتیب فازهای مصوب **R0 تا R7 تغییر نکرده‌اند**.

| مرحله | شواهد انجام‌شده | وضعیت و باقی‌مانده |
|---|---|---|
| R0 — تحلیل و تثبیت خط مبنا | XMI/UI/SQL/Roadmap با Gap Register | تحلیل ایستا تکمیل؛ تصویب کسب‌وکار شکاف‌ها باز |
| R1 — اطلاعات پایه و حاکمیت قواعد | R1A کاتالوگ و سرویس‌های خواندن؛ R1B پیشنهاد و بازبینی تغییر | آزمایش Oracle/امنیت و داده‌های مصوب بانک باز |
| R2 — شناسنامه، معرفی و جست‌وجو | R2A رجیستری خواندنی؛ R2B پیش‌نویس؛ R2C اقلام شمارشی و Preflight؛ R2D بازبینی؛ **R2E بازاعتبارسنجی ذخیره‌شده و پرونده تصمیم ثبت قطعی** | صدور شماره، ثبت قطعی اتمیک، هویت پایدار دارایی، اصلاحیه و UAT باز |
| R3 — ضامن، بیمه و ارزیابی | بدون تغییر در این تحویل | شروع بعدی طبق اولویت پروژه |
| R4 — ظرفیت و تخصیص بین‌دامنه‌ای | بدون تغییر | باز |
| R5 — رفع تخصیص، آزادسازی و سوابق | بدون تغییر | باز |
| R6 — تکمیل رابط کاربری و UAT جامع | UI مربوط به بازبینی و آمادگی در R2 به‌صورت تدریجی افزوده شد | UAT جامع باز |
| R7 — یکپارچه‌سازی، امنیت و آمادگی عملیاتی | Build قبلی R2A توسط کاربر تأیید شده؛ QA R2E از نظر نصب/سیاست انجام شده | Build/Startup/JWT/Oracle/UAT R2E باید مستقلاً تأیید شود |

**شکاف‌های باز برای ثبت قطعی:** `G-01`, `G-03`, `G-12`, `G-14`, `G-16`, `G-17`.

**تغییرات این تحویل:** ۱۵ فایل Collateral (۵ به‌روزرسانی و ۱۰ فایل جدید)، به‌علاوه تضمین نصب خودکار R2D در صورت نصب‌نشدن آن. هیچ کلاس مشترک Backend/Frontend، IAM، CIF، DPS2 یا دیتابیس توسط Installer تغییر نمی‌کند.

**اقدام بعدی:** تصویب ADR شماره انتظامی و هویت Asset توسط تصمیم‌گیر کسب‌وکار/معمار/DBA؛ سپس پیاده‌سازی و آزمون Transaction واقعی در همان R2. توسعه R3 می‌تواند به‌صورت مستقل و بدون ادعای بسته‌شدن R2 آغاز شود.
