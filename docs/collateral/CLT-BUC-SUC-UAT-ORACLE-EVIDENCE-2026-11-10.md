# CLT / BUC-SUC UAT – shared-Oracle evidence journal

**تاریخ:** ۱۰ نوامبر ۲۰۲۶ | **نسخه محصول:** `0.11.0` (بدون تغییر) | **دامنه:** وثایق CLT، بدون توسعه IAM

## علت توسعه

آخرین تحویل `CLT-BUC-SUC-UAT-EVIDENCE-GAPS-2026-11-10` ماتریس ۱۶ BUC / ۲۰ SUC / ۳۲ سناریو، خروجی JSON و فهرست شکاف‌ها را اضافه کرد. نتایج UAT در `CollateralBusinessUatSessionService` فقط در حافظه مرورگر بودند. نسخه جدید **مسیر واقعی و محافظت‌شده ذخیره/بازیابی Oracle** را در همان Backend و همان DataSource مشترک پروژه پیاده می‌کند. **در نبود Schema مصوب، ذخیره صادقانه غیرقابل‌دسترس نشان داده می‌شود و خروجی JSON فعلی پابرجاست.**

## قراردادها

| Domain/API | شرح و تضمین |
|---|---|
| `GET /api/v1/collaterals/uat/business-evidence` | استعلام Schema و خواندن نسخه و ۳۲ نتیجه واقعی، محدود به `branch_code` معتبر؛ در صورت عدم آمادگی Oracle: `available=false` و بدون ادعای ذخیره |
| `PUT /api/v1/collaterals/uat/business-evidence` | ذخیره دستی تمام ۳۲ نتیجه؛ `expectedRevision` ضروری، کنترل optimistic CAS و قفل Oracle برای جلوگیری از lost update؛ `409` در تعارض |
| `GET /api/v1/collaterals/uat/business-evidence/history` | آخرین ۵۰ رویداد ثبت‌شده (نسخه، سناریو، وضعیت قبلی/جدید، زمان و عامل) |
| `CollateralBusinessUatEvidencePolicy` | نام‌گذاری دامنه‌ای بدون پیشوند فاز؛ فقط `BUC-01-P/N..BUC-16-P/N`، چهار وضعیت مجاز، محدودیت طول یادداشت، رد شناسه تکراری یا ناشناس |
| `CollateralBusinessUatEvidenceService` | DataSource مشترک؛ `TransactionTemplate` برای CAS، نتیجه و رخداد در یک تراکنش؛ عدم ثبت نتیجه ساختگی در زمان خرابی Oracle |

`SCOPE_clt.collateral.read` برای مشاهده لازم است. ذخیره در حالت بانکی به `SCOPE_clt.collateral.uat.write` مستقل نیاز دارد. در Prototype محلی، صرفاً توکن داخلیِ سروریِ Loopback (همان قرارداد Stage تحلیلگر، نه JWT ارسالی از مرورگر) مجاز است. **این مجوز فقط برای جداول کمکی UAT است و هیچ مجوز تخصیص/رفع تخصیص/آزادسازی ایجاد نمی‌کند.**

## مدل فیزیکی Candidate و وضعیت تصویب

**Schema پیشنهادی هنوز تصویب/اجرا نشده است**. فقط فایل‌های زیر تحویل شده‌اند:

- `database/oracle/clt/business-uat/00_CLT_BUC_UAT_READONLY_DISCOVERY.sql` برای استعلام فقط‌خواندنی وضعیت واقعی
- `database/oracle/clt/business-uat/01_CLT_BUC_UAT_SCHEMA_CANDIDATE_NOT_APPROVED.sql` با `RAISE_APPLICATION_ERROR(-20961)` و تمام DDL به‌شکل کامنت (Fail-Closed)

| جدول / Sequence | کاربرد |
|---|---|
| `CLT_BUC_UAT_RUN` | یک پرونده قابل‌ویرایش UAT در هر شعبه و مجموعه سناریو، دارای Revision |
| `CLT_BUC_UAT_RESULT` | Snapshot آخرین وضعیت ۳۲ سناریو، FK و PK چندستونی |
| `CLT_BUC_UAT_EVENT` | رویدادهای تغییرناپذیر نتیجه، قبل/بعد، نسخه، عامل و زمان |
| `CLT_BUC_UAT_EVENT_SEQ` | شناسه ترتیبی رویداد |

**DDL خودکار، مهاجرت Schema، Oracle Financial DML یا تأیید بانک در نصب Patch اجرا/ایجاد نمی‌شود.** پس از تصمیم مستقل DBA و استقرار جداگانه ساختار مصوب، مسیر آماده‌سازی مجدد در UI به‌صورت استعلام زنده فعال خواهد شد؛ تا آن موقع نتیجه «ذخیره در Oracle» نمایش داده نخواهد شد.

## قواعد ردیابی و پذیرش

- UAT دارای دو گونه **POSITIVE/NEGATIVE** برای هر BUC است. `PASS` تنها اعلام دستی تحلیلگر و همراه یادداشت غیرمحرمانه است.
- اصلاح `FAIL → PASS` یا `BLOCKED → PASS` تنها یک رویداد UAT ایجاد می‌کند؛ نه تأیید مستقل بانک، نه شاهد اجرای مالی و نه نتیجه خودکار Oracle.
- پیش‌شرط اولیه خروج از آزمون کسب‌وکاری: ۳۲/۳۲ سناریوی PASS با شاهد. **این شرط به‌تنهایی کافی نیست**: ۱۰ آزمون رسمی UI، کنترل RTL ۱۳۶۶، عملیات واقعی UI → Backend → Oracle، قواعد/داده مصوب و تأیید بانک مستقل باقی می‌مانند.
- وقتی چند تحلیلگر هم‌زمان داده را تغییر دهند، Revision اجباری است؛ در تعارض، وضعیت محلی حفظ و بازیابی/مقایسه صریح درخواست می‌شود، بدون بازنویسی بی‌صدا.
- واردکردن JSON نسخه‌های قبلی (`CLT-R6-BUC-EVIDENCE-1` و `CLT-BUC-SUC-UAT-EVIDENCE-2`) همچنان امکان‌پذیر است؛ نام فاز فقط در تاریخچه سازگاری فایل قدیمی آمده است.
- داده شخصی، شماره حساب، اطلاعات محرمانه و سایر جزئیات مشتری نباید در توضیح شواهد UAT ثبت شوند. پیوند به شناسه خطای غیرمحرمانه کافی است.

## آزمون‌های توسعه‌دهنده و وضعیت

- سیاست Java21: تست مستقل ۷۸ کنترل، شامل موارد منفی.
- شبیه‌سازی Spring/JDBC و قفل/Revision/Branch/History: ۳۱ کنترل (بدون DB زنده).
- اعتبارسنجی TypeScript مستقل: ۳۸ کنترل مثبت و منفی.
- آزمون قرارداد سورس و کنترل عدم DDL: ۲۰۴ کنترل.
- Build واقعی Maven/Angular و Oracle Live UAT فقط در محیط مقصد قابل تأیید خواهند بود؛ در محیط ساخت این Patch هیچ ادعای اجرای آن‌ها نشده است.

## وضعیت نقشه راه

ساختار مرجع R0 تا R7 دست‌نخورده است. این خروجی بخشی از تکمیل آزمون یکپارچه کسب‌وکاری است، **نه شماره نسخه، نام کلاس، یا اعلام بسته‌شدن فاز**. گام باقی‌مانده: تصمیم مستقل DBA درباره جدول‌های UAT، اجرای واقعی ۳۲ سناریو و بستن Gapها با شواهد منطبق بر Oracle و پذیرش بانک.
