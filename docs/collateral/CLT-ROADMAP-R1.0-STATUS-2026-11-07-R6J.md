# وضعیت R6J در نقشه راه ثابت CLT-R1.0 — ۱۴۰۵/۰۸/۱۶

## محدوده بدون تغییر
نقشه راه مورد تأیید R0 تا R7 بدون بازنام‌گذاری یا تغییر دامنه باقی می‌ماند. این بسته اصلاح رابط کاربری فاز R6 است، نه شروع فاز جدید.

## شواهد قطعی ورودی
- بارگذاری و COMMIT عدد ۲۸ در `CLT.COLLATERAL_GROUP` تأیید کاربر.
- تشخیص Oracle: ۲۸ گروه فعال؛ ۰ نوع وثیقه؛ ۰ وثیقه عملیاتی.
- نصب R6I: `CLT_R6I_ORACLE_GROUP_PARITY_PASS=28/28` و `CLT_R6I_UAT_DATA_GATE=NO_ACTIVE_TYPES`.
- تصویر کاربر در ۱۴۰۵/۰۸/۱۶: صفحه `/#/collateral/reference-data/COLLATERAL_GROUP` با پیام خطای دسترسی قدیمی و ۰ رکورد.

## شکاف رفع‌شده در سورس R6J
- فرم مرجع هنوز از GET مستقل `/api/v1/collateral/reference/COLLATERAL_GROUP` استفاده می‌کرد؛ این مسیر نیازمند سطح دسترسی `clt.reference.read` است.
- R6I مسیر مجزای مجاز GET `/api/v1/collaterals/groups` را در Local UAT داشت که ۲۸ گروه را برگرداند.
- R6J رابط کاربری `COLLATERAL_GROUP` و `COLLATERAL_TYPE` را صرفاً در نمای فقط‌خواندنی به این دو endpoint فعال وصل می‌کند.
- وضعیت خطا از «جدول خالی» تفکیک می‌شود؛ جزئیات فقط شامل ستون‌های واقعی پاسخ API است. درخواست تغییر برای این دو نمای عملیاتی غیرفعال می‌شود.
- برای ۱۵ جدول دیگر قرارداد مستقل Reference و سیاست دسترسی موجود حفظ می‌شود. هیچ مجوز، endpoint یا نوشتن جدیدی اضافه نمی‌گردد.
