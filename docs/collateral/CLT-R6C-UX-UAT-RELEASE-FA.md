# CLT R6C — یکپارچگی ناوبری، فهرست و شواهد UAT

تاریخ: ۱۴۰۵/۰۸/۱۳ — مرجع: `CLT-ROADMAP-R1.0` — نسخه پروژه: `0.11.0`

## خط مبنا و محدوده

- مبنا: سورس ارسالی `core-banking-prototype-v0-2026-11-04-1245.zip` به‌همراه ادغام موفق `R6B-HF1`؛ نصب واقعی `R6B-HF1` در Windows با `CLT_R6B_PROJECT_BUILD_AND_JAR=PASS` گزارش شده است.
- تغییرات R6C **فقط** در `frontend/src/app/features/collateral/` و `docs/collateral/` و `tools/clt/r6c/` قرار دارند. Route و منوی سراسری، Backend، اسکیما و جداول Oracle، سرویس‌های مالی و سایر ماژول‌ها تغییر نمی‌کنند.
- گیت‌های امنیت و عملیات مالی موجود حفظ می‌شوند. این بسته برای دسترسی 401/403 هیچ دورزدن امنیتی ایجاد نمی‌کند.

|---|---|---|---|
| R6C-01 | جست‌وجو در فهرست | API فیلتر شماره انتظامی داشت ولی UI آن را در معرض کاربر قرار نمی‌داد | فرم مستقل فیلتر، اعمال/پاک‌سازی، اعتبارسنجی شماره و صفحه‌بندی در همان فیلتر |
| R6C-02 | ارقام فارسی و عربی | استعلام مستقیم فقط ارقام ASCII را می‌پذیرفت | عادی‌سازی رشته‌ای ۱۹رقمی بدون Number/parseInt؛ عدم پذیرش صفر پیشرو و کاراکتر غیرعددی |
| R6C-03 | ناوبری | دکمه‌های بخش‌ها فقط سیگنال محلی را تغییر می‌دادند | تغییر آدرس واقعی `/collateral/registry`، `/collateral/lookup`، `/collateral/introduction` و `/collateral/uat` برای Back/Forward |

| R6C-09 | مستندات پوشش | بعضی توضیح‌های ۱۵ نمای مرجع به Route ثبت‌نشده اشاره داشتند | اصلاح توضیح به Route موجود، با حفظ تفاوت پوشش رابط و پذیرش Runtime |

## محدودیت‌ها — صریح و قابل آزمون

۱. **خروجی Build و JAR تا R6B-HF1 موفق بوده است.** موفقیت Build ویژه R6C، پس از نصب Windows باید تأیید شود.
۲. این بسته **هیچ** آزمون مرورگر/Oracle/JWT را به‌صورت واقعی اجرا نکرده است. خواندن فهرست، گزارش و سوابق نیازمند سرویس‌ها، Oracle و مجوزهای موجود است؛ در نبود مجوز، خطای واقعی سرور نمایش داده می‌شود.
۳. ۱۰ سناریوی UAT هنوز به‌صورت پیش‌فرض `NOT_RUN` هستند؛ عدد ۱۵ صرفاً تعداد نماهای مرجع است، نه تعداد نماهای پذیرفته‌شده.
۴. نتایج UAT در حافظه موقت SPA نگهداری می‌شوند و با Reload صفحه از دست می‌روند؛ برای استمرار، باید JSON خروجی ذخیره و سپس Import شود. از درج داده محرمانه بانکی در یادداشت‌ها خودداری شود.
۵. قابلیت‌های ثبت نهایی، تخصیص، رفع تخصیص و آزادسازی واقعی همچنان **غیرفعال** هستند؛ R6C هیچ نوشتن مالی یا گیت جدیدی ندارد.
۶. وضعیت عملیاتی R1–R5، و شکاف‌های G-01 تا G-22، با این Patch بسته نمی‌شوند.

## مسیرهای موجود و بدون تغییر

- ` /collateral ` : فهرست وثایق
- ` /collateral/registry ` : فهرست وثایق (Legacy حفظ‌شده)
- ` /collateral/lookup ` : استعلام مستقیم
- ` /collateral/introduction ` : معرفی وثیقه
- ` /collateral/reference-data ` : داده‌های مرجع
- ` /collateral/reports ` : گزارش‌های خواندنی
- ` /collateral/uat ` : دفتر پذیرش

برای مثال، لینک داخلی ` /collateral/lookup?section=valuation ` **فقط پنل ارزیابی را پس از جست‌وجوی امن کاربر باز می‌کند**؛ شماره انتظامی یا شناسه طرف در Query Parameter ارسال نمی‌شود.

## کنترل‌ها و پذیرش

1. ورود از منوی مدیریت وثایق به فهرست؛ فیلتر شماره انتظامی با ارقام فارسی، پاک‌سازی و تعویض صفحه.
2. ورود مستقیم و امتحان UAT-01/02؛ تغییر شماره، شناسنامه قبلی را بلافاصله پاک کند.
3. کلیک روی یک مورد از ۱۵ نمای مرجع؛ بخش پیشنهادی پس از ورود شماره انتظامی نمایش داده شود.
4. ثبت یک نتیجه نمونه غیرمحرمانه UAT، رفتن به گزارش‌ها و بازگشت به UAT؛ نتیجه در همین نشست حفظ شود.
5. خروجی و ورود دوباره JSON نسخه‌دار؛ همه ۱۰ سناریو وجود داشته باشند و هیچ نتیجه‌ای خودکار PASS نباشد.
6. روی پاسخ 401/403 سرویس گزارش‌ها فقط خطای واقعی و بدون داده ساختگی نمایش داده شود.
7. `INSTALL-AND-BUILD.cmd` باید `CLT_R6C_PROJECT_BUILD_AND_JAR=PASS` و `CLT_R6C_ANGULAR_NG8102=0` بدهد.

**شواهد UAT عملیاتی:** صرفاً توسط تحلیلگر و در مرورگر واقعی ثبت می‌شوند؛ آزمون‌های Node یا Build جای آن‌ها را نمی‌گیرند.
