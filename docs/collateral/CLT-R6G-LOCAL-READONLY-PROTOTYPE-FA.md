# CLT-R6G — حالت خواندنی محلی برای آزمون وثایق، مستقل از IAM

- مرجع: `CLT-ROADMAP-R1.0`، نسخه محصول `0.11.0`، Baseline: `2026-11-04-1518.zip`.
- هدف: رفع اختلاف محیط اجرایی CLT با سایر دامنه‌های Prototype برای **خواندن** واقعی از Oracle و اجرای R6D/R6E؛ بدون IdP، JWKS، توکن ورودی یا تغییر IAM.
- پیش‌فرض: `CLT_LOCAL_UAT_READONLY_ENABLED=false`. مسیر JWT امضاشده اصلی برای تمام محیط‌های غیرمحلی بدون تغییر حفظ می‌شود.
- تنها با `SERVER_ADDRESS=127.0.0.1`، `CLT_REFERENCE_READS_ENABLED=true`، `CLT_REGISTRY_READS_ENABLED=true` و **کد شعبه صریح سمت سرور** فعال می‌شود؛ درخواست با مبدأ غیرمحلی، Host غیرمحلی و هدرهای Forwarded رد می‌شود.
- سمت Backend فقط GET مجاز است. POST، PUT، PATCH، DELETE و مسیرهای تغییر اطلاعات پایه، صف بررسی و Journalهای درخواست مسدود می‌مانند. Scopeهای maker/checker، تخصیص و پیش‌نویس اعطا نمی‌شوند.
- در حالت محلی، Repositoryهای CLT، همان DataSource اوراکل برنامه را برای SELECTهای مشخص‌شده در سورس استفاده می‌کنند. **این یک حساب DB اختصاصی SELECT-only نیست**؛ فقط مسیر HTTP و SQL این قسمت Read-only است. برای داده واقعی یا محیط غیرمحلی از حساب مستقل با حداقل مجوز استفاده کنید.
- شاخه از `CLT_LOCAL_UAT_BRANCH_CODE` گرفته می‌شود؛ تغییر آن از طریق Query، Header، Cookie یا Form پذیرفته نیست. احراز کاربر واقعی در این حالت صورت نمی‌گیرد و صرفاً یک هویت مصنوعی سمت سرور با دو Scope خواندنی ساخته می‌شود.
- هیچ گواهی Oracle، بانک، Audit، UAT یا مجوز مالی از اجرای این حالت استنتاج نمی‌شود.
- داده محرمانه و نتایج واقعی را در JSON تشخیصی ذخیره نکنید؛ گزارش R6D/R6E همچنان فقط وضعیت HTTP/قرارداد را صادر می‌کند.

## مراحل نصب و اجرا

1. `INSTALL-AND-BUILD.cmd "D:\Projects\core-banking-prototype-v0"`
2. سرویس قدیمی روی پورت `8091` را متوقف کنید، سپس:
   `RUN-CLT-LOCAL-UAT.cmd "D:\Projects\core-banking-prototype-v0" BRANCH_CODE`
   (کد شعبه معتبرِ موجود در محیط DEV را جایگزین کنید؛ اگر حذف شود، از شما پرسیده می‌شود.)
3. در Angular، `/#/collateral/uat` و پنل R6D را اجرا کنید. پس از دریافت 4/4 و یک شناسه وثیقه متعلق به همان شعبه، R6E را اجرا کنید. کد 404 برای شناسه ناموجود/شعبه دیگر به معنای خطای مجوز دسترسی نیست.
4. پس از UAT، برنامه را متوقف و با دستور معمول `bin\start.cmd` اجرا کنید تا تنظیمات موقت از فرایند جدید حذف شوند؛ دسترسی‌ها دوباره به رفتار fail-closed اصلی برمی‌گردند.

## Gate نتیجه

- `R6D 4/4` فقط به معنای قرارداد خواندنی سالم با دیتابیس متصل است، نه تأیید نهایی کسب‌وکار.
- `R6E` به شناسه واقعیِ موجود در شعبه نیاز دارد؛ تا پیش از ورود داده معتبر UAT-01..10 همچنان `NOT_RUN` است.
- بدون اجرای Runtime در ماشین کاربر، وضعیت واقعی Oracle و R6D/R6E **تأیید نشده** است.
- تمام عملیات مالی، ثبت نهایی، تأیید Maker/Checker و Migration خارج از این تغییر هستند.
