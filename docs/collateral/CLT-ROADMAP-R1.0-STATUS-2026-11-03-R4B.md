# وضعیت نسخه‌دار Collateral — R4B

مرجع ثابت `CLT-ROADMAP-R1.0`؛ نام و ترتیب فازهای R0 تا R7 بدون تغییر.

| فاز | آخرین وضعیت اثبات‌شده / کار باز |
|---|---|
| R0 تحلیل و تثبیت خط مبنا | انجام‌شده؛ شکاف‌های معماری ثبت شده |
| R1 اطلاعات پایه و حاکمیت قواعد | R1A/R1B نصب و Build؛ Maker/Checker و Audit روی Oracle هنوز فعال/تأیید نشده‌اند |
| R2 شناسنامه، معرفی و جست‌وجو | R2A–R2E؛ ثبت قطعی/شماره انتظامی G-14/G-17 و اصلاحیه G-01 باز |
| R3 ضامن، بیمه و ارزیابی | R3A–R3C Build موفق تا آخرین گزارش کاربر؛ چرخه نهایی/سیاست‌ها باز |
| R4 ظرفیت و تخصیص بین‌دامنه‌ای | R4A Build موفق طبق گزارش کاربر؛ R4B قرارداد و پیش‌نمایش فقط‌خواندنی تحویل؛ تخصیص واقعی غیرفعال |
| R5 رفع تخصیص، آزادسازی و سوابق | آغاز نشده |
| R6 تکمیل رابط کاربری و UAT جامع | آغاز رسمی نشده؛ توسعه تدریجی UI انجام شده |
| R7 یکپارچه‌سازی، امنیت و آمادگی عملیاتی | آغاز رسمی نشده؛ شواهد Integration/Runtime هنوز لازم |

## گام بعد

اجرای Build و UAT محدود R4B، سپس بررسی مشترک G-02/G-09/G-13 و قرارداد قابل‌اتکای Caller با تیم‌های IAM و دامین‌های مصرف‌کننده. مسیر پیشرفت R5 می‌تواند موازی با رفع موانع R2–R4 باشد، اما اجازه Write در Oracle و تخصیص فقط پس از تصویب بانک/DBA و تأیید Runtime صادر می‌شود.

## مرز R4B

- Request Preview و Service Preflight فقط‌خواندنی؛ پاسخ تخصیص همیشه رد.
- `Idempotency-Key` صرفاً معتبرسازی UUID و Digest تشخیصی؛ **هیچ ثبت پایدار یا تعهد Replay وجود ندارد**.
- نبود داده/مجوز/معتبر نبودن Client یا شکست DB همیشه منجر به Fail-Closed می‌شود.
