# CLT-R6I — همبندی واقعی گروه، نوع و شناسنامه وثیقه

- نسخه مرجع: `CLT-ROADMAP-R1.0`، فاز R6.
- خط مبنا: سورس `0.11.0` با اصلاح R6H-R5 (Build / JAR / Startup / R6D PASS در محیط کاربر).
- شواهد Oracle (تأیید شده توسط کاربر): `CLT_GROUP_IMPORT_PRECOMMIT_PASS; SOURCE=28; INSERTED=28; ALREADY_PRESENT=0; VERIFIED=28` و `CLT_GROUP_IMPORT_COMMIT_PASS` در ۱۴۰۵/۰۸/۱۳ (۲۰۲۶/۱۱/۰۴).

## دامنه واقعی

1. API `GET /api/v1/collaterals/groups` گروه‌های **فعال** واقعی `CLT.COLLATERAL_GROUP` را با مجوز خواندن وثایق عرضه می‌کند. این API فهرست وثایق یا گزارش ستادی نیست و هرگز شمارنده وثیقه را از شمارنده گروه نمی‌سازد.
2. API `GET /api/v1/collaterals/types` هم‌اکنون `COLLATERAL_GROUP_CODE` را علاوه بر نام گروه برمی‌گرداند. تنها **نوع فعال با گروه فعال** بازگردانده می‌شود.
3. فهرست عملیات `GET /api/v1/collaterals?groupCode=70&page=0&size=20` علاوه بر شرط همیشگی `c.BRANCH_CODE = ?` از پارامتر bind برای گروه استفاده می‌کند؛ هیچ Header یا ورودی دستی شعبه اضافه نشده است. بدون پارامتر گروه، رفتار فهرست قبلی حفظ می‌شود و LEFT JOIN سبب حذف رکورد عملیاتی فاقد گروه نمی‌گردد.
4. فرم معرفی ابتدا گروه و سپس نوع وابسته را از Oracle انتخاب می‌کند و هر دو از داده واقعی می‌آیند. هنگام تغییر گروه نوع و ویژگی‌های انتخاب‌شده پاک می‌شوند. گروهی که نوع فعال ندارد، به‌درستی انتخاب نوع را غیرفعال نشان می‌دهد.
5. عنوان صفحه استعلام، نمایش پیام عدم یافتن به فارسی و نمایش گروه در فهرست و شناسنامه اصلاح شده است.

## مرز داده و حکمرانی

- جدول `COLLATERAL_GROUP`: ردیف‌های ۲۸گانه **ثبت شده‌اند**.
- جدول `COLLATERAL_TYPE`: وضعیت شمارش واقعی آن هنوز با گزارش Oracle تأیید نشده است. `COLLATERAL_TYPE` شامل ضریب ترهین و استفاده، بیمه‌پذیری، ضامن و سایر انتخاب‌های مصوب کسب‌وکار است. **نباید** به‌صورت خودکار از کد گروه ایجاد شود؛ ۱ به ۱ دانستن این دو جدول نادرست است.
- جدول `COLLATERAL`: وجود گروه/نوع هرگز به معنای وجود وثیقه عملیاتی نیست؛ انتخاب گروه و نوع بدون رکورد واقعی منجر به استعلام شماره انتظامی نمی‌شود.
- Oracle DDL/DML در این بسته: **هیچ**. قفل‌های عملیات مالی و IAM بدون تغییر. Local UAT فقط loopback با داده غیرمحرمانه است. در Production مجوز JWT و شعبه معتبر همچنان برقرار است.

## آزمایش پذیرش کوتاه

1. پس از نصب یک‌مرحله‌ای، در «اطلاعات پایه وثایق / گروه‌های وثیقه» باید ۲۸ رکورد واردشده دیده شوند.
2. در «فهرست وثایق»، انتخاب «گروه وثیقه» باید از Oracle باشد؛ اگر نوع فعالی وجود ندارد، پیام صریح فارسی ظاهر شود و داده مصنوعی تولید نشود.
3. در «معرفی وثیقه» گروه را انتخاب کنید؛ انواع فیلترشده فقط متعلق به همان گروه باشند. تغییر گروه نوع انتخاب‌شده را پاک کند.
4. در صورتی که فهرست وثایق رکوردی دارد، شماره انتظامی همان رکورد را در استعلام مستقیم وارد کنید. 404 برای شماره ناموجود به فارسی نمایش داده شود.
5. خروجی `tools/clt/r6i/CLT_R6I_GROUP_TYPE_COLLATERAL_READONLY.sql` در SQL Developer (F5) برای تعیین کمبود نوع/رکورد قابل استفاده است؛ نه برای تولید Seed یا اجرای Write.

## شواهد و گیت‌ها

- ثبات قرارداد R6D چهار GET: حفظ شده؛ گیت جدید: GET گروه‌ها و نوع‌ها با محتوای واقعی Oracle (از Build مستقل).
- آزمون‌های منفی کد گروه، عدم تزریق SQL، رعایت branch scope و عدم استفاده از عملیات مالی افزوده شدند.
- موفقیت Build، Health 200 و GET 200، جایگزین UAT تحلیلگر نیستند.

**وضعیت:** SOURCE_COMPLETE; RUNTIME_ORACLE_NOT_YET_VERIFIED; ANALYST_UAT_PENDING.
