# Hotfix: افتتاح گروهی بر پایه CIF/PDL واقعی

**مبنای تغییر:** `core-banking-prototype-v0-2026-10-11-1920.zip`

## مسئله

در فرم افتتاح گروهی، `PARTY_ID=100001` و `PRODUCT_VERSION_ID=3102` بدون مراجعه به داده واقعی CIF/PDL مقداردهی می‌شدند. دکمه «بارگذاری نمونه» نیز همین شناسه‌ها و `999999` را درج می‌کرد. بنابراین پاسخ معتبر Runtime Validator می‌توانست «نسخه محصول در PDL یافت نشد؛ Party در CIF.PARTY یافت نشد: 100001» باشد.

## اصلاحات

1. انتخاب محصول قرض‌الحسنه پس‌انداز از نسخه‌های فعال/معتبر PDL، از API موجود Product Builder؛ شناسه Product Version ثابت حذف شد.
2. جستجوی مشتری CIF، انتخاب Party و بررسی وجود Party با API موجود CIF پیش از افزودن هر ردیف؛ شناسه ثابت/نمونه حذف شد.
3. عدم تولید خودکار ردیف نمونه جعلی؛ تنها افزودن آگاهانه ردیف با داده‌های واقعی.
4. نمایش خطای واضح در صورت خالی‌بودن PDL یا ناموفق‌بودن اتصال به CIF و PDL.
5. دکمه Batch جدید برای اصلاح مقادیر بدون دستکاری Batch از پیش ثبت‌شده. Batch قدیمی در DB باقی می‌ماند.
6. حفظ Product Version تأییدشده Batch در Opening Wizard و جلوگیری از انتخاب نسخه جایگزین در handoff.
7. به‌روزرسانی آزمون سازگاری فاز ۶ مطابق دامنه Operational v5 (فقط QARD_SAVINGS) و افزودن آزمون اختصاصی.

## اعمال روی پروژه ویندوز

از نسخه جاری پروژه یک کپی پشتیبان بگیرید. محتوای فایل ZIP اصلاحی را از ریشه ZIP **روی ریشه پروژه** `D:\Projects\core-banking-prototype-v0` استخراج کنید و فایل‌های تکراری را جایگزین کنید.

سپس از CMD:

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\verify-dps2-batch-cif-pdl-runtime.mjs
node tools\verify-dps2-deposit-opening-phase6.mjs
node tools\verify-dps2-opening-v5-phase10e10f.mjs
build-production.cmd
```

پس از ساخت موفق، برنامه اجراشده را با خروجی جدید مجدداً راه‌اندازی و کش مرورگر را تازه کنید. این Patch شامل فایل‌های **Source** است و JAR و Angular Bundle جدید پیش‌ساخته ارائه نمی‌کند. هیچ Migration یا تغییر ساختار/داده DB لازم نیست.

## آزمون عملکردی در محیط Oracle

1. در فرم افتتاح گروهی، نسخه محصول از فهرست PDL بارگذاری شود؛ اگر نسخه مجازی وجود نداشت، فرم ایجاد ردیف را مسدود می‌کند.
2. با عبارت جستجو، یک Party واقعی CIF را انتخاب کنید یا شناسه معتبر آن را وارد کنید.
3. ردیف را اضافه، Batch را Validate و نتیجه را بررسی کنید.
4. ردیف معتبر را با «تکمیل Opening فردی» باز کنید؛ Version و Party باید همان مقادیر Batch باشد.
5. برای اصلاح Batch از پیش Validate شده، «Batch جدید» را بزنید؛ Patch اصلاح/حذف Batch ذخیره‌شده را انجام نمی‌دهد.

## حدود اعتبار QA

آزمون‌های static مرتبط و Syntax Parse فایل‌های TypeScript موفق بوده‌اند. اجرای Angular build و End-to-End متصل به Oracle در محیط تهیه Patch انجام نشده است؛ باید با دستور `build-production.cmd` در محیط پروژه تأیید شود.
