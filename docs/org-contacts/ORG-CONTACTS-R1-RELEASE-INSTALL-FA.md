# نسخه تجمیع اصلاحات ORG و فرم «راه‌های تماس واحدهای سازمانی» — ۲۰۲۶/۱۰/۲۴

## محدوده تحویل

این بسته سورس کامل پروژه بر پایه آخرین نسخه ORG Menu + R2-A است؛ شامل تغییرات R1 انتقال مکان، R2-A نمای فقط‌خواندنی، پنهان‌سازی سه فرم قدیمی مکان/نشانی از منو، تغییر عنوان به «مکان و نشانی واحدهای سازمانی» و فرم اختصاصی تماس واحدها با API و Oracle opt-in.

**برچسب انتشار سورس:** `0.11.0 / ORG-CONTACTS-R1`; نسخه باینری جدید از این محیط تولید نشده است.

## وضعیت واقعی Oracle

- طبق خروجی کارفرما، R1 مکان/نشانی با ۱٬۳۴۰ رکورد، ۰ اختلاف و COMMIT پس از آن موفق بوده؛ هیچ داده Oracle در تولید این بسته تغییر نکرده است.
- `ORG.CONTACT_ROLES`: ۱۲ نقش فعال؛ دو جدول انتساب تماس ORG در آخرین گزارش داده **۰ رکورد** دارند.
- `CIF.CONTACT_POINT` منبع تماس‌های شعب اعلام نشده است؛ Master مستقل ORG ایجاد می‌شود.
- SQL نصب `database/oracle/org/contacts-r1/01-ORG-CONTACT-MASTER-OPT-IN.sql` در حالت پیش‌فرض `DEFINE APPLY_CHANGES = NO` است. هیچ Oracle DDL/DML خودکار هنگام اجرای نرم‌افزار رخ نمی‌دهد.

## گام‌های استقرار در محیط آزمون

1. پشتیبان از کل پوشه برنامه و Backup قابل بازیابی Oracle تهیه کنید.
2. سورس بسته را در پوشه جدید استخراج کنید و `call tools\VERIFY-ORG-CONTACTS-RELEASE.cmd` را اجرا کنید.
3. `01-ORG-CONTACT-MASTER-OPT-IN.sql` را با F5 در SQL Developer اجرا کنید و فقط خروجی Preview را ببینید؛ `APPLY_CHANGES=NO` باید باقی بماند.
4. پس از بررسی ساختار موجود توسط DBA و تأیید محیط آزمون، همان SQL را با `DEFINE APPLY_CHANGES = YES` در نسخه جداگانه اجرا کنید. **DDL در Oracle COMMIT ضمنی دارد؛ اجرای این مرحله تراکنشی/قابل ROLLBACK نیست.** در صورت توقف جزئی، ابتدا خروجی و اشیای ایجادشده را بررسی کنید.
5. پس از موفقیت مرحله ۴، با `02-ORG-CONTACT-MASTER-VERIFY-READONLY.sql` وجود Master، Sequence، دو FK، ستون `ROW_VERSION` و صفر بودن داده عملیاتی را کنترل کنید.
6. سپس در ویندوز `call build-production.cmd` اجرا کنید. Build، وابستگی‌های Angular و Maven و Oracle در این محیط آنلاین آزمون نشده است. تنها پس از Build موفق و Restart سرویس، UI جدید فعال می‌شود.
7. در مرورگر این آدرس را باز کنید: `http://localhost:8091/#/organization/unit-contacts` (وجود `#` الزامی است).

## سناریوهای پذیرش عملیاتی

- انتخاب شعبه با نام/کد از فهرست و ثبت تلفن عمومی در نقش GENERAL؛ بازخوانی پس از Refresh.
- درج ایمیل/نمابر، ارقام فارسی شماره تلفن، وضعیت اصلی و تاریخ شمسی.
- جلوگیری از ثبت دو تماس اصلی در یک واحد، نقش، نوع و دوره هم‌پوشان.
- جلوگیری از شماره/نشانی تکراری در همین نقش، نوع و بازه اعتبار.
- خاتمه اعتبار و ثبت تماس جدید بدون حذف سابقه قبلی؛ کنترل نسخه هنگام ویرایش هم‌زمان.
- نمایش نقش‌های ۱۲گانه، خطاهای فارسی و جست‌وجوی واحد.
- بررسی تأثیر صفر بر داده‌های ۱٬۳۴۰ مکان/نشانی و عدم ایجاد Party در CIF.

## قیود و محدودیت‌ها

- نسخه سورس تحویل شده است، نه JAR جدید قابل اجرا؛ برای Build، Node/npm/Maven در محیط شما لازم است.
- **ثبت تماس تا پیش از نصب SQL و Restart نسخه Build‌شده فعال نمی‌شود.** سرویس `/readiness` این وضعیت را اعلام می‌کند.
- تاریخ شروع و پایان اعتبار تماس شامل روزهای مرزی هستند.
- ویرایش مقدار تماس تنها برای تصحیح خطا کاربرد دارد؛ در تغییر واقعی شماره/ایمیل، سابقه پیشین را خاتمه دهید و رکورد جدید ایجاد کنید.
- فرم مکان و نشانی تجمیعی فعلاً فقط‌خواندنی است. حذف فیزیکی جداول قدیمی، همگام‌سازی خودکار دوطرفه مکان و نشانی، ثبت تاریخچه جابه‌جایی، مدیریت تماس نقاط خدمت و اجرای Oracle UAT در این بسته انجام نشده‌اند.
- سه فرم قدیمی مکان/نشانی **فقط از منو حذف شده‌اند**؛ جداول و مسیرهای مستقیم قدیمی برای سازگاری حفظ شده‌اند. نباید فرم قدیمی برای تغییر روزمره نشانی استفاده شود.

## آزمون‌های سورس

- آزمون‌های ایستای اختصاصی ORG و route/menu اجرا شده‌اند.
- آزمون نحوی TypeScript و Java به شکل جداگانه؛ Maven/Angular full build و UAT واقعی Oracle انجام نشده‌اند.
- اسکریپت نصب اصلاح شده تا نخستین اجرا در Oracle به دلیل ارجاع ایستای PL/SQL به Master ساخته‌نشده با `ORA-00942` متوقف نشود.
