## ۲. «خانواده محصول» از کجا تکمیل می‌شود؟

منبع داده تعریف محصول تسهیلات **`PDL.LOAN_TYPE`** است. گروه تجاری یک نوع عقد در ستون `LOAN_GROUP` ذخیره می‌شود و شرط نمایش، `RECORD_STATUS_CODE='ACTIVE'` است. فقط گروهی به کاربر نشان داده می‌شود که **حداقل یک نوع عقد فعال** به آن تعلق داشته باشد. نگاشت ثابت معنای گروه‌ها در `LoanTypeClassification` تعریف شده، ولی موجود بودن هر گزینه مستقیماً از Oracle خوانده می‌شود.

| `LOAN_GROUP` | `PRODUCT_FAMILY_CODE` | عنوان خانواده | مثال نوع عقد |
|---|---|---|---|
| ۱ | `QARD_HASAN_LOAN` | تسهیلات قرض‌الحسنه | قرض‌الحسنه |
| ۲ | `EXCHANGE_LOAN` | تسهیلات مبادله‌ای | فروش اقساطی، جعاله (فقط اگر عقد فعال ثبت شده باشد) |
| ۳ | `PARTICIPATORY_LOAN` | تسهیلات مشارکتی | مشارکت مدنی، مضاربه (فقط اگر عقد فعال ثبت شده باشد) |
| ۴ | `COMMITMENT_LOAN` | تعهدات اعتباری | ضمانت‌نامه، اعتبار اسنادی (اگر داده‌های مرجع مربوطه موجود باشد) |

بنابراین اگر در اطلاعات پایه تنها «قرض‌الحسنه» و «مشارکت مدنی» فعال باشند و گروه‌های آن‌ها ۱ و ۳ ثبت شده باشد، دو گزینه در ComboBox ظاهر می‌شوند: «تسهیلات قرض‌الحسنه» و «تسهیلات مشارکتی». **مشارکت مدنی خودش خانواده نیست**؛ نوع عقد آن در پروفایل تخصصی تسهیلات تعیین می‌شود.

Endpoint جدید: `GET /api/v1/product-builder/loan-product-families`. در صورت فقدان داده یا خطای ارتباط، هیچ خانواده فرضی ساخته نمی‌شود. فرم مسیر `اطلاعات پایه انواع عقود` و دکمه «بازخوانی» را نشان می‌دهد.

## ۳. «ماهیت ترازنامه‌ای» در فرم محصول

| دامنه `PRODUCT_CLASS_CODE` | ماهیت `BALANCE_NATURE_CODE` | مفهوم فارسی |
|---|---|---|
| `LOAN` | `ASSET` | دارایی بانک (مطالبات و تسهیلات) |
| `DEPOSIT` | `LIABILITY` | بدهی بانک در قبال سپرده‌گذار |

این مقدار **سیستمی و فقط‌خواندنی** است. پس از بارگذاری محصول هم از دامنه استنتاج می‌شود؛ کاربر نباید بتواند مستقلاً آن را تغییر دهد. مقدار انگلیسی فقط در payload داده ذخیره می‌شود، نه در کنترل نمایشی.

## ۴. سیاست قواعد محصول (Lite) چیست و چگونه کار می‌کند؟

این بخش **سیاست حاکمیت بر وجود و فقدان پیکربندی قواعد** را تعریف می‌کند؛ ابزار محاسبه تسهیلات، موتور قواعد اعتباری، گردش کار تصویب تسهیلات یا موتور اجرایی عملیات نیست.

| عنوان فرم | معنی کسب‌وکاری | مثال آزمایشی |
|---|---|---|
| کد سیاست `POLICY_CODE` | کلید پایدار و معنادار یک «سیاست انتشار و آمادگی قواعد»؛ با شناسه سیستمی رکورد متفاوت است | `LOAN_PRODUCT_POLICY` |
| عنوان سیاست | عنوان خوانا برای تیم مدیریت محصول و حاکمیت | سیاست انتشار محصولات تسهیلاتی |
| نسخه سیاست `POLICY_VERSION_NO` | شماره بازنگری همان کد سیاست؛ مستقل از نسخه محصول | نسخه ۱: قواعد اولیه، نسخه ۲: بازنگری مصوب |
| شناسه ایجادکننده (Maker) | ثبت‌کننده پیش‌نویس یا تغییر کنترل‌های آن | `uat_maker01` |
| شناسه تصویب‌کننده (Checker) | بازبین مستقلی که سیاست را تصویب می‌کند؛ باید با ایجادکننده تفاوت داشته باشد | `uat_checker02` |
| مرجع تصویب `APPROVAL_REFERENCE` | شناسه مدرک تصمیم رسمی/صورت‌جلسه | `UAT-MINUTES-1405-001` |
| وضعیت سیاست `STATE_CODE` | ابتدا `DRAFT`، سپس `APPROVED`؛ نسخه مصوب قابل ویرایش مستقیم نیست | مصوب |
| الزام حضور `PRESENCE_MODE_CODE` | آیا وجود قاعده برای محصول الزامی است، مشروط به ماژول فعال است یا اختیاری؟ | `REQUIRED` برای اهلیت |
| واکنش در نبود `ABSENCE_ACTION_CODE` | مسدودکردن انتشار، مسدودکردن عملیات، هشدار یا بدون الزام | `BLOCK_PUBLISH` |
| الزام اجرای عملیاتی `RUNTIME_REQUIRED` | اعلام نیاز به یکپارچگی Runtime؛ **به معنی پیاده‌بودن کنترل اجرایی نیست** | فعال برای کنترل‌های نیازمند اجرای تراکنشی |

**روند UAT بدون داده ساختگی:**

۱. وارد «محصول‌ساز یکپارچه ← یک محصول ← انتخاب نسخه محصول ← بازبینی نهایی (مرحله ۶)» شوید.

۲. اگر «نسخه سیاست» خالی بود، وضعیت «هنوز سیاستی ثبت نشده است» و فرم «ساخت نخستین سیاست» باید دیده شود. اگر خطای HTTP/Oracle باشد پیام «دریافت نسخه‌های سیاست از PDL موفق نبود» دیده می‌شود. این دو نباید مخلوط شوند.

۳. Maker آزمایشی را `uat_maker01` بگذارید، کد و عنوان سیاست را وارد کنید، بازه اعتبار مناسب نسخه محصول را تعیین کنید و «ایجاد پیش‌نویس با ۲۳ کنترل پایه» بزنید. اکنون نسخه سیاست باید در ComboBox ظاهر شود. **برای هر ایجاد، ردیف جدید Oracle و ۲۳ ردیف کنترل ساخته می‌شود.**

۴. در جدول کنترل‌ها، مثلاً قاعده اهلیت را `REQUIRED` و واکنش نبود را `BLOCK_PUBLISH` قرار دهید. تغییرات پیش‌نویس را ذخیره کنید.

۵. مرجع صورت‌جلسه و Checker متفاوت مانند `uat_checker02` را درج و تصویب کنید. Backend مانع یکسان بودن Maker و Checker می‌شود؛ نسخه مصوب قفل است.

۶. اگر نسخه محصول `DRAFT` باشد و تاریخ اعتبار سیاست کل بازه اعتبار محصول را پوشش دهد، می‌توان «اتصال به نسخه محصول» را انتخاب کرد. هر تغییر بعدی سیاست نیازمند ساخت نسخه تازه و تصویب مجدد است.

**هشدار Production:** در نمونه فعلی شناسه‌های اقدام‌کننده از Header آزمایشی `X-User-Name` دریافت می‌شوند، نه هویت احرازشده سمت سرور. این وضعیت برای بهره‌برداری بانکی قابل قبول نیست؛ قبل از Production باید به IAM/SSO و RBAC مبتنی بر هویت واقعی متصل شود. همچنین انتخاب `RUNTIME_REQUIRED` موتور کنترل عملیاتی را نصب یا فعال نمی‌کند.

## ۵. عملیات مجاز هر کانال

ستون نخست اکنون `OPERATION_CODE` را به **عنوان فارسی مرحله یا نوع عملیات** ترجمه می‌کند و به گزینه‌های مجاز فرم ویرایش وابسته نیست. برای تسهیلات مجموعه مجاز از جمله ثبت درخواست، پرداخت، بازپرداخت، خدمت‌رسانی، خاتمه و استعلام است؛ برای سپرده افتتاح، برداشت، انتقال وجه، چک و غیره.

برای جلوگیری از مخدوش‌شدن سابقه، کد تاریخی ناشناخته با عبارت **«کد تاریخی تعریف‌نشده: XXX»** نمایش داده می‌شود، نه عنوان ساختگی. داده‌های تاریخی حذف یا تبدیل نمی‌شوند. خروجی SQL تشخیصی کدهای واقعی را نشان می‌دهد تا درباره نگاشت کدهای باقی‌مانده تصمیم کسب‌وکاری گرفته شود.

- Verifier جدید R27: **۳۷ کنترل موفق، صفر خطا** در محیط دارای TypeScript (در محیط بدون dependency، ۴ کنترل نحوی به Build واقعی Angular واگذار می‌شوند).
- آزمون اجرایی Java برای نگاشت گروه‌های تسهیلات: **۹ موفق، صفر خطا**.
- آزمون اجرایی Java قواعد تسهیلات R26: **۱۲ موفق، صفر خطا**.
- Verifier R20 سیاست Lite: **۵۳ موفق، صفر خطا**.
- Verifier R24 خانواده تسهیلات: **۶۵ موفق، صفر خطا** و آزمون سازگاری HF1: **۱۳ موفق**.
- Verifier R25 تسهیلات: **۶۳ موفق، صفر خطا**.
- Verifier UX قبلی: **۲۰ موفق، صفر خطا**.
- Verifier افتتاح گروهی CIF/PDL: **۱۱ موفق**.
- وضعیت **Build کامل Angular/Maven، آزمون Oracle متصل و آزمون مرورگر**: در محیط تدوین تأیید نشده است؛ باید در محیط پروژه اجرا شود. بنابراین برای هیچ‌یک ادعای UAT عملیاتی نداریم.
- هیچ SQL نوشتنی، DDL، تغییر Schema یا Seed فرضی به پروژه اضافه نشده است.

نسخه کامل R27 جایگزین نسخه قبلی شود؛ Patch R27 فقط روی **R26 تجمیعی** نصب شود (روی نسخه قدیمی 1920 یا UX قبلی نصب مستقیم نشود).

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\verify-pdl-r27-product-policy-channel.mjs
node tools\verify-pdl-r27-loan-family-java.mjs
node tools\verify-rgl-lite-r20.mjs
node tools\verify-pb-r24-loan-integrity.mjs
node tools\verify-pb-r25-loan-final-ux.mjs
node tools\verify-dps2-batch-cif-pdl-runtime.mjs
```
