# R30-HF7-A3 / HF2 — اصلاح یکپارچه چهار ایراد محصول‌ساز

مبنا: نسخه تجمیعی `R30-HF7A3-HF1` مورخ ۱۴ اکتبر ۲۰۲۶. این Patch فقط روی همین مبنا بررسی شده است.

## ۱. نام ماژول سپرده

عنوان‌های قابل مشاهده «چهار سپرده» در منو، Breadcrumb، صفحه اصلی، عملیات افتتاح، فهرست اطلاعات پایه و نام نمایشی Schema به «سپرده» تبدیل شد. مسیر فنی `/four-deposits` و نام پکیج‌ها/ماژول‌ها تغییر نکرده‌اند تا API، تاریخچه و لینک‌های قبلی نشکنند. مستندات تاریخی دست‌نخورده‌اند.

## ۲. مالکیت انفرادی و خطای Oracle CHECK

منشأ محتمل: برخی قیود `SEARCH_CONDITION_VC`، نام ستون را با گیومه دوتایی یا با عبارت `= ... OR = ...` دارند؛ Parser قبلی تنها یک شکل `IN` را تشخیص می‌داد. در این حالت مقدار قراردادی `SINGLE` ممکن بود به‌جای کد واقعی مجاز بانک اطلاعاتی، مانند `INDIVIDUAL`، ارائه شود.

- Parser متادیتای Oracle برای نام ستون داخل گیومه، مقدارهای IN، گزینه‌های OR/equality و اشتراک CHECKهای مستقل بهبود یافت.
- وقتی CHECK قابل استخراج باشد، تنها **کد واقعیِ مجاز در PDL** ذخیره می‌شود. نگاشت `SINGLE ↔ INDIVIDUAL` صرفاً برای عنوان کسب‌وکاری است؛ هیچ DML یا تغییر کد مرجع DPS انجام نمی‌شود.
- در مالکیت انفرادی، تعداد حداقل/حداکثر مالک و امضاکننده = ۱، تقسیم سود بین مالکان نامربوط و غیرفعال است. در مالکیت مشترک، حداقل دو مالک کنترل می‌شود.
- شناسه نامعتبر CHECK واقعی فقط با اجرای گزارش SQL تشخیصی روی همان Oracle قابل تأیید نهایی است؛ محیط توسعه به بانک اطلاعاتی شما متصل نیست.

## ۳. کانال و عملیات: پوشش بازه زمانی

«نخستین روز بدون پوشش: 2031-10-15» به‌معنی روز آغاز گسست *بر اساس قرارداد فعلی نسخه و مجموعه قواعد ACTIVE* است و نباید با حذف کنترل پنهان شود. فرم `PRODUCT_CHANNEL_RULE` اکنون بازه اعتبار `PRODUCT_VERSION` را از Backend می‌خواند و هنگام ثبت رکورد جدید، اگر تاریخ‌ها خالی باشند، آن‌ها را از نسخه پر می‌کند. برای رکورد قبلی تاریخ تغییر خودکار ندارد. دکمه «اعمال بازه نسخه به قاعده» اختیاری است و مقادیر را قبل از Save به‌صورت قابل بررسی تغییر می‌دهد. وضعیت `ACTIVE` و وجود پوشش کامل تا آخرین روز لازم است؛ همپوشانی قواعد هم تابع کنترل‌های موجود می‌ماند.

## ۴. تسویه خاتمه سپرده و وابستگی مقصد

| روش تسویه | مقصد تسویه | قاعده Backend |
|---|---|---|
| `DEDUCT` کسر از مانده | نامربوط؛ خالی و غیرفعال | وجود مقصد رد می‌شود |
| `WAIVE` بخشودگی | نامربوط؛ خالی و غیرفعال | وجود مقصد رد می‌شود |
| `PAY` پرداخت به مشتری | ضروری؛ مقصد پرداخت مجاز | خالی بودن و `BANK_ACCOUNT` رد می‌شود |
| `TRANSFER` انتقال به حساب | ضروری؛ مقصد انتقال مجاز | خالی بودن و `CASH` رد می‌شود |

بررسی‌های مشابه شامل تغییر روش پس از انتخاب مقصد، مقدار تاریخچه نامعتبر، روش ناشناخته، وضعیت NULL مقصد و وابستگی مالکیت انفرادی نیز انجام شده‌اند. **ماتریس حقوقی/مالی نوع جزء** (`PRINCIPAL`, `PROFIT`, `COMMISSION`, `TAX`, `PENALTY`) با روش تسویه هنوز نیازمند تصمیم تأییدشده بانک است؛ این Patch برای آن‌ها قواعد مالی حدسی وضع نمی‌کند.

## آزمون‌ها و محدودیت‌ها

- آزمون Java واقعی Validator و قرارداد معنایی به‌شکل ایزوله با Spring annotation stub، بدون Oracle.
- آزمون Parser واقعی Java با استخراجِ عین منطق از Repository و کامپایل ایزوله، بدون اتصال JDBC.
- آزمون TypeScript و سناریوهای تعاملی فرم از طریق transpile/fixture.
- تست‌های JUnit جدید برای `PdlCheckConstraintOptionsHF7A3Test` و `ProductBuilderSettlementAndJointHF7A3Test` افزوده شده‌اند و باید در Maven/Surefire روی سیستم کاربر اجرا شوند.
- آزمون‌های قدیمی HF7-A1/HF7-A2/HF7-A3-HF1/R14/R19 و Release Layout باید پس از نصب نیز PASS باشند.
- Build واقعی Angular/Java کامل، اتصال واقعی Oracle و E2E عملیاتی در این محیط اجرا نشده‌اند؛ نتیجه Windows/Oracle UAT باید گزارش شود.
- `canOpen`، ممیزی پوشش زمانی و محافظ‌های تسهیلات/سپرده تغییر نکرده‌اند. هیچ Oracle migration یا عملیات نوشتنی انجام نشده است.
