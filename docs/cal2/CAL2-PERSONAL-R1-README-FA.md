# CAL2 PERSONAL R1 — یادداشت و یادآوری شخصی در تقویم

این افزونه از `CAL2.CANONICAL_DAY` برای تاریخ استفاده می‌کند و هیچ رکوردی از `CAL2.EVENT`, `CAL2.EVENT_OCCURRENCE`, تعطیلات، یا تقویم کاری تغییر نمی‌دهد.

## مدل
- جدول جدید `CAL2.USER_CALENDAR_ITEMS` فقط به `CAL2.CANONICAL_DAY` کلید خارجی دارد.
- `NOTE`: یادداشت روز؛ هیچ پیام خودکاری تولید نمی‌کند.
- `REMINDER`: پیش‌آگاهی ۰ تا ۳۰ روز قبل؛ انتخاب حالت `DAILY` یا `ONCE`.
- در هر دو حالت یک اعلان جداگانه در روز موعد (پس از ساعت تعیین‌شده) وجود دارد.
- `DAILY`: از اولین روز پیش‌آگاهی، هر روز بعد از ساعت تنظیم‌شده تا روز موعد؛ اگر همان روز خوانده شده باشد، تکرار نمی‌شود.
- `ONCE`: از شروع بازه پیش‌آگاهی یک پیام خوانده‌نشده نشان داده می‌شود؛ پس از کلیک «خواندم»، تا روز موعد دیگر اعلان پیش‌آگاهی نمی‌آید.
- بعد از موعد، تا زمانی که وضعیت `DONE` نشده باشد، یک پیام «موعدگذشته» قابل مشاهده می‌ماند؛ «خواندم» آن را تا روز بعد پنهان می‌کند.
- با «انجام شد»، پیام‌ها متوقف می‌شوند؛ «بازگشایی» وضعیت را دوباره فعال می‌کند.
- منطق زمان‌بندی روی Backend و بر اساس `Asia/Tehran` است؛ پیام روی تقویم ماهانه با `DAY_ID` نمایش داده می‌شود و تقویم شمسی/میلادی/قمری فقط نحوه نمایش تاریخ است.

## محدودیت مشخص پروتوتایپ
این نسخه **احراز هویت کاربران ندارد**. همه نشست‌های این پروتوتایپ با شناسه ثابت سمت سرور `prototype-admin` کار می‌کنند؛ ذخیره داده در Oracle پایدار است، ولی این طرح را نباید به‌عنوان حریم خصوصی چندکاربره یا انتشار عملیاتی تلقی کرد. شناسه کاربر از هدر یا ورودی قابل جعل مرورگر گرفته نمی‌شود. اتصال به هویت واقعی و مجوز هر کاربر باید قبل از استقرار چندکاربره انجام شود.

اعلان زنگ در نوار بالای برنامه هنگام باز بودن برنامه هر ۶۰ ثانیه بررسی می‌شود؛ اعلان مرورگر/موبایل، ایمیل و پیامک **اجرا نشده‌اند**. کاربر پس از ورود مجدد پیام موعد گذشته یا پیام پیش‌آگاهیِ قابل‌اقدام را خواهد دید؛ اجرای سرویس زمان‌بندی‌شده برای ارسال Push در حالت بسته بودن مرورگر جزو این نسخه نیست. این قابلیت از `@Scheduled` یا ساخت صف اعلان برای هزاران کاربر استفاده نمی‌کند.

## API
- `GET /api/v1/calendar2/personal/items?from=2026-10-01&to=2026-10-31`
- `POST /api/v1/calendar2/personal/items`
- `PUT /api/v1/calendar2/personal/items/{uuid}`
- `PATCH /api/v1/calendar2/personal/items/{uuid}/completion`
- `DELETE /api/v1/calendar2/personal/items/{uuid}`
- `GET /api/v1/calendar2/personal/alerts`
- `POST /api/v1/calendar2/personal/alerts/{uuid}/acknowledge`

مثال ایجاد یادآوری، پس از یافتن `DAY_ID` در تقویم:

```json
{
  "dayId": 123456,
  "itemType": "REMINDER",
  "title": "پیگیری گزارش شعب",
  "description": "ارسال گزارش برای بررسی",
  "reminderTime": "09:00",
  "advanceDays": 3,
  "repeatPolicy": "DAILY"
}
```

در سرور می‌توان این دو تنظیم را در `application.yml` یا متغیر محیطی متناظر تنظیم کرد:

- `core-banking.calendar2.personal.demo-actor` (پیش‌فرض `prototype-admin`)
- `core-banking.calendar2.personal.zone` (پیش‌فرض `Asia/Tehran`)

## ترتیب نصب و کنترل
۱. Backup از Schema `CAL2` و سورس پروژه تهیه کنید. در SQL Developer فایل `database/oracle/cal2/migrations/CAL2-PERSONAL-ITEMS-R1-OPT-IN.sql` را با F5 و پیش‌فرض `APPLY_CHANGES = NO` اجرا کنید؛ **هیچ نوشتنی انجام نمی‌شود**.

۲. اگر پیام `PENDING` داشت، بعد از تأیید، مقدار را `YES` کنید و با F5 اجرا کنید. باید `CAL2_PERSONAL_R1_APPLY_COMPLETE` دریافت شود. DDL در Oracle به‌طور خودکار COMMIT می‌شود. برای کاربر Oracle غیر از SYSTEM/CAL2 مجوز `SELECT,INSERT,UPDATE,DELETE` روی جدول جدید لازم است.

۳. Patch کد را از پوشه مستقل خودش با `tools\apply-cal2-personal-r1.cmd "D:\Projects\core-banking-prototype-v0" CHECK` و سپس `APPLY` اجرا کنید. پوشه `files` و `manifest.json` مربوط به Patch را داخل ریشه پروژه کپی نکنید.

۴. در ریشه پروژه `node tools\verify-cal2-personal-r1.mjs` و `build-production.cmd` را اجرا کنید. سپس http://localhost:8091/#/calendar2/month-view را باز کنید.

۵. روی روز فردا در تقویم کلیک کنید، یادآوری ۱ روز قبل با ساعت گذشته از امروز (مثلاً ۰۸:۰۰) ثبت کنید و زنگ بالای برنامه را بررسی کنید. «خواندم» و «انجام شد» را آزمایش کنید.

## تغییرناپذیری قراردادهای فعلی
فایل‌های رسمی CAL2 و جداول `ORG` تغییر نکرده‌اند. این افزونه هیچ عملیات `DROP` یا `RENAME` ندارد و هیچ وابستگی یا ثبت رخداد رسمی ایجاد نمی‌کند.
