# Oracle constraint and indexing review — R2-A2 (NOT EXECUTABLE DDL)

This document defines candidate integrity rules. No statement here is approved for production. Validate against the actual Oracle version, schema grants and column definitions before writing the opt-in DDL.

## Cross-aggregate reference safety (critical)

Single-column foreign keys alone would let an Alert point to an Occurrence of Entry A and a Reminder Rule of Entry B. Both targets could exist and the naive foreign keys would pass.

Physical candidate must carry `USER_CALENDAR_ENTRY_ID` on Alert and constrain BOTH relationships:

```sql
-- Illustrative only: parent composite unique constraints required.
-- On occurrences: UNIQUE (USER_CALENDAR_OCCURRENCE_ID, USER_CALENDAR_ENTRY_ID)
-- On reminder rules: UNIQUE (REMINDER_RULE_ID, USER_CALENDAR_ENTRY_ID)
-- On recurrence rules: UNIQUE (RECURRENCE_RULE_ID, USER_CALENDAR_ENTRY_ID)
-- On alerts:
-- FK (USER_CALENDAR_OCCURRENCE_ID, USER_CALENDAR_ENTRY_ID)
--     REFERENCES USER_CALENDAR_OCCURRENCES (USER_CALENDAR_OCCURRENCE_ID, USER_CALENDAR_ENTRY_ID)
-- FK (REMINDER_RULE_ID, USER_CALENDAR_ENTRY_ID)
--     REFERENCES USER_CALENDAR_REMINDER_RULES (REMINDER_RULE_ID, USER_CALENDAR_ENTRY_ID)
-- On occurrences:
-- FK (RECURRENCE_RULE_ID, USER_CALENDAR_ENTRY_ID)
--     REFERENCES USER_CALENDAR_RECURRENCE_RULES (RECURRENCE_RULE_ID, USER_CALENDAR_ENTRY_ID)
```

An Entry-only owner scope (issuer + subject) must still be applied by all service queries. These constraints prevent accidental cross-entry linkage but do not replace authorization.

## Identity, type and time

- Entry `NUMBER(12)` for legacy preservation, generated by `SEQ_CAL2_USER_CALENDAR_ENTRIES`, new sequence starts above reserved/migrated IDs. Other sequences shortened to <=30-character Oracle names.
- All local minute-of-day columns check 0..1439. Recurrence/Reminder variant and slot validation is partly cross-table and belongs to domain service (not a single CHECK).
- Immutable planned timestamp uses `TIMESTAMP(6) WITH TIME ZONE`; write values normalized to UTC. Retain IANA `TIME_ZONE_ID` on Entry for recurrence of local wall clock, because UTC offset alone is not enough for future dates.
- For Oracle TSTZ indexes, check function-based index semantics and query plans. Avoid assuming ordinary TIMESTAMP and TSTZ have identical index/performance behavior.
- Normalized weekday mask is seven `0`/`1` characters in ISO Monday..Sunday order. Validation of frequency-shape is mandatory.
- UNTIL_DAY_ID and COUNT_LIMIT are mutually exclusive in this candidate: use zero or one; indefinite rules are generated only within a bounded rolling horizon.

## Uniqueness and cardinality

1. `OCCURRENCES`: UNIQUE `(USER_CALENDAR_ENTRY_ID, ORIGINAL_SLOT_KEY)`.
2. `ALERTS`: UNIQUE `(USER_CALENDAR_OCCURRENCE_ID, REMINDER_RULE_ID, RULE_VERSION_NO, SCHEDULED_SLOT_KEY)`.
3. `REQUEST_KEYS`: UNIQUE `(OWNER_ISSUER, OWNER_SUBJECT_ID, OPERATION_CODE, IDEMPOTENCY_KEY)`; verify index length with target NLS charset/block size.
4. `RECURRENCE_RULES`: UNIQUE for **one ACTIVE rule per Entry** via an approved function-based unique index or virtual-column pattern, while superseded revisions remain.
5. `ALERT_DELIVERIES`: UNIQUE `(USER_CALENDAR_ALERT_ID, CHANNEL_CODE, ATTEMPT_NO)`.
6. Avoid `ON DELETE CASCADE` for records with operational history and audit significance.

## Pattern-dependent reminder shape

- `AT_DUE`: offset 0, other window fields NULL; timed Entry trigger is exact due instant, all-day requires explicit alert minute.
- `SINGLE_OFFSET`: positive offset and valid unit (`MINUTE`, `HOUR`, `CALENDAR_DAY`), window fields NULL.
- `DAILY_WINDOW`: positive start >= end >= 1 and positive interval; offset fields NULL, explicit local alert minute.
- `ACK_STOP_POLICY`: `NONE` by default; `STOP_FUTURE_ADVANCES` is explicitly permitted only for DAILY_WINDOW and is intended to preserve reviewed legacy ONCE behavior.
- Scheduled Alert next-eligible instant may change for snooze; planned UTC time and scheduled slot key do not.

## Index design subject to load-test

| Table | Candidate access pattern | Suggested key |
|---|---|---|
| Entries | Owner-scoped month view | `(OWNER_ISSUER, OWNER_SUBJECT_ID, ENTRY_STATUS, START_DAY_ID)` |
| Occurrences | One entry in date range | `(USER_CALENDAR_ENTRY_ID, DAY_ID)` |
| Alerts | Due scheduler scan | `(ALERT_STATUS, NEXT_ELIGIBLE_AT_UTC)` |
| Alerts | User Inbox | `(USER_CALENDAR_ENTRY_ID, ALERT_STATUS, AVAILABLE_AT_UTC)` joined to Entry with owner scope |
| Request keys | Command dedup | Unique Owner/Operation/Key |

No B-tree partitioning or index creation is approved by this candidate alone; choose after realistic row counts, execution plans, retention and concurrency tests.
