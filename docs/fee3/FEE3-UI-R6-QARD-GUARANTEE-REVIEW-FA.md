# FEE3-UI-R6 — رفع مغایرت آزمون قرض‌الحسنه و سبد وثایق ضمانت‌نامه

**مبنای مرجع:** فایل HTML/JavaScript تست‌شده `FCE_v13_8_84_Program_REDOWNLOAD.html`، منطق F1322 قرض‌الحسنه، F1377 مبنای تک‌وثیقه‌ای، F1378 سبد وثایق، F1380 مالکیت درصد پوشش تعرفه. **بستر نصب:** پروتوتایپ 0.11.0، نسخه ساعت 16:27، با FEE3-UI-R5.

## دامنه و مرز ایمنی
- صرفاً UI آفلاین Angular/Angular Material و منطق محاسبه عددی محدود برای بازبینی. هیچ Backend، Oracle، DDL، DML، نرخ رسمی، سند حسابداری یا تغییر در FEE/FEE2/PDL/ORG انجام نمی‌شود.
- جداول Seed و نرخ‌های تاریخی صرفاً مرجع مطالعاتی‌اند و تأیید بانک محسوب نمی‌شوند.
- اجرای واقعی Angular Production Build و آزمون تعاملی مرورگر در محیط سازنده انجام نشده است؛ آزمون‌های TS با Stub برای Angular و رگرسیون Node عددی جایگزین Build کامل نیستند.

## اصلاح قرض‌الحسنه
- گام ۶ قابل مشاهده «آزمون و جمع‌بندی» پس از ذخیره پیش‌نویس، فرم کنترل‌شده قرارداد دارد: شناسه قرارداد، تاریخ پرداخت واقعی، شروع دوره، پایان غیرشامل دوره، شناسه دوره مطالبه، تاریخ رویداد مطالبه و شناسه سند رویداد.
- `yearFraction` از شمارش روزهای ISO متناظر با تاریخ شمسی انتخاب‌شده، مخرج واقعی 365/366 سال جلالی و تفکیک بازه عبوری از مرز سال مشتق می‌شود؛ توسط کاربر ویرایش نمی‌شود.
- انتخاب مبنای ACT/365 یا ACT/360 هم محاسبه مستقل دارد. در انتخاب CONTRACT_MONTHS برای فرمول سال‌شمار از تبدیل حدسی ماه به روز خودداری و خطای راهنما صادر می‌شود.
- نرخ و مبلغ تعهد معتبر هنوز از ورودی آزمایشی مشخص دریافت می‌شود، نه مقدار مخفی یا نرخ ساختگی.
- آزمون واقعی با Seed `FCE-000235`, فرمول `TPL_E624746F262F6E` و بازه 1403/01/01 تا 1404/01/01 = 366 روز / یک سال کامل، با مبلغ 10,000,000 و نرخ 18%، خروجی قبل مالیات 1,800,000 ریال داشت؛ صرفاً نمونه ریاضی.

## اصلاح ضمانت‌نامه
- گام محاسبه: انتخاب «نوع وثیقه / ساختار وثیقه»، سبد یا تک‌وثیقه‌ای، و «مبنای اعمال نرخ» مطابق قرارداد تعرفه.
- سبد: برای هر نوع وثیقه یک قاعده نرخ با `CONFIG`, `REQUEST` یا `EXEMPT` تعریف می‌شود؛ درصد پوشش **متعلق به تعرفه** است. درصد سهم هر وثیقه **متعلق به درخواست آزمون** است؛ درخواست حق تغییر نرخ/پوشش تعرفه را ندارد.
- سه سناریوی آموزشی با قواعد انتخابی و آشکار (و نه خودکار): CASH_100 معاف/پوشش 100؛ سفته 2.25%/پوشش120؛ اموال منقول1%/پوشش100؛ سهم‌ها 15/50/35. مبلغ تضمین 100,000,000 ریال: مبنای سهم 1,475,000 و مبنای پوشش 1,700,000 ریال پیش از مالیات.
- دو وثیقه 40% CASH + 60% سفته: مبنای سهم 1,350,000 و مبنای پوشش 1,620,000 ریال.
- مجموع سهم باید دقیقاً 100% باشد؛ تکرار نوع وثیقه در قوانین نرخ، نبود قاعده، نرخ نامعتبر، درصد پوشش نامعتبر، و CASH_100 زیر 100% رد می‌شوند.
- نرخ قراردادی فقط در منبع REQUEST دریافت می‌شود، آن هم صریح؛ هیچ نرخ بانکی یا معافیت خودکار استفاده نشده است.
- کف، سقف، گردکردن و مالیات دقیقاً یک‌بار بر جمع کارمزد تمامی ردیف‌ها اعمال می‌شود. هر ردیف در جدول ردگیری قابل مشاهده است.
- در مدل تک‌وثیقه‌ای، مبنای مبلغ تعهد و ارزش پوشش از هم تفکیک شده‌اند؛ و وجود وثیقه نقدی 100 درصد کنترل می‌شود.

## دستور نصب ویندوز
1. روی پروژه دارای R5، بسته `FEE3-UI-R6-INCREMENTAL-FOR-R5.zip` را در ریشه پروژه استخراج و فقط فایل‌های هم‌نام FEE3 را جایگزین کنید. یا اگر نسخه ساعت 16:27 بدون R5 دارید، بسته تجمیعی R6 را استفاده کنید.
2. دستورهای زیر را اجرا کنید:

```bat
cd /d D:\Projects\core-banking-prototype-v0
python tools\fee3-ui\verify-reference-r5.py
python tools\fee3-ui\verify-reference-r6.py
python tools\fee3-ui\verify-parity-r4.py
node tools\fee3-ui\verify-r6-math.cjs
bin\stop.cmd
build-production.cmd
```

3. پس از Build موفق، `bin\start.cmd` و سپس مسیر `#/fee3` (طبق Route واقعی برنامه) را بررسی کنید.

## آزمون‌های پذیرش مورد انتظار
- قرض‌الحسنه: با وارد کردن تاریخ‌ها کسر سال خودکار نمایش داده شود؛ فرم امکان نوشتن مستقیم `yearFraction` نداشته باشد؛ هنگام بازه وارونه و سند رویداد خالی، محاسبه رد شود؛ بعد از ذخیره پیش‌نویس و تکمیل ضوابط مالی، آزمون محلی اجرا شود.
- ضمانت‌نامه: گام ۳ نوع وثیقه دیده شود، مبنای سبد از تعرفه خوانده شود، با دو مبنای متفاوت خروجی متفاوت باشد، درصد پوشش در گام آزمون قابل‌ویرایش نباشد، جمع سهم زیر/بالای ۱۰۰٪ پذیرفته نشود.
- نرخ‌ها/سهم‌ها بعد از تغییر قواعد، مدرک آزمون قبلی را باطل کنند؛ ارسال محلی برای بررسی صرفاً پس از ذخیره، آزمون و تکمیل تعاریف فعال شود.
- این UI، امکان تأیید یا انتشار رسمی تعرفه ایجاد نمی‌کند.

## آزمون‌های اجراشده در محیط تولید Patch
- 30 سناریوی مثبت و منفی عددی با **همان ماژول TypeScript نسخه R6**؛ نتیجه `FEE3_R6_FINANCIAL_POLICY_TESTS_PASS=30`.
- 59 بررسی استاتیک اختصاصی: `FEE3_R6_SPECIALIZED_STATIC_PASS=59`.
- 142 بررسی UI مرجع R5: `FEE3_R5_REFERENCE_UI_STATIC_PASS=142`.
- 98 بررسی R4: `FEE3_R4_PARITY_STATIC_OK=98`.
- type-check سخت‌گیرانه TypeScript روی همه فایل‌های FEE3 با Stub ماژول‌های Angular: بدون خطا.
- 93 حلقه `@for` همگی دارای `track`؛ تعادل تگ‌های HTML کنترل شد.
- تست `ng build` و بازبینی دیداری با مرورگر هنوز اجرا نشده‌اند. مسیر Backend/Oracle همچنان عمداً قطع است.
