# FEE3 F6-A2 — رفع وابستگی آزمون مهندسی به ذخیره پیش‌نویس

**تاریخ:** 2026-10-29  
**وضعیت:** توسعه و آزمون آفلاین انجام‌شده؛ Build و نصب روی Windows کاربر باید تأیید شود.

## مسئله کاربر

در F6-A1 گام «۶ آزمون و جمع‌بندی»، دکمه «محاسبه مبلغ نمونه» تنها وقتی فعال می‌شد که `testDraftSaved()==true` باشد. در وضعیت Oracle فقط‌خواندنی و قلم محلی `DEMO-000002` ذخیره پیش‌نویس مسدود می‌شد. با وجود تعریف دو خانه `ALL/ALL=30000` و `PERSON/MOBILE=10000`، کارشناس نمی‌توانست آزمون عددی MATRIX را انجام دهد.

## اصلاح F6-A2

1. مسیر جدید **محاسبه مهندسی بدون ذخیره** فقط برای قلم نمایشیِ محلی با کد `DEMO-*` یا `F3-UAT-*`، نسخه `DRAFT` غیرفعال، بدون `oracleItemId` و `oracleVersionId` و روش `MATRIX/BRACKET/PROGRESSIVE` فراهم شد.
2. محاسبه به‌صورت **پیش از مالیات** و کاملاً مستقل از `testDraftSaved`, `saveDraft`, Oracle, HTTP, workflow و Posting اجرا می‌شود. برای حالت `UNREVIEWED` هیچ مالیات یا مبلغ قابل وصول استنباط نمی‌شود.
3. نتیجه فقط در state موقتی همان کامپوننت نگهداری می‌شود و در `version.tests[]` و `Fee3Store` ثبت نمی‌شود؛ به‌همین دلیل `lastTestPassed`, `canSendReview`, `demoReady` و شرایط انتشار/ارجاع تغییری نکرده‌اند.
4. تغییر قواعد، مشتری، کانال یا ورودی، خروجی مهندسی قبلی را بی‌اعتبار می‌کند.
5. برای MATRIX خالی، دکمه «بارگذاری نمونه ماتریس» دو خانه `ALL/ALL=30000` و `PERSON/MOBILE=10000` را *فقط در حافظه فرم* ایجاد می‌کند و جدول موجود را بازنویسی نمی‌کند.
6. شرط حفظ داده معتبر: ماتریس مبهم، خانه ناموجود، دامنه ارز متفاوت، روش ناشناخته، نسخه Oracle، قواعد مالی چندمؤلفه‌ای، بازه نامعتبر یا ورودی عددی خارج از کران، همگی fail-closed هستند.

## سناریوی کاربر

1. «کارمزد ۳» → «تعریف قلم جدید» → گام ۳ «محاسبه» → «ماتریسی».
2. اگر جدول ماتریس خالی است، در گام ۶ دکمه «بارگذاری نمونه ماتریس» را بزنید. اگر دو سطر را از قبل تعریف کرده‌اید، آن‌ها را تغییر ندهید.
3. در گام ۶ «نوع مشتری = شخص حقیقی» و «کانال = موبایل‌بانک» انتخاب کنید؛ دکمه «محاسبه مهندسی بدون ذخیره» را بزنید: **۱۰٬۰۰۰ ریال** (فقط پیش از مالیات).
4. مشتری را «حقوقی» بگذارید و کانال را «موبایل‌بانک» نگه دارید؛ دوباره دکمه را بزنید: **۳۰٬۰۰۰ ریال**.
5. به‌عمد هیچ‌یک از ده‌ها فیلد اجباری سایر مراحل برای این آزمایش لازم نیست. آزمون ثبت‌شونده، ارسال برای بررسی و فعال‌سازی دمو همچنان بدون تکمیل پیش‌نیازها غیرفعال‌اند.

## کنترل‌های باقی‌مانده

- آزمون جدید به معنی تأیید تعرفه یا نرخ بانکی نیست.
- ارتباط واقعی CAL2 با روزشمار ACT/ACT و Formula Allowlist مستقل F2 همچنان مراحل جداگانه F6-B هستند.
- Oracle FEE3 فقط‌خواندنی است و تمام نسخه‌های تعرفه واقعی موجود همچنان DRAFT/INACTIVE/UNREVIEWED هستند.
- F5-P2C HTTP ایزوله هنوز اثبات نشده و در فهرست کنترل‌های فنی باز باقی می‌ماند.
