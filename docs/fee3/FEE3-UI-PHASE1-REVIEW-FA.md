# FEE3 — کارمزد ۳ | تحویل مرحله اول: منو و فرم‌های Angular Material

**مبنای پروژه:** Core Banking Prototype 0.11.0، نسخه سورس ارسالی 2026-10-25-1200  
**مبنای کسب‌وکار و مدل:** FCE V13.8.84، HTML مرجع، مدل فیزیکی FEE3 دارای ۱۱ جدول، اسکریپت‌های Full Draft Catalog و Reference/Formula Seed ارسالی کارفرما  
**وضعیت:** `UI_REVIEW_CANDIDATE`؛ اتصال Backend/Oracle، اجرای موتور و گردش‌کار انتشار **جزء این بسته نیستند**.

## ۱. حدود اجرا

- فقط **یک منوی اصلی «کارمزد ۳ (FEE3)»** در گروه «محصولات و قیمت‌گذاری» افزوده شده است. مسیر ` /fee3 ` و بارگذاری Lazy است.
- زیرصفحه‌ها به‌صورت بخش‌های داخلی همان میزکار پیاده‌سازی شده‌اند: فهرست اقلام، فرم، نسخه‌ها، داده‌ها و فرمول‌های مرجع، رویدادهای آزمایشی نشست.
- فرم دارای هشت گام است: شناسنامه، دامنه، محاسبه، ضوابط مالی، اعتبار و گردش‌کار، بازبینی، آزمون، کنترل نهایی و انتشار.
- از Angular Material، جهت راست‌به‌چپ، توکن‌های پوسته پروژه، حالت روشن/تاریک، چینش واکنش‌گرا و کنترل تاریخ شمسی مشترک پروژه استفاده شده است.
- نه خانواده روش محاسبه در UI پوشش داده شده‌اند: `FIXED`, `PERCENT`, `MIXED`, `PROGRESSIVE`, `BRACKET`, `MATRIX`, `USAGE`, `DAILY`, `FORMULA`. فیلدهای ویژه هر روش شرطی نمایش داده می‌شوند.
- اعتبارسنجی اولیه شامل رابطه بخش/عملیات/نوع مبلغ، ضرورت فیلدها، تعارض هویت قلم، روش و نرخ و سقف/کف، بازه اعتبار و هشدار هم‌پوشانی نسخه است. این کنترل‌ها **جایگزین اعتبارسنجی تراکنشی سمت سرور نیستند**.

### تعهد ایمنی مرحله اول

1. هیچ `HTTP`، JDBC، REST، SQL یا فراخوانی بانک اطلاعاتی از FEE3 اجرا نمی‌شود.
2. **ذخیره آزمایشی** فقط در حافظه سرویس Angular (`signal`) است؛ با Refresh یا بستن تب از دست می‌رود و قابلیت اتکا/ماندگاری ندارد.
3. اجرای فرمول، محاسبه خروجی قطعی، تأیید، فعال‌سازی، انتشار، حذف، ثبت حسابداری، برداشت وجه و وصول **غیرفعال‌اند**.
4. اقلام Seed **مطالعاتی/پیش‌نویس** هستند؛ نرخ‌ها و مستندهای سال ۱۴۰۴ به‌طور خودکار در سال ۱۴۰۵ معتبر نیستند.
5. جدول‌ها، کدها و منوهای FEE و FEE2 و Product Builder و ساختار Backend/Oracle پروژه **بدون تغییر** مانده‌اند.

## ۲. منبع اطلاعات UI

اطلاعات نمایش اولیه از متن SQL‌های FCE V13.8.84 پیوست تولید شده‌اند. این به معنی تأیید وضعیت جاری داده‌های اجراشده روی Oracle نیست.

| رکورد/جدول مفهومی | تعداد در fixture آفلاین |
|---|---:|
| `FCE_CALC_ITEM` | ۲۹۷ قلم |
| `FCE_TARIFF_VERSION` | ۳۰۰ نسخه همگی `DRAFT` |
| `FCE_CALC_RULE` | ۳۱۳ قاعده |
| `FCE_VERSION_SCOPE` | ۳۰۰ دامنه |
| `FCE_TEST_CASE` | ۶ سناریوی مطالعاتی |
| `FCE_REF_OPERATION` | ۱۱۳ عملیات |
| `FCE_REF_CODE` | ۱۶۷ مقدار مرجع |
| `FCE_REF_FORMULA` | ۳۳ فرمول |
| `FCE_REF_SOURCE` | ۵ مدرک |

`tools/fee3-ui/extract-seed-fixture.py` جهت بازتولید Fixture از دو فایل اصلی SQL موجود است. این اسکریپت صرفاً فایل TypeScript تولید می‌کند؛ به Oracle متصل نیست.

## ۳. ردیابی مدل داده به بخش UI

| جدول Oracle | بخش UI و وضعیت مرحله اول |
|---|---|
| `FCE_CALC_ITEM` | گام ۱؛ هویت قلم، عملیات، نوع مبلغ و گونه خدمت؛ ویرایش آزمایشی |
| `FCE_VERSION_SCOPE` | گام ۲؛ حوزه‌های مشتری، کانال، محصول، قرارداد، ارز و اولویت |
| `FCE_CALC_RULE` | گام ۳؛ ساخت قواعد و روش‌های محاسبه |
| `FCE_TARIFF_VERSION` | گام‌های ۴ و ۵؛ سیاست مالی، وضعیت مالیات، گردکردن، اعتبار، منشأ و مستند |
| `FCE_TEST_CASE` | گام ۷؛ تعریف ورودی و نتیجه مورد انتظار؛ اجرای آزمون مسدود |
| `FCE_CHANGE_REQUEST` | گام ۸؛ جایگاه گردش‌کار نمایش داده می‌شود؛ ثبت/تأیید غیرفعال |
| `FCE_AUDIT_EVENT` | بخش رویداد؛ رویدادهای محلی با Audit واقعی اشتباه گرفته نمی‌شوند |
| `FCE_REF_OPERATION` | انتخاب عملیات منوط به بخش و تعیین نوع مبلغ مجاز |
| `FCE_REF_CODE` | واژگان مرجع فرم‌ها و فیلترها |
| `FCE_REF_FORMULA` | کتابخانه فرمول با عبارت خواندنی و ورودی‌های ضروری |
| `FCE_REF_SOURCE` | انتخاب مدرک مصوبه و نمایش وضعیت اعتبارسنجی آن |

FEE3 **مالک محاسبه مبلغ** است، نه مالک حساب، عملیات حسابداری، تسویه، تسهیلات یا قرارداد. در فاز API، سازگاری با مرزهای دامین و BIAN و مالکیت سرویس‌ها مجدداً کنترل شود.

## ۴. مسیرهای کد و روش نصب

- `frontend/src/app/features/fee3/` — پیاده‌سازی مستقل Angular شامل مدل، State، Validation، Fixture، Component، Template و Styles.
- `frontend/src/app/app.routes.ts` — یک مسیر Lazy، همراه کنترل خروج از فرم تغییرنیافته.
- `frontend/src/app/layout/app-shell.component.html` — تنها یک لینک اصلی FEE3.
- `frontend/src/app/layout/sidebar-r22/sidebar-r22-group.component.ts` — بازماندن گروه منو برای مسیر FEE3.
- `tools/fee3-ui/` — تولیدکننده Fixture و کنترل استاتیک.

برای نصب Patch، فایل Zip پچ را **از ریشه مخزن** استخراج کنید تا سه فایل Navigation و مسیر جدید جایگزین/افزوده شوند؛ هیچ Migration لازم نیست.

در محیط توسعه دارای `node` و npm و وابستگی‌های Angular نصب‌شده:

```bash
cd frontend
npm ci
npm run build
npm start
```

سپس `http://localhost:4200/fee3` را باز کنید (با در نظرگرفتن تنظیم Proxy و پورت واقعی پروژه). اجرای Backend برای مشاهده این UI ضروری نیست؛ ولی برای راه‌اندازی سایر بخش‌های نرم‌افزار ممکن است لازم باشد.

کنترل استاتیک مستقل از نصب npm:

```bash
python tools/fee3-ui/verify-ui-package.py
```

### ۶. محدودیت آزمون انجام‌شده در محیط تولید بسته

- **انجام‌شده:** بررسی استاتیک ۳۴ کنترل (`verify-ui-package.py`)، بررسی بسته‌شدن HTML، داده‌ها و شمارش Seed؛ نوع‌سنجی TypeScript برای دامنه، سرویس و Component با shimهای تستی موقت؛ آزمون واحد منطق اعتبارسنجی روی Seed (۲۹۷ قلم بدون ایراد هویت و عدم پذیرش مقدار مفقود).
- **انجام‌نشده:** Build واقعی Angular CLI، اجرای مرورگر و بررسی تصویری/دسترس‌پذیری با تیم کسب‌وکار. دلیل: بسته‌های npm موردنیاز Angular در محیط تولید موجود و قابل دریافت نبودند. بنابراین این خروجی **نامزد بازبینی UI** است، نه Build تأییدشده یا نسخه تولیدی.
- **انجام‌نشده و خارج از دامنه این مرحله:** هرگونه بررسی یا اعمال نوشتن در Oracle و محاسبه مالی واقعی.

## ۷. گام مستقل پس از اخذ تأیید UI

پس از تأیید چیدمان و رفتارها، Backend مستقل `FEE3` در Java/Spring و APIهای فهرست/جزئیات/نسخه، کنترل تعارض زمانی و دامنه، CRUD پیش‌نویس، تغییر وضعیت Maker–Checker، اجرای آزمون، محاسبه کنترل‌شده و Audit طراحی و متصل شود. شناسه‌های عددی مبتنی بر Sequence/Oracle و کنترل `RECORD_VERSION` (Optimistic Concurrency) و transaction boundary باید در لایه سرویس مدیریت شوند. **هیچ اقدام فعال‌سازی یا وصول/ثبت حسابداری نباید صرفاً با تغییر Frontend امکان‌پذیر شود.**
