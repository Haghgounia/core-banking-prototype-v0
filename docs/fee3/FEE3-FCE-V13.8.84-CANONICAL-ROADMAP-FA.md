# نقشه راه اختصاصی FEE3 — انطباق با FCE V13.8.84

**وضعیت:** مبنای اجرایی توسعه و کنترل پوشش؛ فاقد اختیار انتشار تعرفه یا تغییر Oracle  
**تاریخ:** ۲۰۲۶-۱۰-۲۸  
**نسخه Core Banking:** `0.11.0`  
**مرجع قابلیت کسب‌وکار:** `FCE_v13_8_84_Program_REDOWNLOAD(3).html` (Prototype مستقل آفلاین؛ نه مصوبه بانکی)  
**مدل Oracle:** `FEE3` و شواهد زنده Read-only ۲۸ اکتبر؛ Oracle مستقل از فایل HTML است.

## ۱. اصول و مرز دامنه

FCE موتور تعیین **مبلغ، علت، نسخه تعرفه و ریزمحاسبه قابل ردگیری** است. ایجاد مطالبه، دریافت وجه، Posting، سند حسابداری و برگشت تراکنش توسط دامنه‌های مالی صاحب اختیار انجام می‌شوند؛ FEE3 باید قراردادهای معتبر برای آن‌ها ارائه کند، نه اینکه ناخواسته مسئولیتشان را بپذیرد. وضعیت `DRAFT` در نمونه HTML یا Oracle به معنای مجوز محاسبه قابل وصول نیست. سیاست مالیات `UNREVIEWED` باید در خروجی و Gate باقی بماند.

`SYSTEM` صرفاً برای توسعه ایزوله `127.0.0.1:8092` در محیط تأییدشده استفاده شده است؛ در بهره‌برداری باید جایگزین، محدود و بازبینی شود. HTTP `POST /preview` در این طرح **خواندن/محاسبه غیرمالی** است؛ `POST` به‌تنهایی نشانه نوشتن در DB نیست.

## ۳. محدوده مرجع V13.8.84

- **۹ روش:** `FIXED`, `PERCENT`, `MIXED`, `DAILY`, `USAGE`, `FORMULA`, `MATRIX`, `BRACKET`, `PROGRESSIVE`.
- **داده اولیه واقعی در کد HTML:** ۳۰۰ رکورد، ۲۹۷ کد یکتا، ۱۱۱ سه‌تایی دامنه/عملیات/نوع مبلغ مجاز؛ تمام ۳۰۰ رکورد در وضعیت `DRAFT`.

- **دلیل اختلاف با شمار خام:** داده JSON اولیه `FCE-000051` را ثابت ذخیره کرده، ولی کد HTML قبل از `f1382SeedState()` آن را به `FORMULA` تبدیل می‌کند. تکیه بر شمار خام ۱۷۹/۵۲ صحیح نیست.
- **تطبیق اولیه کلیدها:** برابری ۲۹۷/۳۰۰ در شمار Oracle و فایل HTML اثبات انطباق سطر/نسخه یا اعتبار نرخ نیست؛ بررسی `code+version+operation+method+effective date+rule fingerprint` لازم است.
- **داده قانونی:** نرخ‌های تاریخی ۱۴۰۴، نرخ‌های گزارش‌شده ۱۴۰۵، قراردادهای فاقد نرخ و مدارک اثبات‌نشده را از تصمیم بانکی جدا نگه دارید. PDF/HTML جای تأیید سیاست بانک را نمی‌گیرد.

جدول ردیابی کل ۳۰۰ رکورد در `FEE3-F5-V13884-300-VERSION-TRACEABILITY.csv` است؛ وضعیت‌های آن **برآورد شواهد ایستای سورس** هستند و تأیید ردیفی Oracle نیستند.

## ۶. سناریوهای بانکی با تقدم بالاتر

- `FCE-000051`, `FCE-000296`, `FCE-000297`: دسته‌چک کاغذی/الکترونیکی؛ هزینه چاپ، حق تمبر و هزینه عملیاتی باید مستند باشند.
- `FCE-000157`: نسخه‌های قدیم/جدید کارت‌به‌کارت، انتخاب نسخه براساس اعتبار تاریخی؛ دو نرخ هم‌زمان به‌عنوان نرخ جاری فرض نشوند.
- `FCE-000160`, `FCE-000164`: پایا و پرداخت حقوق دسته‌ای، مقدار مصرف و نرخ/قرارداد معتبر.
- `FCE-000291` تا `FCE-000294`: ارزش‌گذاری ملک/تجهیزات/زمین/وثیقه مازاد؛ سقف محاسبه خودکار و هزینه کارشناس، بدون عددسازی.
- `FCE-000295`, `FCE-000298`, `FCE-000299`: خدمات درخواست، تحویل و کنترل برگه دسته‌چک با مجوز نرخ مستقل.
- `GUARANTEE`, `LOAN`, `LC`, `DIGITAL`, `GENERAL`: نتایج محاسبه به مالک خدمات تحویل داده می‌شود؛ قرارداد و وقوع مالی نباید در FCE جعل شود.

## ۷. Gateهای قطعی و ممنوعیت‌ها

- `ENGINEERING_PASS ≠ ORACLE_RULE_PARITY ≠ BUSINESS_UAT ≠ PRODUCTION_GO`.
- رد درخواست نامعتبر و حفظ تعداد رکوردها، **آزمون محاسبه مثبت و عددی نیست**.
- در F5 عملیات Oracle باید `SELECT` باشد. برای Preview می‌توان `POST` را به API فقط‌خواندنی ایزوله فرستاد، مشروط به کنترل محدوده مسیر و عدم آثار مالی.
- `TAX_MODE_CODE=UNREVIEWED`، `DRAFT` و `IS_ACTIVE=0` مانع فعال‌سازی مالی هستند، حتی اگر محاسبه آزمایشی عدد برگرداند.
- هیچ `CREATE/ALTER/DROP/INSERT/UPDATE/DELETE/COMMIT`، انتشار، مطالبه یا Posting در این مستند/بسته اجرا نمی‌شود.
