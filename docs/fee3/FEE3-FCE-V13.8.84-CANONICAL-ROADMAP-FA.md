**وضعیت:** مبنای اجرایی توسعه و کنترل پوشش؛ فاقد اختیار انتشار تعرفه یا تغییر Oracle

**مرجع قابلیت کسب‌وکار:** `FCE_v13_8_84_Program_REDOWNLOAD(4).html` (Prototype مستقل آفلاین؛ نه مصوبه بانکی)

## ۱. اصول و مرز دامنه

FCE موتور تعیین **مبلغ، علت، نسخه تعرفه و ریزمحاسبه قابل ردگیری** است. ایجاد مطالبه، دریافت وجه، Posting، سند حسابداری و برگشت تراکنش توسط دامنه‌های مالی صاحب اختیار انجام می‌شوند؛ FEE3 باید قراردادهای معتبر برای آن‌ها ارائه کند، نه اینکه ناخواسته مسئولیتشان را بپذیرد. وضعیت `DRAFT` در نمونه HTML یا Oracle به معنای مجوز محاسبه قابل وصول نیست. سیاست مالیات `UNREVIEWED` باید در خروجی و Gate باقی بماند.

`SYSTEM` صرفاً برای توسعه ایزوله `127.0.0.1:8092` در محیط تأییدشده استفاده شده است؛ در بهره‌برداری باید جایگزین، محدود و بازبینی شود. HTTP `POST /preview` در این طرح **خواندن/محاسبه غیرمالی** است؛ `POST` به‌تنهایی نشانه نوشتن در DB نیست.

## ۷. Gateهای قطعی و ممنوعیت‌ها

- `ENGINEERING_PASS ≠ ORACLE_RULE_PARITY ≠ BUSINESS_UAT ≠ PRODUCTION_GO`.
- رد درخواست نامعتبر و حفظ تعداد رکوردها، **آزمون محاسبه مثبت و عددی نیست**.
- در F5 عملیات Oracle باید `SELECT` باشد. برای Preview می‌توان `POST` را به API فقط‌خواندنی ایزوله فرستاد، مشروط به کنترل محدوده مسیر و عدم آثار مالی.
- `TAX_MODE_CODE=UNREVIEWED`، `DRAFT` و `IS_ACTIVE=0` مانع فعال‌سازی مالی هستند، حتی اگر محاسبه آزمایشی عدد برگرداند.
- هیچ `CREATE/ALTER/DROP/INSERT/UPDATE/DELETE/COMMIT`، انتشار، مطالبه یا Posting در این مستند/بسته اجرا نمی‌شود.

- گزارش تحویل شامل Git Diff قابل بررسی، فهرست تغییرات، وضعیت Build، محدودیت‌ها و قدم دقیق بعدی باشد.
