# گزارش QA — FEE3-BE-R4B2

**دامنه:** محاسبه محدود تک‌وثیقه و سبد وثایق در صدور ضمانت‌نامه، بدون Oracle Write.

## شواهد محلی

- اجرای production pure contract با `javac` و Java: **۶۶/۶۶** آزمون عددی و مرزی (چهار Golden، مالیات، کف/سقف، ۳ روش day count، دقت نرخ/مبلغ/پوشش، رد سهم زیر/بالای ۱۰۰، منبع نرخ نامعتبر، تکرار وثیقه، تاریخ ناقص، سرقت نقش نرخ، توقف نسخه منتشرشده، SHA-256).
- کامپایل با Stubهای امضای Spring/JUnit: **۴ کلاس تولیدی و یک تست JUnit**؛ این آزمون **معادل Build واقعی Maven نیست**.
- Harness HTTP محلی با سرور تقلیدی و محاسبه مستقل Python `Decimal`: **۱۱/۱۱**؛ کنترل no-proxy، no-redirect، allowlist، failure-on-write، failure-on-workflow و عدم فراخوانی APIهای نوشتنی.
- آزمون Harness در حالت HTTP شبیه‌سازی‌شده: **۲۶/۲۶**؛ این مورد **Oracle نیست**.
- منبع R4-A و R4-B1 بدون دستکاری، افزوده‌شدن چهار Java و ابزارها با نصب اتمیک و SHA-256.

## مفروضات و محدودیت‌ها

1. عملیات فقط `GUARANTEE_ISSUE` است. سایر رویدادهای چرخه عمر ضمانت‌نامه، حتی اگر در فهرست عملیات Oracle فعال باشند، برای این API `BLOCKED` هستند.
2. نرخ‌ها، ضرایب پوشش و معافیت از اصل کارمزد **صرفاً از پیش‌نویس تعرفه ورودی** یا نرخ قراردادی صریح می‌آیند؛ هیچ رقم تاریخی Seed به‌عنوان نرخ جاری استفاده نمی‌شود.
3. برای `PERCENT` دوره‌ای اعمال نمی‌شود؛ نرخ سالانه نیازمند `DAILY` و day count صریح است. مبنای `ACT_ACT` در این فاز تقویم **میلادی** است، مستقل از روز کاری Oracle با منطقه `Asia/Tehran`.
4. تخفیف‌ها، نرخ ارزی، ترکیب چندقاعده‌ای، فرمول دلخواه، توافق‌ها، حقوق ثالث، رفع وثیقه و حسابداری مسدودند.
5. در ارجاع نسخه Oracle، شناسه و نسخه رکورد باید کامل باشد و `Fee3R4ReferenceRepository` تمام اطلاعات موثر را از Oracle تطبیق دهد. صرف وجود شناسه یک «اجازه محاسبه منتشرشده» نیست.
6. تک‌وثیقه در این فاز نیازمند نرخ صریح `RULE` یا `REQUEST` است؛ در سبد نرخ پایه سراسری **نباید** استفاده شود. ساختار عمومی R3 تغییر نکرده است.

## کنترل‌های پذیرش نهایی (باید روی Windows واقعی تکمیل شوند)

- [ ] `build-production.cmd` — موفق، شامل JUnit جدید.
- [ ] `run-runtime-readonly.cmd` — `FEE3_R4B2_RUNTIME_PASS=26 FAIL=0`.
- [ ] Oracle read-only baseline دوباره اجرا شود؛ `FCE_CHANGE_REQUEST=0` و وضعیت DRAFT/ACTIVE و شمارش‌های ۱۱ جدول بدون تغییر.
- [ ] Workflow و Posting همچنان غیرفعال باشند؛ هیچ مجوز وصول ایجاد نشده است.

**وضعیت:** فقط نامزد پذیرش Oracle Runtime؛ در انتظار اجرای کاربر.
