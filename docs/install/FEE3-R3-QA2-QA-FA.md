# گزارش QA: FEE3-R3-QA2

## منشأ تغییر

آزمون R3-QA1 در سیستم هدف با `RemoteDisconnected` قبل از اولین گام Readiness پایتون متوقف شد؛ در همان سیستم فراخوانی `curl.exe` موفق بود. با توجه به استفاده QA1 از `urllib.request.urlopen`، یکی از احتمالات عبور ارتباط محلی از Proxy تنظیم‌شده در محیط است. این علت هنوز روی محیط ویندوز مقصد احراز نشده است.

در QA1 همچنین مقایسه اولیه/نهایی از فیلدهای `itemCount` و `versionCount` استفاده می‌کرد، درحالی‌که قرارداد واقعی `Fee3Models.Readiness` و پاسخ کاربر `calcItemCount` و `tariffVersionCount` است. در حالت سابق دو مقدار ناموجود `None` ممکن بود با هم برابر محسوب شده و یک آزمون نادرست PASS شود. QA2 این نقض را رفع کرده است.

## شواهد اجرا در محیط توسعه

۱۱ مورد آزمون مستقل QA2 با HTTP Server محلی موفق شدند:

1. دریافت مستقیم موفق باوجود Proxy خراب و `NO_PROXY` خالی؛ هیچ درخواست به Proxy ارسال نشد؛ تنها ۵ POST غیرماندگار.
2. جلوگیری از POST در صورت روشن بودن Flag نوشتن.
3. جلوگیری از POST در صورت روشن بودن Workflow.
4. رد نشانی غیرمحلی قبل از ارسال درخواست.
5. رد HTTP 302 با مقصد خارجی بدون دنبال‌کردن Redirect.
6. تشخیص `RemoteDisconnected` با مسیر دقیق `GET /readiness`.
7. نمایش امن خطای HTTP 503 و `errorCode` بدون بدنه کامل.
8. رد تغییر واقعی `calcItemCount` بین ابتدای و انتهای آزمون.
9. رد نبودن فیلدهای شمارش بدون ارسال POST.
10. تشخیص HTTP 422 در `POST /preview` بدون ادامه درخواست‌های اضافی.
11. حفظ Allowlist عملیات؛ هیچ مسیر نوشتن و گردش‌کار فراخوانی نمی‌شود.

**نتیجه:** `FEE3_R3_QA2_SELFTEST_PASS=11 FAIL=0`.

این‌ها آزمون ابزار QA هستند، نه شواهد اجرای Runtime واقعی یا اتصال مستقل به Oracle. پذیرش Runtime همچنان منوط به اجرای QA2 روی سیستم کاربر و بررسی SQL بعد از آزمون است.

## محدوده فایل‌ها

تنها ابزارهای جدید `tools/fee3-backend/qualification/r3-qa2`، دو گزارش در `docs/install` و Manifest در `release` افزوده شده‌اند. هیچ فایل موجود پروژه جایگزین نشده است.
