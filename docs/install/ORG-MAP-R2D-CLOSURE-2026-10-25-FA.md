# ORG — نقشه شعب / بسته نهایی R2-D (پذیرش UAT)

**مبنای سورس:** `core-banking-prototype-v0-2026-10-24-ORG-R2C-MAP-FILTERS-FIX.zip`، مبتنی بر سورس ارسالی کارفرما ساعت ۱۷:۵۱ روز ۲۴ اکتبر ۲۰۲۶.

## هدف و محدوده

* بستن مسئله انطباق شناسه جغرافیایی و فیلترهای نقشه در همین مرحله؛ بدون انتقال، حذف یا بازنویسی اطلاعات شعب.
* قرارداد جدید `GEO_ENTITY_TYPE_CODE` در `ORG.ORGANIZATION_UNIT_LOCATIONS`، مقادیر `CITY` / `RURAL_DISTRICT`؛ ارتباط با شناسه عددی ترکیبی است.
* ۱٬۳۴۰ استقرار فعلی (`LEGACY_BACKFILL_FLAG=1`) طبق شواهد ورود شعب از `TECH_GEO_CITY_ID` هستند. بنابراین تا زمانی که کاربر نوع جدید را صریحاً اصلاح نکرده، منطق **خواندن** برای همین رکوردهای مستند نوع CITY را اعمال می‌کند. روی ردیف‌ها حتی یک UPDATE خودکار صادر نمی‌شود.
* در ثبت جدید انتخاب استان ← شهرستان ← نوع شهر/دهستان ← نام عارضه از GEO اجباری است. سامانه نوع و شناسه را در Backend اعتبارسنجی می‌کند. از مختصات یا OpenStreetMap هرگز GEO ID جعل نمی‌شود.
* برای شهرها/دهستان‌ها تعداد واحدهای فعالِ دارای استقرار جاری در فهرست فیلتر نمایش داده می‌شود. دهستان‌های فعلی صفر خواهند بود مگر اینکه یک انتساب صریح `RURAL_DISTRICT` وجود داشته باشد.
* واحد فاقد مختصات معتبر از گرید نتایج حذف نمی‌شود، اما نشانگر آن ترسیم نمی‌شود.
* وضعیت `MERGED` یا `CLOSED` تغییر نمی‌کند. ۲۰۹ شعب فاقد استقرار جاری به‌صورت خودکار درج نمی‌شوند.
* عنوان‌ها و فرم‌های تماس، سایر جداول ORG و مدل رسمی استان/شهرستان/نشانی‌های بانک در این Patch دست‌نخورده‌اند.

## دو گام نصب (Oracle سپس Source)

**پیش‌نیاز CRUD نشانی:** ابتدا اسکریپت موجود `database/oracle/org/locations-r2b/01-ORG-UNIT-LOCATIONS-R2B-OPT-IN.sql` باید به تأیید DBA نصب شده باشد. این R2-D آن اسکریپت را جایگزین نمی‌کند. اگر هنوز نصب نشده باشد، مشاهده نقشه همچنان کار می‌کند ولی ثبت/ویرایش همچنان به‌درستی غیرفعال می‌ماند.

1. از ORG و GEO خروجی پشتیبان تهیه کنید. فایل `database/oracle/org/map-r2d/01-ORG-MAP-EXPLICIT-GEO-TYPE-OPT-IN.sql` را با F5 در SQL Developer اجرا کنید. پیش‌فرض `DEFINE APPLY_CHANGES = NO` است. انتظار طبق شواهد پیشین: ۱۳۴۰ ردیف استقرار با شناسه فنی شهر معتبر، بدون مورد نامنطبق؛ **عدد خروجی واقعی مبناست**.
2. فقط پس از تأیید پیش‌نمایش و موافقت DBA، در همان فایل `APPLY_CHANGES=YES` قرار دهید و مجدداً F5 اجرا کنید. این عملیات فقط **ستون اختیاری و CHECK** می‌سازد؛ Oracle DDL دارای COMMIT ضمنی است، هیچ DML برای ۱۳۴۰ ردیف ندارد. برای جلوگیری از اجرای تصادفی، بعد از نصب آن را به NO برگردانید.
3. فایل `database/oracle/org/map-r2d/02-ORG-MAP-GEO-TYPE-POSTVERIFY-READONLY.sql` را با F5 اجرا کنید. انتظار: `GEO_TYPE_COLUMN_PRESENT=1`، `GEO_TYPE_CHECK_ENABLED=1`، `UNMATCHED_CITY_REFERENCES=0` و پیام `ORG_MAP_R2D_POSTVERIFY_PASS`.
4. سورس/Hotfix را در مسیر پروژه جایگزین کنید. فایل‌های ZIP در ریشه پروژه فایل راهنمای سرگردان ندارند؛ تمام مستندات در `docs/install/` هستند.
5. در CMD ویندوز:

```cmd
cd /d D:\Projects\core-banking-prototype-v0
call tools\VERIFY-ORG-MAP-R2D-CLOSURE.cmd
call bin\stop.cmd
call build-production.cmd
```

فقط پس از تکمیل موفق Build:

```cmd
call bin\start.cmd
```

سپس Ctrl+F5 و آدرس `http://localhost:8091/#/organization/branch-map`.

## کنترل پذیرش (بدون نوشتن روی Oracle)

فایل `03-ORG-MAP-FINAL-ACCEPTANCE-READONLY.sql` را با F5 اجرا کنید و خروجی را با داده فعلی تطبیق دهید. پیش از ورود داده جدید، انتظار تاریخی: ۱۵۴۹ شعب شامل ۱۳۴۰ شعب فعال دارای استقرار و مختصات در ایران؛ ۲۰۹ شعب بسته/ادغام‌شده فاقد استقرار، ۴۴۳ شناسه شهر فنی دارای شعبه. تفاوت اعداد باید علت‌یابی شود و با UPDATE خودکار «اصلاح» نشود.

UAT مرورگر (بدون ثبت داده) شامل: (۱) نمای ایران، (۲) استان البرز ← شهرستان طالقان: یک شعبه با کد ۸۸۲۲۹، (۳) انتخاب شهری با عدد صفر: گرید صفر و نشانگر صفر، (۴) انتخاب دهستان با صفر: نشانگر نادرست از شهری که GEO_ID برابر دارد ظاهر نشود، (۵) تغییر دوباره استان/شهرستان: نمای نقشه خودکار به نتایج برگردد، (۶) کلیک روی یک شعبه و مشاهده نشانی صحیح؛ (۷) بررسی اینکه ۱۳۴۰ نقطه/شعبه مطابق فیلتر سراسری هستند و ۲۰۹ مورد CLOSED/MERGED اضافه نشده‌اند.

UAT نوشتنی **صرفاً روی محیط تست مجاز**: ایجاد/ویرایش یک نشانی با نوع `CITY` و یک نشانی آزمایشی با نوع `RURAL_DISTRICT`، بررسی FK منطقی در Backend، ثبت Audit و کنترل ROW_VERSION. بدون مجوز عملیاتی روی بانک واقعی اجرا نشود.

## محدودیت شفاف

* GEO.City یک **مرجع فنی** است و ممکن است شهرِ مرکز شهرستان برای آدرس رسمی خارج شهر انتخاب شده باشد؛ مختصات روی نقشه همچنان بر اساس پاسخ رسمی بانک ثبت می‌شوند. شهرِ واقعی از مختصات به‌طور خودکار تشخیص داده نمی‌شود.
* کدپستی اجباری نیست و با GEO به‌عنوان مرجع صحت‌سنجی نشانی رسمی برخورد نمی‌شود.
* اجرای کنترل‌های ایستا معادل موفقیت Build کامل، Oracle SQL اجرایی یا UAT مرورگر نیست؛ پرونده پس از دریافت نتایج مورد انتظار بسته می‌شود.

## معیار توقف و بازگشت

اگر اسکریپت نصب NO یا Verify دارای تعارض بود، `YES` نزنید. اگر Build شکست خورد، `bin/start.cmd` را اجرا نکنید. هیچ‌گاه برای رسیدن به شمار ثابت ۱۳۴۰، رکوردهای شعب را خودکار پاک یا اضافه نکنید.
