# ORG R2-C — راهنمای نصب، قابلیت‌ها و آزمون پذیرش

مبنای تغییر: سورس `core-banking-prototype-v0-2026-10-24-1751.zip`، نسخه نرم‌افزار `0.11.0`.

## تغییرات قابل استفاده

- «نشانی و موقعیت شعب و واحدها»: جست‌وجو، مشاهده، افزودن استقرار، ویرایش با شماره نسخه و نگهداری سابقه تغییر؛ توضیحات مربوط به مهاجرت اطلاعات از صفحه عملیاتی حذف شده است.
- «راه‌های ارتباطی شعب و واحدها»: انتخاب جست‌وجویی واحد، بارگذاری خودکار، دکمه بازخوانی، ثبت و ویرایش تماس، و متن خالی بودن فهرست به زبان کاربر.
- «نقشه استقرار شعب و واحدها»: نقشه تعاملی ایران (زمینه OpenStreetMap/CARTO)، نشانگرهای خوشه‌بندی‌شده، فیلترهای استان/شهرستان/شهر/دهستان، نوع واحد و نام/کد، فهرست صفحه‌بندی‌شده، لینک به دو فرم دیگر.

**تفاوت داده‌ای مهم:** جدول‌های `ORG.ORGANIZATION_UNIT_CONTACT_POINTS` و `ORG.SERVICE_POINT_CONTACT_POINTS` در کنترل واقعی پیشین صفر ردیف داشتند. R1 جدول `ORG.CONTACT_POINTS` را تازه ایجاد کرده است. بنابراین هیچ یک از شماره‌های ادعایی قبلی را نمی‌توان بدون ارائه/شناسایی منبع معتبر به شعب نسبت داد. این نسخه شماره فرضی، نمونه یا داده CIF را وارد نمی‌کند. برای بررسی محل اطلاعات از SQL فقط‌خواندنی زیر استفاده کنید:

`database/oracle/org/contacts-r2/01-ORG-LEGACY-BRANCH-PHONES-READONLY.sql`

اطلاعات تماسِ ثبت‌شده در `ORG.CONTACT_POINTS` و انتساب‌های معتبر، به محض انتخاب واحد نمایش داده می‌شوند. واردکردن شماره‌ها از منبع رسمی باید بعد از تأیید تطبیق **سازمان + کد شعبه** با رکورد مقصد انجام شود.

## شرط ضروری فعال‌سازی ثبت و ویرایش نشانی

در تصویر قبلی دکمه‌ها غیرفعال بودند چون ویژگی مدیریت و حسابرسی R2-B در Oracle فعال نبود. این وضعیت را نمی‌توان صرفاً با نصب سورس تغییر داد؛ دور زدن کنترل باعث ثبت تغییر بدون تاریخچه می‌شود.

1. **پشتیبان قابل بازیابی** پایگاه داده و نسخه سورس را تهیه کنید.
2. فایل `database/oracle/org/locations-r2b/01-ORG-UNIT-LOCATIONS-R2B-OPT-IN.sql` را در SQL Developer با **F5** اجرا کنید؛ مقدار پیش‌فرض `APPLY_CHANGES = NO` است و فقط پیش‌نمایش می‌دهد.
3. DBA ساختار و نام کاربری را بررسی کند. فقط در محیط **UAT**، مقدار را به `YES` تغییر داده و با F5 اجرا کنید. Oracle DDL به‌صورت ضمنی Commit می‌کند و اجرای نیمه‌کاره نیازمند بررسی دستی است.
4. در اتصال جدید فایل `database/oracle/org/locations-r2b/02-ORG-UNIT-LOCATIONS-R2B-VERIFY-READONLY.sql` را اجرا کنید. هر شش مورد ساختاری در بخش اول باید مقدار `1` داشته باشند. هر مغایرت را قبل از آزمون نوشتنی بررسی کنید.
5. برای بررسی مجوز حسابی که **برنامه با آن به Oracle متصل می‌شود** فایل `database/oracle/org/locations-r2b/03-ORG-R2B-APP-GRANT-AUDIT-READONLY.sql` را اجرا کنید. DBA دسترسی مناسب UPDATE/INSERT/SELECT روی `ORG.ORGANIZATION_UNIT_LOCATIONS` و INSERT/SELECT روی `ORG.OU_LOCATION_CHANGE_AUDIT` و دسترسی Sequence را برای حساب مشخص برنامه تأیید کند.
6. در نسخه جدید سورس:

```cmd
cd /d D:\Projects\core-banking-prototype-v0
call tools\VERIFY-ORG-R2C-MAP-UX.cmd
call build-production.cmd
call bin\start.cmd
```

اجرای `bin\start.cmd` فقط **پس از Build موفق** انجام شود. تغییر کد نسخه نرم‌افزار از `0.11.0` لازم نیست.

## مسیر فرم‌ها — Angular Hash Routing

- `http://localhost:8091/#/organization/unit-locations-canonical`
- `http://localhost:8091/#/organization/unit-contacts`
- `http://localhost:8091/#/organization/branch-map`

**توجه:** اتصال اینترنت مرورگر برای دریافت کاشی‌های نقشه CARTO لازم است. اگر کاشی‌ها در دسترس نباشند، فهرست نقاط و فیلترها همچنان کار می‌کنند. مختصات معتبر ایران محدود به عرض جغرافیایی ۲۴ تا ۴۱ و طول ۴۴ تا ۶۴ درجه‌اند؛ سایر ردیف‌ها به‌عنوان فاقد موقعیت قابل نمایش گزارش می‌شوند، نه اینکه جایگاه ساختگی دریافت کنند.

سلسله‌مراتب GEO به‌صورت `استان ← شهرستان ← بخش ← شهر` یا `استان ← شهرستان ← بخش ← دهستان` است. فیلترهای شهر و دهستان با هم هم‌زمان انتخاب نمی‌شوند. برای اینکه واحدی به دهستان منتسب شود باید شناسه GEO آن واقعاً شناسه همان دهستان باشد؛ در شناسه‌های فاقد تعیین نوع جغرافیایی احتمال هم‌نامی شناسه شهر/دهستان وجود دارد و مورد باید توسط متخصص داده بررسی شود. سیستم **نباید** نسبت مکانی حدس بزند.

## سناریوهای پذیرش (UAT)

1. قبل از نصب R2-B، فهرست نشانی قابل مشاهده و نوشتن غیرفعال بماند و پیام واضح نشان داده شود.
2. بعد از نصب و مجوزها، افزودن نشانی برای واحد آزمایشی با نقش `REGISTERED` و مرجع مستند ممکن باشد؛ کنترل کنید ردیف در `ORG.ORGANIZATION_UNIT_LOCATIONS` و سابقه `CREATE` در `ORG.OU_LOCATION_CHANGE_AUDIT` درج شود.
3. ویرایش همان ردیف، سابقه `UPDATE` ایجاد کند؛ نسخه اشتباه و استقرار اصلی هم‌پوشان باید رد شوند.
4. تعداد ۱۳۴۰ ردیف اولیه و چهار انتساب مشترک `LOCATION_ID=1327` محفوظ بماند؛ هیچ داده قدیمی به‌صورت خودکار حذف/بازنویسی نشود.
5. انتخاب شعبه دارای تماس ثبت‌شده در ORG، بلافاصله گرید را نمایش دهد؛ انتخاب شعبه فاقد تماس، پیام ساده و امکان افزودن نشان دهد. «خالی بودن گرید» به معنی حذف اطلاعات از فایل‌ها یا منابع دیگر نیست.
6. در نقشه، فیلتر استان سپس شهرستان سپس شهر/دهستان را آزمایش کنید؛ نقطه‌ها و فهرست باید هماهنگ باشند، بزرگ‌نمایی خوشه و بازکردن جزئیات کار کند.
7. دکمه‌های «نشانی و موقعیت» و «راه‌های ارتباطی» از جزئیات نشانگر، باید واحد درست را در فرم مقصد انتخاب کنند.
8. برای شعبه بدون مختصات، نقطه ساختگی نشان داده نشود و در آمار فاقد مختصات شمارش شود.
9. پنل موقعیت در اندازه کوچک مرورگر و در حالت راست‌به‌چپ نیز قابل استفاده باشد.

## وضعیت آزمون انتشار

کنترل‌های مستقل کد و ساختار ORG و تطبیق با نسخه‌های قبلی، بررسی نحوی TypeScript و کامپایل مستقل کلاس‌های جدید Java با stubها انجام شده است. این آزمون‌ها جایگزین **Build واقعی Angular/Spring Boot روی Windows** و **آزمون Oracle UAT** نیستند. دریافت برخی وابستگی‌های npm در محیط آماده‌سازی به علت محدودیت شبکه ممکن نشد. بدون تکمیل این دو مرحله، از انتشار در محیط تولید خودداری کنید.
