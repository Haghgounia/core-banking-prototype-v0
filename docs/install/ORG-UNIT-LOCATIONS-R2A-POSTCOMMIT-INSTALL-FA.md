# نصب و آزمون ORG Unit Locations R2-A — نسخه تجمیعی فقط‌خواندنی

## پیش‌شرط

- بسته R1 روی سورس فعلی نصب شده باشد.
- طبق خروجی SQL Developer تأیید شده: ۲۶ ستون جدول `ORG.ORGANIZATION_UNIT_LOCATIONS` وجود دارد؛ ۱۳۴۰ ردیف منتقل‌شده پس از `COMMIT` با مبدأ یکسان‌اند و مغایرت صفر بوده است.
- اتصال Backend به همان Schema معتبر ORG فعال باشد.

## نصب

برای Patch، فایل ZIP را با حفظ ساختار پوشه‌ها روی پروژه دارای R1 استخراج کنید. یا به‌جای Patch از ZIP کامل R2-A استفاده کنید؛ هر دو یک تغییر واحد دارند.

سپس در Windows:

```cmd
cd /d D:\Projects\core-banking-prototype-v0
call tools\VERIFY-ORG-UNIT-LOCATIONS-R2A.cmd
call build-production.cmd
call bin\start.cmd
```

## نشانی فرم

`http://localhost:8091/#/organization/unit-locations-canonical`

صفحه قدیمی برای کنترل مستقل نیز باقی مانده است:

`http://localhost:8091/#/organization/unit-locations-review`

> توجه: Frontend با `provideRouter(routes, withHashLocation())` اجرا می‌شود. علامت `#` در آدرس مرورگر الزامی است. بدون `#`، درخواست به Spring Boot می‌رسد و خطای `No static resource organization/unit-locations-canonical` برمی‌گرداند. این خطا مربوط به Oracle نیست و به‌تنهایی نیازی به Build یا SQL ندارد. مسیرهای داخلی `routerLink` خودشان `#` را مدیریت می‌کنند؛ فقط آدرس مستقیم مرورگر باید آن را داشته باشد.

اگر آدرس صحیح باز هم صفحه تازه را نشان نداد، نسخه R2-A را از منوی «سازمان و واحدها» باز کنید، و بررسی کنید نسخه R2-A پس از Build موفق در فرآیند Java فعلی فعال شده باشد. ابتدا برای عیب‌یابی مرورگر صفحه اصلی `http://localhost:8091/` را بررسی کنید.

## معیار پذیرش اولیه

- اعداد خلاصه از Backend در اتصال واقعی Oracle دریافت شوند.
- مطابق خروجی پس از COMMIT، انتظار می‌رود ۱۳۴۰ ردیف کل و ۱۳۴۰ نسخه منطبق و صفر اختلاف نمایش داده شود؛ به شرط آنکه منابع قدیمی از زمان گزارش تغییر نکرده باشند.
- جست‌وجوی کد واحد و نام واحد، و دکمه‌های صفحه قبل/بعد برای مرور کل ۱۳۴۰ رکورد کار کنند.
- برای مکان مشترک `1327`، چهار رکورد مستقل مربوط به واحدها باقی بمانند و برنامه مجازی/فیزیکی‌بودن را از روی نشانی حدس نزند.
- مقادیر کدپستی خالی بدون خطای اعتبارسنجی نمایش داده شوند.
- برای آدرس‌های یکسان با شناسه مشترک، هیچ سطر خودکار حذف یا ادغام نشود.
- آمار بالای صفحه کل داده‌های ORG است؛ هر صفحه ۱۵۰ سطر و همراه با تعداد رکوردهای فیلترشده باشد.
- هیچ endpoint نوشتنی یا DDL جدید در R2-A وجود ندارد؛ این بسته **فرم CRUD نهایی نیست**.

## در صورت خطا

اگر API canonical خطا بدهد، از بررسی اتصال/مجوزها و وضعیت ۲۶ ستون شروع کنید؛ صفحه legacy مستقل به تشخیص کمک می‌کند. اجرای مجدد SQL مهاجرت `02/03` بدون دلیل یا اجرای Drop دو جدول قبلی **مجاز نیست**.

## محدودیت آزمون منتشرشده

آزمون‌های استاتیک و کامپایل نحوی مستقل، جایگزین Build کامل ویندوز، اتصال واقعی Oracle، تست مرورگر و نظر کارشناسان کسب‌وکار نیست. تا پایان این کنترل‌ها، وضعیت R2-A «Source Ready / Live UAT Pending» است.
