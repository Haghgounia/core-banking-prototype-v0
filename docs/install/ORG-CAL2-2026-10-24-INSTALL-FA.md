# راهنمای نصب Patch مرزبندی ORG/CAL2 — ۲۰۲۶-۱۰-۲۴

**مبنای Patch:** نسخه سورس `core-banking-prototype-v0-2026-10-24-1043.zip`، با نقشه راه ORG قبلی. این Patch جایگزین همه Patchهای قبلی نیست؛ فقط از همین مبنا تغییر می‌دهد.

## مرحله اول — سورس و برنامه

1. از پروژه خود نسخه پشتیبان بگیرید؛ برنامه در حال اجرا را قبل از Build متوقف کنید.
2. ZIP Patch را روی ریشه پروژه `D:\Projects\core-banking-prototype-v0` استخراج کنید و فایل‌های موجود را جایگزین کنید. هیچ فایل جدیدی در ریشه غیرمجاز قرار داده نشده است.
3. کنترل ایستا را اجرا کنید:

```cmd
cd /d D:\Projects\core-banking-prototype-v0
call tools\VERIFY-ORG-CAL2-CLEANUP.cmd
```

4. سپس Build و راه‌اندازی را با فرمان‌های موجود پروژه انجام دهید:

```cmd
call build-production.cmd
call bin\start.cmd
```

اگر از Launcher قبلی CAL2 Pilot استفاده می‌کنید، پس از نصب این Patch همان Launcher نیز با `build-production.cmd` جدید کار می‌کند. در پنجره مرورگر، کش را Refresh کنید و منوی «سازمان و واحدها» را مشاهده کنید؛ «ساعات کاری» دیگر زیر ORG قرار ندارد و لینک آن در بالای صفحه به CAL2 می‌رود.

## مرحله دوم — Oracle (مجزا، مشروط، در محیط آزمایشی)

سورس و فرم‌ها را می‌توان مستقل از حذف جداول Oracle نصب کرد. برای Oracle ابتدا `01-ORG-CAL2-PREVIEW-READONLY.sql`، سپس `02-ORG-CAL2-DROP-EMPTY-OPT-IN.sql` با **پیش‌فرض NO** و در نهایت `03-ORG-CAL2-VERIFY-READONLY.sql` را اجرا کنید. محل: `database/oracle/org/calendar2-consolidation/`.

**هشدار:** اگر حتی یکی از هشت جدول رکورد دارد، یا وابستگی فعال خارج از محدوده دارد، مرحله APPLY نباید اجرا شود؛ اسکریپت آن را مسدود می‌کند. تصمیم برای انتقال داده باید جداگانه گرفته شود. اجرای DROP به‌صورت DDL در Oracle قابل ROLLBACK نیست. این بسته هیچ‌گاه خودش DDL را هنگام Build/Start اجرا نمی‌کند.
