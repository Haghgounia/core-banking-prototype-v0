# ORG R2-C — اصلاح فیلترها و تمرکز نقشه

مبنای Patch: نسخه R2-C نقشه با اصلاح OpenStreetMap (Map Tiles Hotfix). شماره نسخه 0.11.0 بدون تغییر.

## تغییرات

- پس از دریافت موفق نتایج فیلترها، مرکز و سطح بزرگ‌نمایی نقشه از **مختصات واقعی واحدهای فیلترشده** محاسبه می‌شود. برای مثال، انتخاب استان/شهرستان تهران دیگر نقشه را در شهرکرد رها نمی‌کند.
- در زمان تغییر استان، شهرستان و گزینه‌های وابسته پاک می‌شوند؛ هنگام تغییر شهرستان، شهر و دهستان پاک می‌شوند. دریافت گزینه‌های وابسته مانع به‌روزرسانی نقشه نمی‌شود. پاسخ‌های قدیمی نیز با توکن درخواست نادیده گرفته می‌شوند.
- نوع واحد به‌جای لیست ثابت سمت Angular، از `ORG.ORGANIZATION_UNIT_TYPES` خوانده می‌شود. برای این تغییر، فایل Java همراه Hotfix لازم است؛ هیچ DDL/SQL نوشتنی لازم نیست.
- جابه‌جایی/بزرگ‌نمایی دستی کاربر تا درخواست فیلتر بعدی حفظ می‌شود. روی تغییر اندازه پنجره، در صورتی که کاربر هنوز نمای دستی انتخاب نکرده باشد، نقاط دوباره متناسب می‌شوند.
- اگر فیلتر هیچ نتیجه‌ای نداشته باشد، نقشه نشانگر قدیمی را نگه نمی‌دارد و پیام مشخص نمایش داده می‌شود.

## نصب روی Windows

1. از سورس فعلی پشتیبان بگیرید. Hotfix ZIP را **داخل ریشه پروژه** `D:\Projects\core-banking-prototype-v0` استخراج کنید و چهار مسیر داخل بسته را با ساختار پوشه‌ای خود جایگزین/اضافه کنید. فایل توضیحی در `docs/install` قرار دارد و در ریشه پروژه نیست.
2. در CMD اجرا کنید:

```cmd
cd /d D:\Projects\core-banking-prototype-v0
node tools\verify-org-r2c-map-filters.mjs
node tools\verify-org-r2c-map-ux.mjs
node tools\verify-node-tool-path-portability.mjs
call bin\stop.cmd
call build-production.cmd
```

3. تنها اگر Build کامل موفق شد: `call bin\start.cmd` و سپس مرورگر `Ctrl+F5` روی `http://localhost:8091/#/organization/branch-map`.

## آزمون کسب‌وکاری

- ابتدا بدون فیلتر، نقشه باید روی نقاط کشور متمرکز شود.
- «استان تهران» را انتخاب کنید؛ شهرستان/شهر/دهستان باید پاک شده و نقشه با نقاط استان هماهنگ شود.
- «شهرستان تهران» را انتخاب کنید؛ با وجود بارگذاری شهرها/دهستان‌ها، داده‌ها باید بلافاصله با شهرستان تغییر کنند و نقشه به محدوده نتایج حرکت کند.
- سپس شهر تهران را انتخاب کنید؛ فهرست و نقاط نقشه باید فقط نتایج واقعی این انتخاب را نشان دهند.
- دهستان را انتخاب کنید: شهر انتخاب‌شده باید پاک شود و بالعکس. تعداد فیلترشده و فهرست و نقشه باید با هم سازگار باشند.
- نوع واحد را عوض کنید؛ گزینه‌ها باید از پایگاه داده باشد و نتایج به‌درستی محدود شود.
- شناسه یا نام واحد را با دکمه جست‌وجو وارد کنید؛ سپس بزرگ‌نمایی دستی را آزمون کنید.
- فیلترهایی انتخاب کنید که هیچ نتیجه‌ای ندارند؛ پیام بدون نتیجه باید روشن باشد.

## محدودیت مهم صحت GEO

ساختار فعلی `ORG.ORGANIZATION_UNIT_LOCATIONS` دارای `GEO_ENTITY_ID` عددی، بدون مشخص‌کننده سطح/نوع جغرافیایی است. در ساختار GEO، شناسه `GEO.CITIES.CITY_ID` و `GEO.RURAL_DISTRICTS.RURAL_DISTRICT_ID` از دو مجموعه مستقل‌اند و **ممکن است برابر شوند**. کد نقشه R2-C برای رفع تداخل، به‌صورت مقدماتی City را بر Rural District ترجیح می‌دهد؛ این کار ممکن است برای بعضی رکوردها نتیجه شهر/دهستان نادرست ایجاد کند. Hotfix حاضر **بدون داشتن منبع قطعی نوع GEO، این انتساب را حدس یا بازنویسی نمی‌کند**.

برای سنجش ریسک موجود، فایل `database/oracle/org/map-r2c/01-ORG-MAP-GEO-FILTER-DIAGNOSTIC-READONLY.sql` را با F5 اجرا و خروجی بخش‌های A و B را ارسال کنید. اگر `AMBIGUOUS_ID` غیرصفر باشد، باید نوع GEO از منبع رسمی تأیید و مدل داده تکمیل شود، نه اینکه نوع بر پایه انطباق عددی یا مختصات تخمین زده شود.

**هیچ DDL، DML یا COMMIT در Hotfix انجام نشده است.** آزمون‌های کد و منطق تغییر دوربین نقشه روی داده آزمایشی محلی اجرا شده‌اند، اما Build کامل Angular/Java و اجرای Oracle واقعی در این محیط تأیید نشده‌اند.
