# FEE UX R3-B.1 — اصلاح عنوان مرحله اخذ و وضعیت مؤلفه اختیاری

## زمینه و علت

در فرم «مرحله اخذ» نسخه 837 (تعریف 837)، فهرست «شناسه مؤلفه کارمزد» تنها گزینه `—` را نشان می‌دهد. طبق DDL جدول `FEE.FEE_CHARGE_STAGE`، ستون `CHARGE_COMPONENT_ID` قابل Null و ستون `CALCULATION_RULE_ID` اجباری است. در نسخه قبلی خطای اتصال/پاسخ lookup نیز به آرایه خالی تبدیل می‌شد و از حالت «مؤلفه ثبت نشده» قابل تفکیک نبود. بنابراین **فقط با تصویر نمی‌توان نبود رکورد مؤلفه در Oracle را قطعی دانست.**

## اصلاحات

1. عنوان وضعیت ثبت مرحله از «ثبت قاعده جدید — مراحل اخذ» به «تعریف مرحله اخذ جدید» و در ویرایش به «ویرایش مرحله اخذ» تغییر می‌کند.
2. برچسب‌های فرم **فقط در ویرایشگر کسب‌وکاری مرحله اخذ** به «قاعده محاسبه» و «مؤلفه کارمزد» تبدیل می‌شوند؛ نام ستون‌ها و API ثابت‌اند.
3. گزینه Null برای `CHARGE_COMPONENT_ID` به‌جای «—» با «بدون مؤلفه» نمایش داده می‌شود؛ **فیلد اختیاری می‌ماند**.
4. وضعیت‌های «در حال بارگذاری»، «پاسخ موفق ولی مؤلفه‌ای برای نسخه پیدا نشد» و «خطا در دریافت» از هم جدا می‌شوند. خطای دریافت هرگز به‌عنوان نبود مؤلفه معرفی نمی‌شود.
5. هنگام خالی بودن پاسخ موفق، لینک «تعریف مؤلفه در طراح قواعد» به تب `charge` با همان `definitionId` و `versionId` افزوده می‌شود. خروج از فرم با تغییرات ذخیره‌نشده همچنان به Guard موجود وابسته است.
6. فیلتر انتخابگر بر اساس `FEE_DEFINITION_VERSION_ID` و **کنترل سمت سرور R3-B** بدون تغییر حفظ می‌شوند.

## دامنه و استقلال

این Patch فقط سه فایل UI متعلق به FEE و چهار ابزار Verifier مرتبط را اصلاح می‌کند. **هیچ فایل Product Builder، FEE2، Backend، Oracle، منوی اصلی یا Routes اصلاح نمی‌شود.** نه SQL اجرایی دارد، نه Seed و نه Migration.

## نصب در CMD ویندوز

پیش‌نیاز: R3-B با موفقیت نصب شده باشد. از پروژه پشتیبان تهیه کنید؛ سپس بسته ZIP را در **پوشه ریشه پروژه** استخراج کنید. استخراج به‌تنهایی کد را تغییر نمی‌دهد.

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\install-fee-r3b1.mjs --check
node tools\install-fee-r3b1.mjs
node tools\verify-fee-r3b1.mjs
node tools\verify-fee-r3b.mjs
node tools\verify-fee-r3a.mjs
node tools\verify-fee-ux-r23.mjs
node tools\verify-fee2-studio.mjs
node tools\verify-pdl-r29-finalization.mjs
build-production.cmd
```

پس از Build موفق، برنامه را راه‌اندازی و مرورگر را با `Ctrl+Shift+R` بازآوری کنید. مسیر مورد آزمون:

`http://localhost:8091/#/fee/workspaces/collection?definitionId=837&versionId=837`

سپس در «مراحل اخذ» وارد «افزودن مرحله» شوید. عنوان‌ها، گزینه «بدون مؤلفه»، راهنمای وضعیت lookup و لینک طراح قواعد را بررسی کنید. **تا پیش از UAT کنترل API/Oracle هیچ رکورد تعرفه‌ای واقعی را ذخیره نکنید.**

## آزمون Read-only در Oracle

در صورت نیاز برای تشخیص واقعی اینکه نسخه 837 مؤلفه دارد یا نه، این پرس‌وجو را با اتصال خواندنی به **اسکیما FEE** اجرا کنید:

```sql
SELECT CHARGE_COMPONENT_ID, COMPONENT_CODE, NAME_FA, FEE_DEFINITION_VERSION_ID
  FROM FEE.FEE_CHARGE_COMPONENT
 WHERE FEE_DEFINITION_VERSION_ID = 837
 ORDER BY SEQUENCE_NO, CHARGE_COMPONENT_ID;
```

- اگر خروجی **هیچ رکوردی** نداشت و رابط کاربری نیز «مؤلفه‌ای یافت نشد» نشان داد، استفاده از «بدون مؤلفه» از نظر ساختار داده مجاز است.
- اگر Oracle رکورد داشت ولی رابط کاربری آن را نشان نداد، پاسخ endpoint مربوط به `FEE_CHARGE_STAGE/CHARGE_COMPONENT_ID` و سپس لاگ Backend بررسی شود؛ R3-B.1 این اختلاف را خودکار ترمیم نمی‌کند.
- اگر خطای دریافت رخ داد، پیام خطای متمایز نمایش داده می‌شود. رفع خطای شبکه/API خارج از دامنه اصلاح ظاهری است.

## بازگشت مستقل

```bat
node tools\uninstall-fee-r3b1.mjs --check
node tools\uninstall-fee-r3b1.mjs
node tools\verify-fee-r3b.mjs
build-production.cmd
```

بازگشت R3-B.1 فقط برچسب‌ها، راهنمای وضعیت lookup و Verifierهای سازگارشده را به حالت R3-B برمی‌گرداند؛ کنترل سمت سرور R3-B باقی می‌ماند. اگر فایل هدف توسط نسخه جدید دیگری تغییر کرده باشد، ابزار نصب یا بازگشت **عمداً متوقف می‌شود** تا تغییرات هم‌زمان از بین نروند.

## محدودیت آزمون

در محیط بسته‌بندی، کنترل‌های ایستا و Java policy و نصب/بازگشت اجرا می‌شوند؛ ساخت کامل Angular و Java با `build-production.cmd` و اتصال Oracle در سیستم شما لازم است. بر اساس تصویر نمی‌توان نتیجه تراکنش ذخیره در Oracle را تأیید کرد.
