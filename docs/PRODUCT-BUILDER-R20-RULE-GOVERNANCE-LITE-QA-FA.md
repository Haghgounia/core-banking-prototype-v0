# Core Banking Prototype — PB-R20 Lite

**موضوع:** اتصال حاکمیت دو جدولی Ruleها به Java / Angular فعلی، بر مبنای PB-R19 و Oracle نصب‌شده در `FREEPDB1`.

## اصول ثابت

- **صفر جدول جدید در این Patch.** از `PDL.RULE_POLICY_VERSION` و `PDL.RULE_CONTROL_POLICY` نصب‌شده با SYSTEM-HF1 استفاده می‌شود و تنها ستون قبلاً نصب‌شده `PDL.PRODUCT_VERSION.RULE_POLICY_VERSION_ID` مصرف می‌شود.
- قابلیت‌های قبلی، فرم‌های مراحل ۱ تا ۵، قواعد سپرده/تسهیلات، FEE2، و سایر ماژول‌ها حذف نمی‌شوند.
- پیاده‌سازی موتور عمومی Rules، زبان شرط، Override دلخواه، سلسله‌مراتب G1 تا G7 یا جدول اضافی در محدوده این نسخه نیست.
- هیچ حساب/نسخه قدیمی با اتصال سیاست `NULL` خودکار مهاجرت نمی‌شود؛ با قطع بودن گزینه Cutover، مسیر PB-R19 باقی می‌ماند.
- سیاست مصوب از جدول‌های واقعی Oracle خوانده می‌شود و بر ارزیابی قواعد مرحله ششم اثر می‌گذارد.
- **این نسخه اجرای عملیات تراکنش سپرده را به Ruleها متصل نمی‌کند.** قفل Runtime مربوطه حفظ شده است.

## تغییرات برنامه

1. `RuleGovernanceLiteService.java` — APIهای کوچک SQL-parameterized با `@Transactional`: فهرست، ایجاد پیش‌نویس با ۲۳ کنترل پیش‌فرض، ویرایش کنترل‌ها، Clone، تصویب، اتصال به نسخه DRAFT.
2. `RuleGovernanceLiteController.java` — endpointهای اختصاصی، بدون افزودن جداول سیاست به CRUD عمومی PDL.
3. `ProductRuleGovernanceService.java` — ارزیابی سیاست متصل با منطق `REQUIRED` / `WHEN_ENABLED` / `OPTIONAL` و `BLOCK_PUBLISH` / `BLOCK_OPERATION` / `WARN` / `IGNORE`، بررسی اعتبار سیاست و وابستگی مدت/نرخ پله‌ای.
4. `ProductBuilderService.java` — جلوگیری از تغییر `RULE_POLICY_VERSION_ID` از مسیر CRUD عمومی.
5. `ProductRuleEvidenceEvaluator.java` — تشخیص درست `IS_ACTIVE` بدون اشتباه گرفتن `IS_ALLOWED` با فعال بودن.
6. Angular — کامپوننت مستقل `rule-policy-lite.*` در **مرحله ۶ بازبینی نهایی** با `MatFormField` و سایر کامپوننت‌های Design System فعلی.
7. Node Verifier خودکار + SQL بررسی ساختار موجود + Runtime smoke فقط خواندنی.

## مسیرهای REST

```
GET  /api/v1/product-builder/rule-policies
GET  /api/v1/product-builder/rule-policies/{id}/controls
POST /api/v1/product-builder/rule-policies
POST /api/v1/product-builder/rule-policies/{id}/clone
PUT  /api/v1/product-builder/rule-policies/{id}/controls
POST /api/v1/product-builder/rule-policies/{id}/approve
PUT  /api/v1/product-builder/versions/{id}/rule-policy
GET  /api/v1/product-builder/versions/{id}/rule-governance
```

در Prototype، عملیات `POST`/`PUT` سیاست، Header آزمایشی `X-User-Name` می‌پذیرند. **این هویت‌سنجی واقعی نیست؛ Production مجاز نیست تا اصل هویت و Role در Backend جایگزین شود.**

## فعال‌سازی تدریجی Cutover (پس از UAT)

به‌صورت پیش‌فرض غیرفعال است. پس از تصویب رسمی استقرار می‌توان تنظیم زیر را به Spring Boot افزود:

```properties
core-banking.product-builder.rule-governance-lite.enforce-from=2026-11-01
```

تاریخ نمونه است؛ نباید بدون تأیید بانک تنظیم شود. نسخه‌هایی که `CREATED_AT` آن‌ها از این روز به بعد باشد، بدون سیاست مصوب نمی‌توانند از Gate انتشار عبور کنند. مقایسه در سطح **تاریخ** انجام می‌شود. نسخه‌های قدیمی با `NULL` همچنان از مسیر قبلی ارزیابی می‌شوند. برای محصول جدید نخست پیش‌نویس، سپس سیاست مصوب و بعد ارزیابی انتشار انجام می‌شود.

## راه‌اندازی و سناریوی UAT

1. از ZIP کامل PB-R20 Lite بر پایه PB-R19 استفاده کنید، یا Patch را فقط روی **همان PB-R19** Overlay کنید؛ برای درخت‌های سورس جدیدتر، ابتدا Merge انجام شود.
2. **اسکریپت نصب Oracle قبلی را دوباره اجرا نکنید**؛ ساختار قبلاً در PDL ساخته شده است.
3. با SYSTEM در `FREEPDB1`، فقط SQL بررسی read-only را اجرا کنید.
4. `build-production.cmd` را در Windows اجرا کنید، سپس سرویس را با تنظیمات صحیح DB آغاز کنید.
5. `set CORE_BANKING_BASE_URL=http://127.0.0.1:8091` و سپس `node tools\\runtime-rgl-lite-r20-smoke.mjs` را اجرا کنید.
6. یک محصول آزمایشی، نسخه DRAFT و یک سیاست DRAFT بسازید. ۲۳ کنترل را مرور کنید.
7. با Maker و Checker جدا و مرجع تصویب مشخص، سیاست را تصویب کنید؛ آزمون کنید که نسخه مصوب قابل ویرایش نیست.
8. سیاست مصوب را به نسخه محصول DRAFT وصل کنید؛ ماتریس را بازآزمایی کنید.
9. Rule ضروری را موقتاً در نسخه آزمایشی DRAFT حذف/غیرفعال کنید و اختلاف `BLOCK_PUBLISH`/`BLOCK_OPERATION` را بیازمایید.
10. روی نسخه عملیاتی قدیمی بدون ارجاع سیاست کنترل رگرسیون بگیرید؛ نباید تغییر رفتار غیرمنتظره داشته باشد.

## بازگشت

در صورت بروز مشکل برنامه، فایل‌های Patch را از نسخه PB-R19 جایگزین کنید یا همان نسخه PB-R19 را مجدداً نصب کنید. **جداول نصب‌شده Oracle را Drop نکنید**؛ نسخه R20 Lite آن‌ها را حذف یا تغییر نمی‌دهد. اگر پیش از بازگشت از R20 به نسخه PB-R19 سیاست‌هایی را متصل کرده‌اید، هماهنگی رفتار Gate با مسئول استقرار لازم است.
