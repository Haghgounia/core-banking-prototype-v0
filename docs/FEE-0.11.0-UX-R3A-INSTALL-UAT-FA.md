# راهنمای نصب و پذیرش FEE UX R3-A

## هدف و محدوده
این بسته، نخستین محیط کاری وابسته به نسخه برای «اخذ، وصول و ثبت حسابداری» در ماژول مستقل **FEE** است. به جای پنج گرید فنی کنار یکدیگر، انتخاب یک **تعریف کارمزد** و سپس **نسخه معتبر همان تعریف** انجام می‌شود. آنگاه داده‌های هر تب فقط بر اساس `FEE_DEFINITION_VERSION_ID` خوانده می‌شوند.

پنج بخش: مراحل اخذ (`FEE_CHARGE_STAGE`)، زمان‌بندی (`FEE_TIMING_RULE`)، ارز (`FEE_CURRENCY_RULE`)، وصول (`FEE_COLLECTION_RULE`) و ثبت حسابداری (`FEE_POSTING_RULE`). چهار بخش آخر فرم «افزودن/ویرایش» مستقل از جدول دارند، با استفاده مجدد از متادیتا و API عمومی FEE؛ FK نسخه هنگام ثبت خودکار تنظیم و در فرم قفل است.

**محدودیت آگاهانه:** مرحله اخذ (`FEE_CHARGE_STAGE`) علاوه بر نسخه تعریف، FK اجباری به `FEE_CALCULATION_RULE` دارد. از آنجا که DDL دو FK جداگانه دارد و رابطه ترکیبی تضمین‌کننده تطابق نسخه وجود ندارد، R3-A برای این تب **فقط بازبینی** ارائه می‌کند؛ ساخت/ویرایش از محیط جدید تا کنترل cross-version در R3-B غیرفعال است. مسیر فنی قدیمی همچنان موجود است و باید با مسئولیت کنترل دامنه استفاده شود.

هیچ DDL، Seed، API یا رفتار Backend، موتور FEE2 یا فایل اختصاصی Product Builder تغییر نمی‌کند.

## روش نصب
پیش‌نیاز: نسخه پروژه با FEE UX R2.2 و R2.3 نصب‌شده. این بسته روی مبنای نسخه ۲۰۲۶-۱۰-۱۱ ساعت ۲۱:۵۳ با R2.2 و R2.3 آزمایش شده است.

ZIP را **در ریشه پروژه** استخراج کنید؛ صرفاً استخراج ZIP سورس فعال را تغییر نمی‌دهد. از پروژه پشتیبان بگیرید و دستورات را اجرا کنید:

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\install-fee-r3a.mjs --check
node tools\install-fee-r3a.mjs
node tools\verify-fee-r3a.mjs
node tools\verify-fee-ux-r23.mjs
node tools\verify-fee2-studio.mjs
node tools\verify-pdl-r29-finalization.mjs
build-production.cmd
```

مسیر جدیدی در `app.routes.ts` اضافه نشده است. همان کارت و مسیر موجود `/fee/workspaces/collection` اکنون محیط وابسته به نسخه را باز می‌کند. نصب‌کننده **نسخه قدیمی `app.routes.ts` را جایگزین نمی‌کند**: فقط یک `canDeactivate` محافظ ذخیره‌نشدن برای Route موجود FEE و یک import type اضافه می‌کند. اگر این سطر در نسخه موازی عوض شده باشد، نصب متوقف می‌شود؛ تغییرات Product Builder دست‌نخورده می‌مانند.

## UAT روی ویندوز و Oracle

۱. صفحه `http://localhost:8091/#/fee` را باز کنید و کارت «اخذ، وصول و ثبت حسابداری» را انتخاب کنید. در `/fee/workspaces/collection` باید محیطی با دو انتخابگر تعریف/نسخه و پنج تب ببینید، نه پنج گرید عمومی پشت سر هم.

۲. یک تعریف کارمزد با نام فارسی جست‌وجو کنید. سپس نسخه همان تعریف را انتخاب کنید. تغییر تعریف باید نسخه قبلی و اطلاعات وابسته را پاک کند. فهرست نسخه نباید رکورد تعریف دیگری نشان دهد.

۳. در تب‌های «زمان‌بندی»، «ارز و تبدیل»، «روش وصول» و «ثبت حسابداری»، رکوردهای همان نسخه را مشاهده کنید. هنگام افزودن/ویرایش، جدول نباید هم‌زمان کنار فرم ظاهر شود. فیلد FK نسخه باید مخفی و خودکار باشد. برای آزمون ایجاد، از یک تعریف و نسخه **آزمایشی** استفاده کنید، نه تعرفه واقعی بانک مرکزی.

۴. در تب «مراحل اخذ»، پیام امنیت ارتباط قاعده محاسبه نمایش داده شود و دکمه افزودن/ویرایش در محیط جدید نباشد. لینک طراح قواعد محاسبه با `definitionId` و `versionId` فعلی کار کند.

۵. در فرم ویرایش یک مقدار را تغییر دهید و بدون ذخیره روی تب دیگر یا گزینه منو کلیک کنید. باید هشدار از دست‌رفتن تغییرات نمایش داده شود. با «انصراف» باید مقدار Oracle بدون تغییر باقی بماند.

۶. از کاتالوگ به طراحی قواعد و بالعکس بروید، و `definitionId` و `versionId` را در URL کنترل کنید. خروجی و فهرست مربوط به همان نسخه باشد.

۷. ناوبری موتور FEE2 و Product Builder R29/جدیدتر را کنترل کنید؛ هیچ ادغام یا وابستگی تازه‌ای ایجاد نشده است.

## بازگشت

```bat
node tools\uninstall-fee-r3a.mjs --check
node tools\uninstall-fee-r3a.mjs
build-production.cmd
```

بازگشت محتوای قبلی دو فایل FEE را فقط در صورت تطبیق SHA برمی‌گرداند و فایل‌های جدید R3-A را برمی‌دارد؛ سطر Guard جدید در `app.routes.ts` حذف می‌شود، ولی هر Route دیگری که هم‌زمان اضافه شده است **حفظ می‌شود**. اگر فایل‌های R3-A بعداً تغییر کنند، بازگشت امن متوقف می‌شود.

## وضعیت آزمون
آزمون‌های ایستا، بررسی DDL و API، نصب، برگشت و Regression در محیط توسعه انجام می‌شوند؛ اجرای کامل Angular، اتصال Oracle و پذیرش مرورگر باید روی دستگاه کاربر گزارش شود. هیچ ادعای Runtime PASS بدون اجرای واقعی وجود ندارد.
