# FEE UX R2.1 — کاتالوگ زمینه‌محور و اصلاح انتخاب/ویرایش

**مبنای تغییر:** `core-banking-prototype-v0-2026-10-11-1835.zip`

**دامنه تغییر:** فقط رابط کاربری ماژول FEE و تست ایستای آن. ساختار Oracle، قراردادهای REST، موتور محاسبه کارمزد و ماژول FEE2 تغییر نکرده‌اند.

## مسئله اصلاح‌شده

در R2 فهرست `FEE_DEFINITION` هم در ستون انتخاب سمت راست و هم در جدول میانی نمایش داده می‌شد. با وجود ۳۸۳ تعریف کارمزد، گرید تکراری و ستون شرح طولانی خوانایی را از بین می‌برد. تب نسخه‌ها نیز به انتخاب یک نسخه نیاز داشت و در صفحه قواعد، کاربر بدون انتخاب زمینه با حالت خالی روبه‌رو می‌شد.

## تغییرات R2.1

1. ستون سمت راست، **تنها فهرست دائم انتخاب کارمزد** است. هر آیتم دکمه «انتخاب» و Highlight حالت انتخاب‌شده دارد.
2. تب «تعریف کارمزد» در مرکز، **شناسنامه کارمزد انتخابی** را با اطلاعات معتبر `FEE_DEFINITION` و شرح کوتاه‌شده نشان می‌دهد. شرح کامل با بازکردن قسمت جزئیات قابل مشاهده است.
3. تب «نسخه‌ها» به‌طور پیش‌فرض **مشخصات نسخه انتخاب‌شده** را به‌جای گرید تکراری نمایش می‌دهد. در نبود نسخه، «ایجاد نسخه برای این کارمزد» ارائه می‌شود.
4. عملیات «تعریف کارمزد جدید»، «ویرایش تعریف»، «نسخه جدید» و «ویرایش نسخه» **فرم فعلی Generic CRUD را در همان صفحه و به‌صورت درخواستی** باز می‌کند. عملیات ویرایش با رکورد انتخاب‌شده مقداردهی اولیه می‌شود.
5. هنگام ثبت رکورد وابسته، ارتباط والد مطابق R2 از طریق همان قرارداد FEE کنترل می‌شود. برای فیلتر روی Primary Key، **ستون PK به payload ذخیره تحمیل نمی‌شود**.
6. انتخاب Definition/Version و تب فعال در URL نگهداری می‌شود. دکمه «طراحی قواعد این نسخه» همان Definition و Version را به محیط قواعد می‌برد.
7. در صفحه قواعد بدون Definition/Version، **دکمه جستجو یا انتخاب نسخه** نمایش داده می‌شود و در نبود نسخه لینک مستقیم به تب ساخت نسخه وجود دارد.
8. پس از جستجو یا تغییر صفحه، اگر تعریف/نسخه انتخاب‌شده خارج از نتایج جاری باشد، پیام «انتخاب جاری خارج از صفحه نتایج» نمایش داده می‌شود؛ انتخاب کاربر پاک نمی‌شود.
9. تعویض Rule انتخاب‌شده هنگام ویرایش ذخیره‌نشده نیز به کنترل تغییرات ذخیره‌نشده متصل شد.

## ساختار و سازگاری

- `FEE_DEFINITION`، `FEE_DEFINITION_VERSION` و سایر ۴۵ جدول همان جداول قبلی‌اند.
- مسیرهای `/fee/design/catalog`، `/fee/design/rules`، `/fee/tables/:table` و `/fee/references` حفظ شده‌اند.
- تمام فرم‌های مستقل CRUD برای ابزارهای فنی و عیب‌یابی در دسترس‌اند.
- هیچ فایل `frontend/src/app/features/fee2/`، هیچ کلاس `fee2` در Backend، و هیچ فایل DDL/Seed تغییر نکرده است.
- **SQL جدید ندارد.**

## نصب روی Windows

1. از پوشه `D:\Projects\core-banking-prototype-v0` نسخه پشتیبان تهیه کنید.
2. Runtime را به روش معمول پروژه متوقف کنید.
3. اگر نسخه ۱۸:۳۵ را هم‌اکنون نصب دارید، **فقط Patch R2.1** را در ریشه پروژه استخراج کنید؛ اگر از نسخه قدیمی‌تر استفاده می‌کنید، از بسته کامل R2.1 استفاده کنید. **هردو ZIP را هم‌زمان نصب نکنید.**
4. از CMD در ریشه پروژه دستورهای زیر را اجرا کنید:

```bat
node tools\verify-fee-admin-baseline.mjs
node tools\verify-fee-ux-r1.mjs
node tools\verify-fee-ux-r2.mjs
node tools\verify-fee-ux-r21.mjs
node tools\verify-fee2-forms.mjs
node tools\verify-fee2-studio.mjs
build-production.cmd
```

5. بعد از Build موفق، Runtime را به روش معمول (در نسخه فعلی `bin\start.cmd`) راه‌اندازی کنید و صفحه `http://localhost:8091/#/fee/design/catalog` را باز کنید.

## آزمون پذیرش UAT پیشنهادی

| آزمون | اقدام | انتظار |
|---|---|---|
| UAT-01 | ورود به کاتالوگ بدون انتخاب | پیام راهنمای انتخاب، بدون جدول بزرگ تکراری |
| UAT-02 | انتخاب کارمزد از ستون راست | Highlight و نمایش جزئیات همان تعریف در مرکز |
| UAT-03 | انتخاب کارمزد دارای شرح طولانی | نمایش حداکثر دو خط شرح و امکان بازکردن متن کامل |
| UAT-04 | جستجو یا صفحه‌بندی با تعریف انتخابی | عدم پاک‌شدن انتخاب؛ پیام انتخاب خارج از نتایج جاری در صورت لزوم |
| UAT-05 | ورود به تب نسخه‌ها | نمایش نسخه‌های فقط همان تعریف |
| UAT-06 | تعریف دارای صفر نسخه | نمایش پیام «فاقد نسخه» و دکمه ایجاد نسخه |
| UAT-07 | انتخاب یک نسخه موجود | نمایش شماره، وضعیت، تاریخ اعتبار، سیاست و کد تعرفه |
| UAT-08 | کلیک ویرایش تعریف/نسخه | بازشدن فرم ویرایش در همان صفحه با داده رکورد؛ ذخیره فقط پس از تأیید کاربر |
| UAT-09 | ایجاد رکورد جدید در حالت آزمایشی مجاز | اتصال نسخه به تعریف جاری، ثبت صحیح Oracle و بازگشت به خلاصه |
| UAT-10 | ورود به طراحی قواعد از نسخه | انتقال همان Definition/Version و فیلتر قواعد براساس آن |
| UAT-11 | ورود مستقیم به `/fee/design/rules` بدون انتخاب | نمایش دکمه‌های جستجوی کارمزد و انتخاب نسخه، نه بن‌بست UX |
| UAT-12 | ویرایش ناتمام و تلاش برای تغییر زمینه | هشدار تغییرات ذخیره‌نشده و جلوگیری از خروج در صورت لغو |
| UAT-13 | بازکردن `/fee2/studio` | رفتار قبلی بدون تغییر |

**توجه:** UAT-09 فقط روی داده آزمایشی یا با مجوز انجام شود؛ R2.1 هیچ داده Seed وارد نمی‌کند و هیچ رکوردی را خودکار ایجاد یا حذف نمی‌کند.

## وضعیت تضمین کیفیت

- تست‌های استاتیک R1، R2، R2.1، FEE Baseline و FEE2 اجرا و پاس شده‌اند.
- بررسی نحوی TypeScript و توازن تگ‌های HTML انجام شده است.
- برای اعلام آمادگی انتشار، هنوز **کامپایل کامل Angular، Build پروژه، و آزمون Runtime/Oracle در محیط کاربر** لازم است. در محیط ساخت این بسته، وابستگی‌های `frontend/node_modules` موجود نبودند.
