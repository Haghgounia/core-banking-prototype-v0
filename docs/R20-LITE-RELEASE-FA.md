# Core Banking Prototype — PB-R20 Lite (2026-10-10)

## چه چیزی نصب می‌شود؟

این تحویل **سورس Java و Angular** را به ساختار **Rule Governance Lite** نصب‌شده در Oracle متصل می‌کند. مبنا دقیقاً `core-banking-prototype-v0-2026-10-10-PB-R19.zip` است.

- ۲ جدول و ۱ ستون مرجع RGL **قبلاً** در `PDL` نصب و Smoke-Test شده‌اند.
- این نسخه **هیچ جدول، ستون یا Trigger جدیدی ایجاد نمی‌کند** و اجرای دوباره `02-install.sql` لازم نیست.
- صفحه مدیریت سیاست به مرحله ۶ «بازبینی نهایی» Product Builder اضافه می‌شود؛ مراحل ۱ تا ۵ دست‌نخورده‌اند.
- منطق Validation از سیاست واقعاً تصویب‌شده می‌خواند؛ وجود Rule/Rule فعال، تعارض و Scope ماژول بررسی می‌شود.
- اتصال Ruleها به موتور عملیات سپرده هنوز انجام نشده و همان کنترل ایمنی R19 برقرار است.

## تفاوت Patch با Full

- **Patch:** فقط فایل‌های تغییر‌یافته. آن را روی PB-R19 نصب کنید، یا تغییراتش را با کد جدیدتر خود Merge کنید.
- **Full:** منبع کامل PB-R19 به‌علاوه PB-R20 Lite. اگر روی ماشین شما تغییرات بعد از PB-R19 مثل فرم‌های جدید FEE2 دارید، **Full را بدون Merge جایگزین نکنید**؛ در غیر این صورت فایل‌های جدیدتر ممکن است از دست بروند.

## مراحل Windows

۱. یک Backup از سورس موجود تهیه کنید.

۲. Patch را در `D:\\Projects\\core-banking-prototype-v0` روی پروژه مبتنی بر PB-R19 Overlay کنید؛ فایل‌های قبلی را حذف نکنید.

۳. با SYSTEM در `FREEPDB1` در صورت نیاز تنها اسکریپت **خواندنی** زیر را اجرا کنید:

```
@docs/oracle/rgl-lite-installed-contract.sql
```

۴. ساخت نسخه Production:

```
cd /d D:\\Projects\\core-banking-prototype-v0
build-production.cmd
```

۵. پس از راه‌اندازی Backend روی پورت مرجع، آزمون فقط خواندنی API:

```
set CORE_BANKING_BASE_URL=http://127.0.0.1:8091
node tools\\runtime-rgl-lite-r20-smoke.mjs
```

۶. از منوی محصول‌ساز → محصولات → نسخه پیش‌نویس → **مرحله ۶** پنل «سیاست قواعد محصول (Lite)» را ببینید. با دو شناسه آزمایشی **متفاوت** سیاست را ایجاد/تصویب و اتصال به نسخه محصول را امتحان کنید. بانک باید نقش Maker/Checker واقعی را پیش از Production متصل کند.

## فعال‌سازی کنترل اجبار سیاست برای نسخه‌های جدید

در این تحویل **غیرفعال** است تا نسخه‌های قبلی و UAT شکسته نشوند. بعد از تصویب تاریخ Cutover در تنظیمات Spring:

```
core-banking.product-builder.rule-governance-lite.enforce-from=YYYY-MM-DD
```

مقدار نمونه را کپی نکنید؛ تاریخ واقعی Cutover باید به تصمیم بانک برسد. تاریخ نسخه محصول از `CREATED_AT` بررسی می‌شود؛ نسخه جدید بعد از تاریخ انتخابی بدون سیاست مصوب اجازه انتشار ندارد. تغییری در نسخه‌های تاریخی قبل از آن تاریخ داده نمی‌شود.

## مرزهای آزمون

- ۱۰۶ verifier ایستای Node موفق (شامل ۵۳ کنترل تازه R20).
- Java smoke برای مسیر Policy و وضعیت فعال Rule موفق؛ کامپایل Java با stub وابستگی‌های Spring انجام شده است.
- بررسی نحوی TypeScript موفق؛ **Angular build واقعی** نیازمند `npm ci` و اجرای `build-production.cmd` روی ماشین توسعه‌دهنده است.
- اجرای Oracle قبلی با موفقیت توسط کاربر گزارش شده؛ **API جدید هنوز به Oracle واقعی این مرحله وصل و تست نشده است**.
- تست role security، آزمون Endpoint در محیط واقعی و تست Runtime تراکنش برای Production باقی مانده‌اند.
