# PB-R15 — اصلاح قواعد قیمت‌گذاری، روابط محصولات و رفتار ثبت/کپی سپرده

**مبنای کد:** آخرین بسته PB-R14؛ **مبنای رفتاری:** `docs/reference/Unified_Product_Builder_Interactive_Forms_FA.html`، بخش‌های `PRODUCT_PRICING_RULE`، `PRODUCT_RELATIONSHIP`، `DEPOSIT_PRODUCT_PROFILE`، `DEPOSIT_PRODUCT_OPENING_RULE`. قرارداد دیتابیس و API موجود تغییر نکرده است.

## تغییرات

### قواعد قیمت‌گذاری مشترک
- `PRICING_PURPOSE_CODE`: هدف قیمت‌گذاری از چهار گزینه مصوب: سود سپرده، سود/نرخ تسهیلات، کارمزد، وجه التزام. ورود آزاد ممنوع.
- `PRICING_METHOD_CODE`: ثابت، شناور، پلکانی، فرمولی، به‌صورت ComboBox.
- `ACCRUAL_FREQUENCY_CODE`: تناوب شناسایی مستقل از `SETTLEMENT_FREQUENCY_CODE`: تناوب تسویه/پرداخت. هر دو انتخابی، با راهنمای کسب‌وکار.
- `DESTINATION_RULE_CODE`: نحوۀ تعیین مقصد پرداخت از چهار حالت بررسی‌شده در HTML مرجع، انتخابی.
- `EARLY_TERMINATION_ALLOWED`: کلید بله/خیر؛ `EARLY_TERMINATION_RATE` فقط هنگام «بله» فعال است، در «خیر» تهی می‌شود؛ سمت سرور نیز کنترل دارد.
- نرخ پایه و نرخ خاتمه زودهنگام **به صورت اعشاری** است: `0.18 = 18%`؛ مقدار بین ۰ و ۱ است. این «نرخ خاتمه زودهنگام» نرخ قابل استفاده برای تسویه زودتر از سررسید است؛ نه کارمزد عملیات حذف رکورد.
- منبع گزینه‌ها قرارداد مصوب HTML است **فقط در صورتی که** با دامنه CHECK واقعی Oracle سازگار باشند؛ اگر CHECK محدودتر باشد، تقاطع نمایش داده می‌شود؛ کد نامعتبر ساختگی در پایگاه داده ثبت نمی‌شود.

### رابطه بین محصولات
- انتخاب «محصول مقصد» از **محصولات واقعی**، با نمایش نام و کد محصول؛ خود محصول مبدأ کنار گذاشته می‌شود.
- انتخاب «نسخه مقصد» از نسخه‌های همان محصول مقصد و به صورت اختیاری. با تغییر محصول مقصد، نسخه قبلی پاک می‌شود.
- `RELATIONSHIP_TYPE_CODE` مطابق مدل همین فرم (`REQUIRES/BUNDLE/RATE_DEPENDENCY/COLLATERAL_ACCOUNT`) نه فهرست عمومی نامتناسب.
- اولویت، عدد صحیح مثبت است؛ **۱ بالاترین اولویت**. الزامی بودن با کلید بله/خیر؛ حداقل/حداکثر مبلغ باید سازگار باشند.
- Endpoint ذخیره، ارتباط مقصد با نسخه، عدم ارجاع به خود و محدودیت‌های مبالغ را **در Backend** نیز کنترل می‌کند.

### پروفایل سپرده و قواعد افتتاح
- هر رکوردی که قبلاً برای نسخه محصول جاری وجود دارد با انتخاب **افزودن** برای ویرایش باز می‌شود، تا به‌جای خطای نامفهوم یکتایی، مسیر اصلاح در اختیار کاربر قرار گیرد.
- **Clone** برای پروفایل سپرده و قاعده افتتاح، انتخاب *نسخه مقصد دیگری از همان محصول* را می‌خواهد که هنوز رکورد مشابه ندارد. هنگام کپی، کلید فنی جدید از سامانه گرفته می‌شود و رکورد مبدأ تغییر نمی‌کند.
- اگر نسخه دیگری موجود نباشد، پیام راهنما «ابتدا نسخه جدید محصول را ایجاد کنید» نمایش داده می‌شود. هیچ دورزدنی برای قید UNIQUE انجام نشده است.
- Backend قبل از INSERT تکراری، پیغام فارسی با اقدام درست برمی‌گرداند. نکته: وجود رکورد **soft-deleted** یا سایر قیود ترکیبی در بانک واقعی هنوز باید با SQL تشخیصی فقط‌خواندنی سنجیده شود.

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\verify-pb-r15.mjs
build-production.cmd
bin\start
```

**آزمون دستی پذیرش:** قیمت‌گذاری (انتخاب تمام کدها، نرخ ۰٫۱۸، خاموش/روشن‌کردن خاتمه)، رابطه محصولات (تعویض محصول مقصد و مشاهده تغییر فهرست نسخه)، پروفایل و افتتاح (افزودن روی نسخه دارای رکورد → ویرایش؛ Clone → انتخاب نسخه دیگر؛ ذخیره و Refresh). برای بررسی یکتایی فیزیکی از `database/oracle/pdl/diagnostics/pb-r15-pricing-opening-diagnostics.sql` بدون هرگونه DML استفاده شود.
