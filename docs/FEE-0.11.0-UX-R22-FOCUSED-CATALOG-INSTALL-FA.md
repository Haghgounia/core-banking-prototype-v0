# FEE UX R2.2 — کاتالوگ و نسخه‌های کارمزد، نمای متمرکز

## دامنه
- فقط بخش `FEE /fee/design/catalog` تغییر می‌کند. منوهای R22/R22.1، Product Builder R29، FEE2، Backend و Oracle دست‌نخورده می‌مانند.
- **مرور فهرست:** جستجوی تمام‌عرض تعاریف، تعداد رکوردها و صفحه‌بندی. جزئیات فقط پس از انتخاب نمایش داده می‌شود.
- **نسخه‌ها:** فهرست نسخه‌ها فقط برای تعریف کارمزد انتخابی؛ هنگام انتخاب نسخه، جزئیات و دکمه اتصال به قواعد نمایش داده می‌شود.
- **ثبت/ویرایش:** فرم از روی metadata موجود FEE و همان APIها ساخته می‌شود ولی در حالت Editor-Only، جدول تکراری نمایش داده نمی‌شود؛ فضای افقی کامل به فرم اختصاص می‌یابد.
- **حفاظت:** کنترل تغییرات ذخیره‌نشده، کنترل FK نسخه به تعریف مادر، حفظ context در query params و امکان بازگشت به فهرست.
- فرم‌های فنی همچنان قابل دسترسی‌اند، اما لینک آنها زیر «دسترسی فنی» قرار دارد.

## نصب ایمن
ابتدا از مسیر پروژه نسخه پشتیبان تهیه کنید. ZIP را در **ریشه پروژه** استخراج کنید. این ZIP **خودبه‌خود هیچ فایل FEE را بازنویسی نمی‌کند**. فقط ابزار نصب و payload را در `tools` و راهنما را در `docs` اضافه می‌کند. سپس در CMD:

```bat
cd /d D:\Projects\core-banking-prototype-v0
node tools\install-fee-ux-r22.mjs --check
node tools\install-fee-ux-r22.mjs
node tools\verify-fee-ux-r22.mjs
node tools\verify-fee-ux-r21.mjs
node tools\verify-fee2-studio.mjs
node tools\verify-pdl-r29-finalization.mjs
build-production.cmd
```

نصب‌کننده شش فایل FEE را با SHA-256 نسخه مبنا/مقصد مقایسه می‌کند؛ اگر فایل FEE در نسخه جدیدتر تغییر کرده باشد، **قبل از هر تغییر** متوقف می‌شود. نصب چندباره بدون اثر اضافی است. این کنترل صرفاً برای نسخه مبنا R2.1 روی سورس ۲۱:۵۳ یا نسخه‌های جدیدتری است که همان شش فایل را تغییر نداده‌اند.

## بازگشت

```bat
node tools\uninstall-fee-ux-r22.mjs --check
node tools\uninstall-fee-ux-r22.mjs
build-production.cmd
```

اگر یکی از شش فایل بعد از نصب دستکاری شده باشد، بازگشت خودکار متوقف می‌شود تا تغییر جدید از بین نرود. ابزار بازگشت فایل‌های FEE را به محتوای معتبر قبل از R2.2 برمی‌گرداند، نه AppShell یا Product Builder.

## سناریوهای پذیرش مرورگر و Oracle
1. در `/fee/design/catalog` فهرست کارمزدها نمایش داده شود، نام/کد قابل جستجو باشد و «صفحه بعد/قبل» عمل کند.
2. روی یک کارمزد کلیک کنید: فقط جزئیات آن نمایش داده شود و دکمه بازگشت به فهرست کار کند.
3. «تعریف کارمزد جدید» را انتخاب کنید: **فقط فرم** با عرض کافی باز شود؛ هیچ جدول رکوردها در کنار آن نباشد. ثبت موفق باید کارمزد تازه را انتخاب و به جزئیات برگرداند.
4. «ویرایش تعریف» را آزمون کنید؛ انصراف از فرم و هشدار تغییرات ذخیره‌نشده را کنترل کنید.
5. به «نسخه‌ها» بروید؛ فهرست فقط نسخه‌های همان تعریف را نشان دهد؛ ایجاد، انتخاب، ویرایش نسخه و حفظ FK والد را کنترل کنید.
6. روی «طراحی قواعد این نسخه» کلیک کنید: `definitionId` و `versionId` در URL و طراح قواعد معتبر باشند.
7. سایر تب‌های ویژگی/محصول و صفحه قواعد، منوی R22.1، موتور FEE2 و محصول‌ساز بدون Regression کار کنند.

**وضعیت QA محلی:** آزمون‌های ایستا، TypeScript Transpile، FEE R1/R2/R2.1، FEE2، Product Builder R29 و Release Layout اجرا شده‌اند. **Build کامل Angular، ارتباط Oracle و UAT مرورگر باید روی محیط ویندوز کاربر انجام شود.**
